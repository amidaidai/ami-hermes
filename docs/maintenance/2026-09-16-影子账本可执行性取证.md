# 影子账本可执行性取证（2026-09-16）

结论先行：**当前的影子账本不能支撑任何胜率 / WFO 结论。** 原因不是闸门太严，而是三条数据链缺陷：
① 冻结的计划几何被持续重放并计入"样本"；② 陈旧限价被成交判定当成"立即市价成交"，产出退化结局；
③ `order_model` 查表键不匹配，半数样本永远无法评估。本文只取证、不改代码。

数据：`data/shadow/decision_signals.jsonl`（489 条）、`data/shadow/decision_outcomes.jsonl`（220 条）。
复现脚本：`outputs/_shadow_probe1..7.py`（只读）。

## 一、账本里没有"授权交易"，只有计划几何

| 事实 | 数值 |
|:--|:--|
| signals 的 `final_state` | NO-GO 422 / WAIT 66 / GO-B 1 —— **GO-A 0** |
| signals 的 `grade` | B等待 290 / C等待 155 / X禁做 44 —— **A 级 0** |
| `final_verdict.executable=True` | **0 / 489** |
| `final_verdict` 里 entry/stop/target 齐全 | **0 / 489**（全 null） |
| 顶层 entry/stop/target 齐全 | 489 / 489（**标注用的是这一组**） |

也就是说：账本在给**从未授权、从未进入 FinalVerdict** 的计划/观察几何打分。
与卡面规则一致（未授权不给 Entry/Stop/Target），但账本侧的统计口径没跟上这个事实。

## 二、220 条 outcome 的四类构成（真正"可评估"的 54 条全是退化样本）

| 类别 | 条数 | `h4.status` | 能否用于绩效 |
|:--|--:|:--|:--|
| 缺订单模型 | **148 (67%)** | `missing_order_model` | 不能 —— 且其中 95 条是**可修的登记缺口**（见 §4） |
| 老 schema | 15 | 无 `status`/`filled`（只有 `first_hit`/`mfe_r`/`mae_r`） | 口径不同代，不能与新款混算 |
| 限价未成交 | 3 | `unfilled` | **正确**（限价没到就不成交，符合计划语义） |
| 已成交已收口 | **54** | `closed`，**first_hit 全是 stop** | **全部退化，0 信息量**（见 §3） |

卡面"可评估 51"（`shadow_calibration.shadow_sample_stats` 的 `filled=True`）对应就是这 54 条。

## 三、54 条退化样本的机制（决定性证据）

实测一条 closed 样本：

```
entry=63,884.0  stop=64,139.536  target=63,372.928  side=short
fill_price = 77,272.3        ← 成交价是当时市价，不是 entry
first_hit  = stop, bars_to_hit = 1
gross_r    = -0.0
```

- **entry→fill 偏离：中位 20.85%，最小 18.38%，最大 22.72%（54/54 全部 >10%）。**
- 链条：`shadow_calibration.label_outcome` 的成交判定对空头写 `at_open = op >= entry`
  —— 当市价远高于陈旧 entry 时，限价被判为"立即可成交"，以 bar open（77,272）成交；
  随后止损/目标**仍按计划价**（64,139 / 63,372）判定，对 77,272 的空头第一根就 `high >= stop`
  → 全部 `first_hit=stop`、`bars_to_hit=1`，`exit_price` 取 `fill_price` → `gross_r = -0.0`。
- 所以这 54 条不是 54 笔交易，而是**同一组陈旧价位在同一语义下反复退化**：
  既不能证明闸门对，也不能证明闸门错。任何用它们算的胜率/期望值都是噪音。

对照：3 条 `unfilled` 样本是**多头**且 entry 远低于市价（`at_open = op <= entry` 不成立）→ 正确地永不成交。
同一个判定规则下"多头陈旧几何 → 不成交"、"空头陈旧几何 → 立即成交"，这种不对称本身就是缺陷信号。

## 四、几何重复：193 条 outcome 共用一组价位，跨两个多月

- 220 条 outcome 只有 **20 组不同几何**；其中 **193 条（88%）** 是同一组
  （`BTCUSDT short 63,884 / 64,139.536 / 63,372.928`，隐含 R:R=2.00）。
- 这 193 条的时间跨度：**07-10 23:28 → 09-16 12:32**，相邻间隔 5–16 分钟（≈每 15 分钟一条）。
- 即：一个**冻结的 `_decision_snapshot`** 被持续重放，`signal_id` 按 15 分钟分桶 → 每天都在"新增样本"，
  真实独立样本数却恒定。有效样本量上限 = 不同几何组数 = **20**。
- 仓库里**没有任何"陈旧几何"守卫**：`shadow_outcome_labeler.py` / `shadow_calibration.py` 中
  搜不到 `stale` / `陈旧` / 距离阈值 相关判断。

## 五、`order_model` 键不匹配：半数样本被永久排除

| 账本 `model_id` | 条数 | `order_model_for_plan()` |
|:--|--:|:--|
| `VWAP反抽`（中文） | 109 | **None** ← 中文键查不到 |
| `vwap_pullback`（英文） | 95 | `{'type': 'limit'}` |
| `poc_rejection` | 9 | `{'type': 'limit'}` |
| `breakout_acceptance` | 7 | `{'type': 'limit'}` |

`PLAN_ORDER_MODEL` 注册的是英文键（`vwap_pullback`/`vah_reclaim`/…），而 `model_id` 存在中英两种写法
→ 中文那 109 条（占 220 的 **50%**）永远落在 `missing_order_model`、永远无法评估。
这与"身份归一必须单点、禁止各模块自写副本"是同一类问题（本会话已在 symbol/精度上各栽过一次）。

## 六、WFO 的前置清单（按此顺序，缺一不可）

1. **几何陈旧守卫**：标注前先比 `entry` 与信号时价格；偏离超阈值（建议 >1%，或"限价已越过一根 ATR"）
   → 标 `stale_geometry` 并**跳过**，不进统计。**不得**把陈旧限价当市价成交。
2. **`model_id` 归一**：中文/英文同一单点映射；补齐 `PLAN_ORDER_MODEL` 未登记的计划类型。
   验收：`order_model_for_plan(mid) is not None` 对账本出现的每个 `model_id` 成立。
3. **止损/目标必须与 fill 同源**：若成交价 ≠ 计划 entry（跳空/市价化），要么按 fill 重算几何、
   要么作废该样本；现在的"以 77,272 成交、按 64,139 止损"在生产上不可能发生。
4. **样本去重与冻结检测**：同一 `(symbol, side, entry, stop, target)` 连续出现 N 次（或跨日重复）
   → 只保留一条并记 `reemitted=true`；否则"样本数"是假的。
5. **老 schema 分代隔离**：15 条无 `filled`/`status` 的记录单独归档，不与新款混算。
6. **成本模型**（`cost_model`：fee/slippage/funding）—— 当前 220 条**全部缺失**，
   所以只能报 gross；在补上成本模型前，任何"净收益"表述都是编的。
7. **统计口径**：WFO / 胜率只在「已授权（executable）**且**触发成交**且**已收口**且**非陈旧几何**」
   的子集上计算，并同时报出**可评估率**（评估数 / 授权数）。
   现在的可评估率应写 0：授权样本数 = 0。

## 七、非加密品种借用 BTC 的账本（卡面数字错配）

| 事实 | 数值 |
|:--|:--|
| `decision_signals.jsonl` 的 symbol | BTCUSDT 422 · XAUUSD 61 · AAPL 3 · EURUSD 3 |
| `decision_outcomes.jsonl` 的 symbol | **只有 BTCUSDT 220** |

- 标注器对非加密直接跳过（`shadow_outcome_labeler`：`if not symbol.endswith("USDT"): stats["unsupported"] += 1`）
  → XAU / 股票 / 外汇的影子信号（共 67 条）**永远不会被标注**。
- 而 `auto_card.py` 把**全账本**（实际只有 BTC）的统计注入每张卡的 `_shadow_stats`：

```python
_shadow_stats = shadow_sample_stats(ROOT / "data" / "shadow" / "decision_outcomes.jsonl")   # 全局单本账
```

  所以 XAU 卡上那行「影子217·成熟202·可评估51」**是 BTC 的账本数字**，不是黄金的样本。
  这与「多资产共用加密话术」是同一类口径错配，而且它会让人以为"黄金样本在积累"。
- 修法方向：按 symbol 分账（或至少卡面按 `symbol` 过滤后再显示；无样本时如实写 0，不借账）。

## 八、结论与建议

- **不要现在算 WFO**：会得到一个由 54 条退化样本驱动的 -0.0R，看起来像"策略无效"，
  实际是"数据链没接好"。这属于把未知写成结论。
- 建议顺序：先修 §6 的 1–3（都是小改动、可测），再看可评估率；可评估率 > 0 之后再谈 WFO。
- 一句对**用户可见**的影响：那 193 条同几何重放横跨 **07-10 23:28 → 09-16 12:32（约 68 天）**，
  所以门6 显示的「影子217·成熟202·可评估51」不能当作"样本在积累"的证据 ——
  它更像「同一条计划被记了 193 次 + 54 次退化模拟」，且这行数字与品种无关。
