# 指标驱动的分析、流程与策略合同

版本：2026-09-11  
权威来源：用户上传的 `SVP_主指标_空格修正_20260911.pine`、`AggVol_副指标_最终版_20260911.pine`。两份源码已与仓库 `outputs/pine_20260905/` 中的定版文件逐字一致，源码哈希由 `scripts/indicator_source_audit.py` 校验。

## 一、系统总原则

| 层 | 权限 | 唯一依据 |
|---|---|---|
| SVP 主指标 | 结构、位置、方向候选、路径、执行授权 | 行动格 + MCP Data Window |
| AggVol 副指标 | 确认、降权、冲突否决 | 行动格 + HALDRO 总线 + CVD/OI/覆盖率 |
| Python 决策闭环 | 数据新鲜度、组合闸门、体制、风险、FinalVerdict | `decision_loop.py` |
| 渲染/提醒 | 只呈现 FinalVerdict | `render_tv_card.py` / 推送管道 |
| 人工交易 | 最终下单决定 | 用户本人；系统不自动下单 |

副指标不能把 SVP 的 B/C 升成 A；Python 不能把 SVP 的 WAIT/X 升级成可执行。只有 `FinalVerdict=GO-A` 且 `executable=true` 才允许显示执行三件套。WAIT 保留人工观察候选，NO-GO/X 清空候选价格。

### 四态契约与 PLAN-B（2026-09-15 定版）

`FinalVerdict.state` 四态，授权强度严格递减，且**只允许 GO-A 带执行权**：

| state | 什么时候出 | 给什么价 | executable |
|:--|:--|:--|:--:|
| `GO-A` | SVP 授权 + 主副同向 + 数据新鲜 + 闭柱 + 触发 + 体制 + 风控 + R:R≥2 + 高级订单流放行 | 执行三件套（entry/stop/target） | `true` |
| `PLAN-B` | B 级（结构成立+方向明确）+ 三件套几何有效 + R:R≥1.5 + **无任何硬门** | 人工方案：参考进场区 / 失效位 / 参考目标区，落在 `plan` 字段 | **`false`** |
| `WAIT` | 有等待类拦因，或 C 级 | 只有观察条件与结构位 | `false` |
| `NO-GO` | 任一硬门（X/S3/风控/体制/证据缺失/高级订单流否决…） | 连候选价都不出 | `false` |

**为什么要有 `PLAN-B`**：影子账本 2026-07-10→09-15 的 454 个信号里 `GO-A` 出现 **0 次**，grade 从未到 A，B 级占 58% 却一律被折成 WAIT/禁做 —— 「不能自动执行」被误当成「不能给方案」，用户只看到「永远禁做」。PLAN-B 把两者拆开：**方案照给，授权不给**。

三条不可退让的边界：

1. `PLAN-B` 的方案**只写 `plan` 字段**，`entry/stop/target` 恒为 `None`；任何下游读 `.entry` 都拿不到方案价，物理上无法当成订单。
2. `PLAN-B` 的 `executable` 恒为 `false`，`state` 永不带 `GO` 字样；卡面 `⭐` 只在 GO-A 点亮。
3. 有**任何**硬门 → 只出 `NO-GO`，连 `plan` 都不生成（不允许把被否决的结构包装成方案）。

## 二、指标输出如何进入系统

### SVP 主指标

行动格固定顺序：

`位置 → 结论 → 方向 → 路径 → 风控 → CVD → OI → 协同 → 结构 → 磁吸↑ → 磁吸↓ → 前位 → 现位`

关键机器字段：

- `MCP Side Code`：方向候选；X 状态由 Pine 优先输出 9。
- `MCP Grade Code` / `MCP Setup Score`：候选质量，不是最终执行授权。
- `MCP Entry/Stop/Target Price`：只有行动格 `风控` 标签下才进入可执行候选。
- `MCP Entry Valid Code`：`-3 X禁做`、`-2 几何无效`、`-1 R:R不足`、`0 无方向`、`1 待确认`、`2 B/C观察候选`、`3 A候选`。
- `MCP RR Ratio`：A 级硬线为 2.0；1.5–1.99 只能保留 B/C 人工观察候选，不能授权执行。
- `MCP NoTrade Reason Code`：位掩码原因，必须进入卡片解除条件，不得被数字等级覆盖。
- `MCP Trigger Pack` / `MCP Evidence Pack`：校验触发年龄、触发新鲜度、闭柱和位置证据。
- `MCP Regime Pack` / `MCP StructPack`：体制、FVG、OB、BOS/CHoCH 结构辅助策略选择。

### AggVol 副指标

- `HALDRO Valid Code`：聚合可用性；无效不能制造冲突。
- `HALDRO State Pack`：`S0 无效`、`S1 支持多`、`S2 支持空`、`S3 冲突`、`S4 降权`。
- `Basic Packed Bus`：主副唯一连接总线，合同 22003；OI 编码 0 表示缺失，不能解释为持平。
- `CVD Value` / `CVD Quality Code`：流向和质量，CVD 方向必须与当前主周期口径对应。
- `OI Change %` / `OI Price Direction` / `OI Agreement %` / `OI Dispersion Ratio`：判断新多、新空、空回补、多平仓及跨所一致性。
- `Coverage Exchanges/Spot/Perp`、`Exchange Dominance %`、`Coverage Feed Mode`：决定共振是否可信；单所主导或覆盖不足只能降权。
- `Composite`、`HALDRO Flow Pack`：确认票，不得越权为方向主票。

## 三、唯一裁决流程

```text
声明分析租约
  → 核对 TV symbol + 周期 + 指标存在
  → 读取 SVP 行动格与 Data Window
  → 读取 AggVol 行动格与总线
  → 读取 Binance 衍生品（仅加密）
  → 标准化字段/新鲜度/合同/闭柱
  → 体制与策略模型筛选
  → FinalVerdict 八类闸门
  → 只渲染裁决允许的字段
  → 写影子记录/复盘证据
  → 结束租约
```

任何一步品种、周期、合同、时间戳或字段不成立，走 fail-closed：数据状态写明 `unavailable`、`stale_cache` 或 `degraded`，不使用旧缓存冒充实时。

### 图表证据层（P0）

`scripts/chart_evidence.py` 将当前图表身份、价格栏、Pine线/区域/标签及ICT结构证据标准化为 `chart_evidence`。
状态只有 `verified` 才表示品种、周期、指标、价格栏和ICT对象均可结构化复核；`partial` 表示可看图但对象读取不完整，
只能观察；`identity_mismatch` 硬阻断。BTC分析调用 `tv_data_bridge.collect_and_cache(..., expected_timeframe="15m")`
时，15m身份必须通过；5m仅作为触发层，不得冒充主执行周期。

## 四、策略选择矩阵

| SVP 结构状态 | AggVol 状态 | 策略 | 允许输出 |
|---|---|---|---|
| 价在 VA 内、结构平衡 | S1/S2 不明确 | VA 边界等待 / POC 拒绝观察 | WAIT，不能追中间位 |
| VAH/VAL 外且回收 | 同向确认 | VAH/VAL 回收 | A 仍需闭柱、触发、R:R≥2 |
| POC 拒绝 | 同向或弱确认 | POC 拒绝回踩/反抽 | A 或 WAIT，取决于授权与位置 |
| FVG/OB 高质量回踩 | 同向确认 | FVG/OB 回踩 | A 候选或 B/C 观察候选 |
| MSS/BOS/CHoCH 后回踩 | 同向确认 | 结构突破接受 | 不做第一根追价，等回踩确认 |
| 扫流动性后收回 | CVD/OI 同向 | 扫位回收 | 等收线和触发新鲜，禁止中途追 |
| SVP X / NoTrade 位掩码 | 任意 | 禁做 | NO-GO，清空全部价格 |
| SVP WAIT 或 S3 | 任意 | 等解除/等副同向 | WAIT，只显示条件与人工观察价 |
| AggVol S4 / 覆盖不足 | SVP 可用 | 降级观察 | 不升级方向，不给自动执行权 |

策略不是单独投票。先由 SVP 给结构候选，再用 AggVol 确认或否决，最后由数据、体制、风险和 R:R 闸门裁决。

## 五、分析档位对应的数据深度

- **轻量**：主执行周期 SVP 行动格、现价、全屏截图、加密衍生品方向票；不做全量多周期重扫。
- **标准**：轻量 + 上下邻居周期的 SVP 结论行 + 关键位 + AggVol 交叉；优先继承已验证高周期背景。
- **完整**：D/4h/1h/15m/5m 五周期、SVP/AggVol、Binance、多源矩阵、体制、风控、FinalVerdict 和证据链。
- **监控**：只产生关键位事件，不自行判方向、不生成执行三件套。

加密主执行周期为 15m，5m 是触发；黄金主执行周期为 5m。每次正式加密/黄金更新必须新 TradingView 全屏截图，含价格轴和 CVD 窗格。

## 六、渲染边界与审计证据

- 两条卡片路径复用 `render_tv_card.final_is_executable`：只有GO-A、明确可执行、A等级与方向一致、有限正数且几何正确的三件套才能渲染；声明R:R与三件套实际R:R都不得低于2。缺失旧式rr字段只能从同一FinalVerdict元组推导，不回落到旧计划。
- 跨周期结构位保留周期前缀（D·VAL / 15m·VAH）。只有同品种、周期、来源快照与价值区锚点的VAL/VAH才可检查上下沿一致性，跨周期不得误判倒挂。
- 卡面价格共识等级不等于全源健康度。来源矩阵、路由完成度分别标识自己的分母；默认中性数值不是有效采集证据。
- 批准监控位保留原批准来源；TTL续期、结构复核、候选采集、人工批准是不同事件，不能同步覆盖成一个假新鲜时间戳。
- 历史心跳陈旧需追踪生产者是否退役、现行替代与消费者，不据此自动重启或报P0。模拟影子结果与真实人工成交复盘分开，不制造账户余额或收益。
- 测试通过只证明所覆盖的合同；TV编译/现场读取、外部源可用性与投递回执须另取证。

## 七、系统改进已经落地

1. `decision_loop.py` 现在直接消费 `MCP Entry Valid Code`，数字 A 不能绕过 SVP 的无效/待确认/B/C 状态。
2. 现在直接消费 `MCP NoTrade Reason Code`，原因会进入 WAIT/NO-GO 阻断与警告，不再只依赖面板文字。
3. 现在直接消费 `HALDRO State Pack`：S3 硬冲突、S0/S4 降级等待、未知状态 fail-closed。
4. `tv_indicator_contract.py` 已明确 1.5–1.99 是“B/C观察候选·不授权”，与 Python 决策闭环一致。
5. 新增 `scripts/indicator_source_audit.py`，防止指标源码替换后契约仍指向旧版本。
6. 既有 TradingView 分析租约防止后台任务抢图；共享图表归属恢复失败会保留待归还目标。
7. `decision_loop.py` 已接入 Trigger/Evidence/Regime/Contract/Struct/Quality Pack：触发过期、未闭柱、合同损坏、质量码异常会明确进入 WAIT/NO-GO。
8. 加密副指标的 Coverage Feed Mode、Stale Venue Count、CVD Quality、OI Presence/Agreement 已进入同一 FinalVerdict；回退、单源、异常、跨所缺失与低一致度不再只是卡面文字。

以上字段均通过 `tv_indicator_contract.py` 的单一解码入口消费，消费方不得重新实现 packed code 或位掩码。

## 七、每次分析的验收清单

- [ ] TV 连接正常，symbol 和周期正确，SVP/AggVol 均为目标品种。
- [ ] 行动格行名完整，Data Window 字段来自当前源码合同。
- [ ] SVP 风控标签、Entry Valid、NoTrade 位掩码一致。
- [ ] AggVol 合同、覆盖率、Feed Mode、Valid/State、CVD/OI 新鲜度一致。
- [ ] 只使用闭柱；触发年龄未过期；当前价格来自实时行情源。
- [ ] S3、X 状态、硬 NoTrade 原因没有被任何降级逻辑覆盖。
- [ ] WAIT/NO-GO 没有执行 Entry/Stop/Target；B/C 只标“人工观察候选”。
- [ ] GO-A 同时满足 SVP 授权、双指标允许、数据新鲜、闭柱、触发、体制、风险、R:R≥2。
- [ ] 截图和文字卡来自同一 TV 现场；分析结束释放租约。
- [ ] `chart_evidence.status` 为 `verified`；若为 `partial`/`visual_only`，FinalVerdict 不得 GO-A。
- [ ] 保存裁决 ID、来源状态、指标合同版本和关键阻断原因，供复盘回放。
