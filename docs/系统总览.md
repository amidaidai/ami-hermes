# 棠溪交易驾驶舱 · 系统总览

> 更新：2026年9月14日
> 这是**唯一入口**文档。想知道「某件事该看哪个文件 / 该跑哪个脚本 / 谁说了算」，先看这里。
> 带日期的数字与运行态清单是历史实测，不代表当前在线状态；每轮验收以当轮工具输出为准。

## 1. 这是什么

一个**人工决策驾驶舱**：TV 上的两个 Pine 指标（SVP 主 + AggVol 副）负责出结构、位置、
执行授权与订单流确认；本系统负责**采集 → 交叉验证 → 唯一裁决 → 出卡 → 监控告警**。
用户手动下单，系统不自动交易。

## 2. 权威层级（冲突时听谁）

裁决只有一个出口，其余都是证据：

| 层 | 角色 | 能不能改裁决 | 能不能改价格 |
|---|---|---|---|
| `FinalVerdict`（`decision_loop.py`） | **唯一执行权** | — | — |
| 主指标 SVP 行动格 | 结构/位置/授权 | 决定 A/B/C/X 与「风控」授权态 | 提供执行三件套 |
| 副指标 AggVol | 确认 / 降级 / 否决 | **只降不升** | ✗ |
| Binance / CoinGecko / 宏观 / X·Grok | 证据与催化剂 | ✗ | ✗ |

铁律：`GO-A + executable=true` 才允许出现 Entry/Stop/Target；`WAIT/NO-GO` 清空三件套；
`X` 硬阻断连人工候选价都不出。

## 3. 主链路

```
TradingView (SVP 主指标 + AggVol 副指标 + 光秃秃 Volume)
  │  data_get_pine_tables / data_get_study_values / data_get_pine_lines
  ▼
auto_card._build_tv_main_data()        ← 契约 tv_indicator_contract 解码
  │  main 字典（13 行 + DW 字段 + 解码后的闸门码/原因链）
  ▼
decision_loop.resolve_final_verdict()  ← 唯一裁决（含 svp_authorization 闸）
  │  FinalVerdict
  ▼
render_tv_card.render_tv_card()        ← 推送卡（决策）
render_v96.render_v96_card()           ← 完整报告卡（证据）
  │
  ├─→ Telegram（仅在明确授权时）
  └─→ data/auto_card_*.md 本地留档
```

监控是与分析**分离**的第二条链（不由分析触发）：
`keylevel_guard.py`（0.5s 轮询）→ 到价 → 直发 Telegram → 用户自己看图判断。

## 4.1 技能备份（唯一备份路径）

`~/AppData/Local/hermes/skills` 是**真实目录、不在仓库内**；而 `~/AppData/Local/hermes/scripts`
是符号链接指向本仓 `scripts/`（已受 git 管理）。**技能是核心资产却只存在于本机** ——
换机或重装就没了。因此：

```
~/AppData/Local/hermes/skills  ──(单向镜像)──▶  D:/Hermes agent/hermes/skills  ──git──▶  远端
        ↑ 真实源（唯一可写）                            ↑ 只读快照 + _snapshot_manifest.json
```

- 执行者：`scripts/maintenance/skills_snapshot.py`，cron `技能快照备份` 每日 04:20（`no_agent`）。
- **fail-closed**：源文件数骤降到上次的 60% 以下、或少于 100 个，就**拒绝镜像**并报错，
  绝不把仓库里的备份擦掉（`tests/test_skills_snapshot_20260911.py` 锁死这条）。
- **单向**：只从 hermes 目录读到仓库；运行态（`.hub` 索引缓存、`.curator_ledger.jsonl`、
  `.curator_backups/`、`__pycache__`、`node_modules`）不进备份。
- **提交范围**：只 `git commit -- hermes/skills`，**不碰你其它在途改动**。
- **推送也有护栏**：只在**待推提交全部是技能快照**时才 `git push`。本地只要有一条在途的功能
  提交，就停下并报告「未推送：待推提交里有 N 条非快照提交」—— 自动推送等于替你发布，不允许。
- **内容级密钥扫描**：命中 `sk-`/`ghp_`/`AIza`/TG bot token/私钥块/JWT → 拒绝入库并登记在
  清单 `blocked_secrets`（2026-09-11 靠这条抓出一个 67 位真 `sk-` 密钥，已脱敏并建议轮换）。
- 手工核对：`python scripts/maintenance/skills_snapshot.py --status`（0=同步 / 2=有漂移）。
- `--no-push` / `--no-commit` 可单独关闭某一步；`--dry-run` 只看差异。
- 首次快照：1913 个文件 / 15.0 MB；首次推送 `4883e1b..c89fc1e`，远端已核实 1913 文件。


**变更纪律**：改指标字段 → 先改契约，再改消费方，跑守卫；
改裁决 → 先改 `decision_loop.py`，再改渲染器；
任何消费方**禁止**自写 DW 字段白名单（历史事故：四处白名单漂移，13 行行动格只有 4 行被吃到）。

## 6.1 图表租约 —— 分析期间后台让路（2026-09-11 新增）

TradingView 只有**一张图**。`tv_collection_lock` 只序列化**后台任务彼此**；
对话里的分析是直接读行动格 + 截图，不持这把锁，于是后台续航会在读图中途切走图表
（实测 2026-09-11 14:07 读 5m 被 `btc_tv_refresh` 连抢两次，行动格整张读成空表）。

| 角色 | 谁 | 行为 |
|---|---|---|
| 声明 | 分析侧 | `python scripts/tv_analysis_lease.py start --minutes 10 --symbol <sym>`；结束 `end` |
| 声明（自持） | `auto_card` 管线 | 开跑时无租约则自持 15 分钟（已有租约则沿用不覆盖），`__main__` 收尾只释放自己声明的 |
| 感知 | 后台侧 | `keylevels_collect` / `xau_tv_sync` / `btc_tv_refresh` 入口查租约，有效即**让路** |
| 放行 | 分析自有采集 | 管线发的 `keylevels_collect` 子进程带 `TANGXI_ANALYSIS_OWNER=1` → 不判让路（防「分析挡住自己的五周期证据」） |
| 自动 | `tv_screenshot.py` | 截图是分析链一环：持有/续期租约（≥6 分钟），防截图与读数不同源 |

- 状态文件 `data/tv_analysis_lease.json`；TTL **上限 30 分钟**，脚本崩溃也不会锁死图表。
- **让路不是失败**：`keylevels_collect` 用专用退出码 `7`，cron 侧按成功处理，
  下一轮自然补上；不会被记成采集失败。
- **租约自锁已修（2026-09-14）**：修前分析持有的租约会把分析自己的五周期采集判
  `deferred`，快照超 30 分钟契约后源状态落 `TV五周期 unavailable`（五层证据降级，
  裁决仍 fail-closed）。放行只认环境变量**严格等于 `1`**，外部后台不置该变量，
  防抢图语义不变。排查口子：`data/keylevels_collect_diagnostic.json`
  的 `analysis_owner:proceed`（自有放行）/ `lease:deferred`（外部让路）。

  `fetch_all` 五个周期整体打死 → 每次同步都退回逐周期切图。修后 `ohlcv_source` 显示
  `api:twelvedata`，只保留 1 次 5m 校核（原为 5 次切图）。

- 免费源失败**不阻塞**主流程，但状态必须可见：`live / cache / stale_cache / unavailable / quota_cooldown`；

## 10. 取证契约（2026-09-13 加固）

**XAU 每层 K 线必须自带来源证据**。`data/xau_tv_state.json` 的每个周期含
`evidence`（`source` / `bar_open_time` / `bar_close_time` / `closed` / `closure_basis`
/ `same_source_as_chart`）与 `volume_kind`，并用 `ohlcv_evidence[tf].status`
（`verified` / `rejected`）汇总；切图前后各读一次 `chart_get_state`，
品种或周期不符即判 `rejected` 并回退。**不凭固定振幅阈值判真假**——
微幅区间本身不是失效证据（实测 5m/15m 黄金本就 0.07%/0.08%）。

**风险快照陈旧必须可见，不冒充实时**。`risk_state.json` 的 `date` 早于当天（北京时间）
时，`risk_state_status()` 报 `stale`，并作为 `来源矩阵` 里 `风险快照` 一行可见；
读取**绝不回写文件、绝不用默认值补齐余额/日期**。陈旧不新增硬拦截
（既有 `FinalVerdict` 闸门与「未接账户余额·非真实额度」标注已覆盖这一层）；
历史遗留的模拟快照（`sim from monitor …`）不是已核对账户。

**宏观快照不得用默认值伪造**。VIX/SPX 取数失败时不得回落到「中性 | VIX 20 | SPX +0.0%」；
只有真的取到字段才写 `sentiment` / `vix_level` / `timestamp`，否则该轮明确标注
「本轮未采到有效字段」。

**可选源（dune / x_sentiment / qlib / liquidation / deribit / COT）当前无采集调度**，
属有意停用：不机械重启 cron，只在来源矩阵里如实显示 `stale_cache` / `not_run`。
需要恢复时，先恢复对应采集器并验证产出，再把文件加回 `WATCH_FILES`。

**影子校准链已恢复**（2026-09-13）：`影子结果标注`（`shadow_outcome_labeler.py`，`*/15`）
把 `data/shadow/decision_signals.jsonl` 的候选按 4/8/16 根闭柱标注成
`data/shadow/decision_outcomes.jsonl`（MFE/MAE），只读 Binance 公开 K 线、不外发。
本机 Binance 直连固定 12s 超时、走代理 0.4s，因此脚本会**记住探明的可用模式**并优先复用
——否则整轮标注要 20 分钟以上，`*/15` 的 cron 永远跑不完（实测修复后单轮 ≤15s）。

**风险对账只能由人触发**：`risk_state_reconcile.py` 必须显式给 `--balance`，
默认 dry-run，`--write` 才落盘；它只盖章当天日期与账务字段，其余键原样保留。
系统本身不会、也不应该凭空产生账户余额。

**TV 复用窗口只有一个值，前置必须更严**（2026-09-14）：读取侧窗口
`TV_LIVE_READ_MAX_AGE_MIN = 5`（用户批准的「最多滞后一根 5m K 线」），
前置决策用 `TV_LIVE_READ_MAX_AGE_MIN − TV_LIVE_PRE_SYNC_MARGIN_MIN(=3) = 2 分钟`。
原因：出卡本身要 20~160s，若前置也用 5 分钟判「新鲜」，卡跑完时缓存已跨过读取阈值
→ 主指标被丢弃、`tv_live` 门亮红，**同一张卡自相矛盾**（实测复现：XAU 缓存 4 分钟
时前置跳过、90s 后读取拒绝）。改窗口时两个常量一起改，`tests/test_audit_fixes_20260914.py`
锁死这条不变量。

**XAU 现场同步必须留下「连续失败」证据**（2026-09-14）：`xau_tv_sync.py` 每轮写
`data/xau_tv_sync_status.json`（`status` / `consecutive_failures` / `last_success_at` /
`kept` / `last_error`）。退出码语义不变——失败仍返回非零，让调度器看得见；新增的是
**分级**：单次抖动 = `failed(1)`，连续 ≥2 轮 = `degraded`，`audit_preflight.py` 与
`data_freshness_watchdog.py`（盯 `last_success_at`，阈值 1h）据此报警。
这样「一次 TV 抖动」与「黄金现场结构已经连续几轮没更新」不再长得一样。

**X 情绪 = 客观部分本地刷新 + X 叙述按需拉取**（2026-09-13）：
`scripts/x_sentiment_refresh.py` 刷新恐贪（alternative.me）、BTC/ETH 市占与总市值
（CoinGecko /global）、热门（/search/trending），写入 `data/x_sentiment_context.json`；
X 上的舆情叙述由 agent 用 `x_search` 拉到后经 `--x-note` 写入，**脚本本身不碰社交平台、不外发**。
该文件的生产者曾消失两个月（停在 2026-07-15），卡面却用 ✅ 打印那时的恐贪 25 / 市占 56.3%
—— 现在按语义时间戳判新鲜度：超过 6 小时就写「本轮不采用」，旧值不展示。

**`x_search` 结果必须拒收 degraded / 无引用的回答**：实测带 `from_date/to_date` 过滤时
返回 `degraded=true` 且零引用，内容出现「阻力 112,000–114,000」而当时现价 77,200 ——
明显是模型幻觉。判定规则：`degraded is false` 且 `inline_citations` 非空才可写入，
并把引用里的关键位与 Binance 现价做常识核对；不通过就整条丢弃，宁可没有情绪也不能写错。
