# 棠溪闭环验收复现记录（2026年9月3日）

## 实际修复主题

- `keylevels_collect.py`：增加MCP阶段诊断、逐调用超时、完整五周期发布校验和失败非零返回；五周期完成后在stdio上下文退出前原子发布，避免MCP退出阶段吞掉结果。
- `xau_tv_sync.py`：将XAU五周期采集、5m行动格刷新、双缓存批次校验和最终提交置于共享TV锁内；提交后才允许生成/发送报告。
- `trade_exec_bridge.py`：legacy `entry_ready` 无完整GO-A FinalVerdict时记录 `execution_blocked`；完整GO-A按 `verdict_id/setup_id`幂等生成执行事件，并校验BTC品种。
- `hard_stop.py`：`dry_run=False`时校验GO-A、三件套、品种、方向、价格、价格几何和风险金额一致性。
- `auto_card.py`、`telegram_reliable.py`、`telegram_direct.py`、`topic_router.py`：外发要求显式自动投递开关、显式目标、闸门和完整GO-A；移除硬编码话题旁路。
- `atomic_json.py`：JSON、文本、JSONL追加使用同一线程/跨进程锁；临时文件使用PID+UUID；队列flush在锁内原子重写。

## 人工批准位续期操作

只有用户明确授权后才可执行。安全顺序：

1. 读取 `data/keylevels_config.json`，确认目标资产、位数量、价格和有效期。
2. 复制备份到同一data目录。
3. 只修改用户授权范围内字段；“只续期”不得改价格。
4. 使用 `atomic_write_json` 发布。
5. 运行 `btc_keylevel_guard_watchdog.py`。
6. 运行 `audit_preflight.py`，确认 `active=8/configured=8`、守护单实例且心跳新鲜。

## 安全边界

- 本次现场没有发送Telegram、下单或启用自动交易。
- 过期批准位必须导致降级；候选池不能自动升级。
- “测试全绿”与“实时预检全绿”必须同时成立，才能声明生产就绪。
- 发现旧daemon、旧心跳或禁用任务时，先确认是否仍为现役生产入口，再决定是否纳入预检。
