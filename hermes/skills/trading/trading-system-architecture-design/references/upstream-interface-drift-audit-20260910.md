# 上游输出接口漂移：检测、量化、修复（20260910 实案）

## 一、症状：静默丢数据，不报错

上游改了字段名/行名/表结构，下游照旧跑，**不报错、不警告，只是数据少了一块**。
实案：主指标行动格从 10 行改成 13 行，`auto_card` 的行名清单还停在旧 10 行，
两版只有 4 个名字重合 → **13 行只有 4 行进卡**，其余 9 行静默丢弃，
而丢的恰是决策主信息（装着入场/止损/目标/R:R 的「风控」行、装着主副一致性的「协同」行）。
用户无法从卡片上看出少了东西——这是它最危险的地方。

**根因永远不是“忘了改”，而是名字被硬编码在 N 处**：本例同一套字段名散在三个地方
（`tv_data_bridge` 的别名表、`auto_card` 的 DW 映射表、`auto_card` 的行键清单），
各自漂移。**先数清楚有几处，再谈修。**

## 二、检测：出两份清单做差集

### 2.1 导出上游的完整输出接口

从**上游源码**（不是文档）导出它真正对外输出的东西：

```python
CALL = re.compile(r"(?<![\w.])(plotcandle|plotbar|plotshape|plot|bgcolor|hline|fill)\s*\(")
TITLE = re.compile(r"(?:title\s*=\s*|,\s*)['\"]([^'\"]+)['\"]")
# 逐行取绘图调用的 title → 得到 DW 字段名全量
# 表格行名：rowLabs.push("…") / table.cell(...) 的字符串字面量
```

**关键：以源码为权威，不要用仓库里的字段映射文档。** 本例那份文档停在两个月前、
描述的是更早两代的上游版本（文档写“主 v5 / 副 v6”，实际已是 v13），照它改只会错得更远。

### 2.2 构建「消费矩阵」

把上游每个输出名去整个仓库语料里搜“谁在读”：

```python
corpus = [(p, p.read_text(errors="ignore")) for p in 各目录.rglob("*") if p.suffix in {'.py','.md','.json'}]
for name in 上游输出名:
    hits = [p for p, txt in corpus if name.split("(")[0].strip() in txt]
```

产出三列：**被消费 / 无人消费 / 只被文档提到**。
注意：`✗ 无人读` 是可靠信号（名字哪儿都不出现）；`✓` 有假阳（`Volume`/`CVD` 这类通用词会到处命中），
要再人工确认下游是**真解析**还是只是**被提到**。

### 2.3 定位“硬编码名单”并对账

搜下游代码里的行键清单 / 字段映射表，直接与 2.1 的清单求交集：

```python
old = ["结论","方向","进场","止损","目标","确认","核对","风险","磁吸↑","磁吸↓"]
new = 上游真实行名
print(len([k for k in old if k in new]), "/", len(old))   # → 4 / 10
```

这个数字就是“损失了多少”。直接写进报告，比任何描述都有力。

## 三、量化：用真实载荷跑前后对比

**不要只看静态代码就下结论。** 拿一份真实缓存/真实响应，把下游的构造函数真跑一遍：

```python
tables = auto_card._tv_cache_decision_tables(real_cache)
# 修复前：主表 4 行   修复后：主表 13 行
```

静态分析可能误判（比如函数其实做了通用解析、硬编码名单只是兜底），
**只有跑真实载荷才能证明损失真实存在**，也才能拿这个数字当回归测试的期望值。

## 四、修复四原则

1. **建单一契约源**（本例 `scripts/tv_indicator_contract.py`）：行名、字段名、双向映射、解码器全放一处。
   纪律：**上游改字段 → 先改契约 → 再改消费方**。
2. **只增不删**：旧字段名保留在 `LEGACY_*` / `LEGACY_DW_ALIASES_*` 里。
   历史缓存与既有测试因此不被打断，也不会出现“修一处红一片”。
3. **消费侧改契约驱动**：不要逐条 `if key == "…"` 手写，而是从契约反查表批量解析。
   否则下次上游加字段又要改 N 处。反查表要同时支持**全名**与**去括号短名**：
   ```python
   table[dw] = src
   table[dw.split(" (")[0]] = src   # "HALDRO State Pack (0无效/…)" 也要能用短名命中
   ```
   踩过的坑：通用规则 `key.lower().replace(" ","_")` 对**带括号/百分号/中文后缀**的字段名全失效
   （`HALDRO Flow Pack (OI*100+CVD*10+SP)`、`OI Agreement %`、`Basic Packed Bus (唯一主副连接)`）。
4. **先查下游有没有安全闸门会被绕过**：本例 `tv_data_bridge` 故意跳过 `mcp_evidence_*`
   （只允许走校验过的 `_read_evidence()` 通道）。批量别名解析**必须显式排除**这些前缀，
   否则新增的便捷解析会把未校验字段泄进缓存。

## 五、不只是“改名”：三种更隐蔽的结构性变化

| 变化 | 表现 | 检法 |
|---|---|---|
| **字段被折进另一行** | 上游把 入场/止损/目标 合并成 `风控` 行的 `入X·止Y·n.nA·标Z·n.nR` | 下游那几个字段全变空，但没报错 → 为合并行写结构化解析器拆回来 |
| **行标签变成动态的** | `风控` 会在四态间变（`风控` / `风控·观察` / `风控·未授权` / `禁做·不出价`） | 只认字面 `风控` 时**观察态整个漏读** → 写 `ordered_main_rows()` / `risk_row_value()` 认全部变体 |
| **字段彻底删除** | `OI Total` / `Estimated CVD Value` / `MCP CVD Value` 已不存在 | 映射恒空但无害；**不要因此去删旧映射**，只列为 deprecated |

## 六、闸门要放在“裁决落定那一点”

新写的裁决逻辑（如主副九宫格）**不要塞进上游解析函数**，而是挂在**唯一那个裁决落定处**：

```
final_verdict = _resolve_card_final_verdict(...)   # 原有链不动
final_verdict = _apply_matrix_guard(final_verdict, tv_main)   # ← 就在这里加一道
```

- 方向必须是**单向保守化（只降不升）**：降级/否决可以，升级绝不可以。
- 已经算好的、本来就不是可执行的结果：只**标注**原因，不重写它。
- 把裁决结论挂进 `final["matrix_verdict"] / matrix_reason / matrix_downgraded`，
  让渲染层能解释“为什么被拦”，而不是默默变成 WAIT。
- **不变量用全网格扫描测**，不要只测几个代表点：
  ```python
  for grade, state in itertools.product(ALL_GRADES, [None,0,1,2,3,4]):
      for rr in (None,1.0,1.5,2.0,3.0):
          assert 副指标不能把非A变成可执行
  ```
  本例 270 组全网格扫过，才有底气说“合成永不升级”。

## 七、未知市场 → 按保守侧处理

新裁决需要 `is_crypto` 这类市场守卫（副指标只对加密有否决权，套到 XAU/外汇上违反多市场边界）时：

- 优先把 **symbol 串进构造函数**（本例给 `_build_tv_main_data` 加 `symbol=` 入参）。
- 拿不到 symbol / 判定不出来时，**默认走保守侧**（`is_crypto=True`，让副指标参与降权），
  宁可降权也不放行一个没被确认的单子。
- 反向验证不能少：XAU 餵 `S3冲突` 时 **GO-A 必須不被误杀**——守住边界的证据比守不住的证据重要。

## 八、交付时必须跑的三层验证

1. **静态**：契约自洽（每个 alias 指向的字段必须在权威名单里；已废字段不得出现在权威名单）。
2. **真实载荷**：用真缓存/真响应跑一遍，把“4/13 → 13/13”这类数字写进测试期望值。
3. **交叉自洽**：同一份实盘数据里，**两个独立解码器必须互相印证**。
   本例：`Execution Pack 1801` 解出「几何0 / 未收线 / 止损1.80ATR / 入场码−2」，
   与 `Entry Valid Code = −2`、`NoTrade 掩码含 256 未收线` 三处独立印证。
   能这样互证的解码器才算真的对上了。

## 九、提醒用户的那一句

新增的 DW 字段**要等下一轮上游落盘才会进缓存**。在那之前解码层显示“缺失”是正常的，
必须主动告诉用户，否则他会以为修坏了。
