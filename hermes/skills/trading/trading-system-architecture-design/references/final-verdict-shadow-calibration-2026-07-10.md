# FinalVerdict、HALDRO有效性与影子校准实案（2026-07-10）

## 核心不变量

### 唯一最终裁决
渲染、告警、仓位和执行不得分别读取原始SVP等级与HALDRO文本。统一输出：

```text
GO-A / GO-B / WAIT / NO-GO
```

非可执行状态必须清空 `entry/stop/target`，保留仅供观察的 `watch_entry/watch_side`。渲染器再次读取 `_final_verdict`，避免调用方漏投影后恢复出旧A级订单。

### HALDRO Valid Code 权限
- `0`：无效；不得制造方向冲突，WAIT。
- `1`：单源回退；只作弱确认，冲突时WAIT，不得硬NO-GO。
- `2`：聚合有效；与SVP强冲突时硬NO-GO。
- 非加密：HALDRO不适用，不因缺失降级。

下游同时消费 `Risk Code` 位图，不能只展示文字。

## 实时体制
禁止用固定VIX或演示波动率填充实时体制。使用闭柱OHLCV和TV结构位构建：ADX、ATR比率、EMA spread/ATR、20K VWAP穿越、20K VA停留、位移/ATR、RVOL、VWAP距离。体制只选择模型，不决定多空。

优先级：扩张 → 收敛 → 趋势 → 平衡；耗尽是风险叠加位。

## 模型路由
- 体制白名单过滤后只选一个主模型。
- 旧 `confidence` 是模型标签，不是概率，不能参与仓位或称为胜率。
- 排序优先使用区域/触发质量与R:R；只有分组样本达标的校准胜率才能轻微参与排序。
- `区域A级 ≠ 交易A级`：位置、触发、订单流、R:R、风控仍可否决。

## 风控单一出口
风险金额先受1%账户上限与绝对金额上限约束，再除以体制风险除数。仓位展示层只能投影FinalVerdict，不得按旧置信度重新放大。

## 影子校准
闭柱候选按 `signal_id` 幂等写JSONL，记录体制、主模型、等级、区域质量、HALDRO有效性、最终状态与阻断原因。后续4/8/16根记录MFE/MAE、先止损/先目标、耗时。同根同时触发采用保守止损优先。

按 `资产→周期→体制→主模型` 分层；每格样本不足30不输出校准概率。回测复用同一个 decision loop，旧近似VAH/VAL/POC结果不得作为当前SVP生产证据。

## TDD与验证顺序
1. 为每个裁决缺陷先写失败测试：Valid 0/1/2、NO-GO清订单、体制错配、区域质量、R:R、风控。
2. 最小实现通过专项测试。
3. 渲染器回归：NO-GO绝不出现星标订单。
4. 回测回放同一FinalVerdict。
5. 全量测试后才做TV部署、五周期DW、BTC/XAU实测和文件同步。

## 常见陷阱
- 仅修改 `dual["state"]`，但渲染仍读取原始 `grade/direction/entry`。
- Valid=0的负Composite仍制造冲突。
- Valid=1按聚合数据做硬拦截。
- 体制分类器实盘和回测各写一套。
- 低波动自适应把单笔风险放大到宪法1%上限以上；正确顺序是先封顶基础风险，再做体制缩小。
- 把写死confidence校准成“胜率”，造成高分桶反而更差。
