# Telegram 手机端分析卡排版规范 v9.11

## 适用范围

适用于棠溪 Telegram RichMarkdown 快速分析卡，尤其是 BTC/XAU 的移动端推送。目标不是增加字段，而是让用户在首屏完成“现在是什么状态、价格在哪、下一步做什么”的判断。

## 推荐信息顺序

1. 品种 + 中文时间
2. 方向/等待 + 等级
3. 一句加粗结论
4. 现价；可附日高、日低、涨跌幅
5. 五周期体温（D→4h→1h→15m→5m）
6. 结构位表
7. 执行表
8. 验证表
9. 下一步 + 失效条件

## 表格规则

- 默认三张窄表：结构、执行、验证。
- 每张表最多 3 列；表头短，单元格避免完整句和内部审计术语。
- 表格前必须有空行；不要让 `【章节】`、`## 标题` 或粗体独立标题紧贴表头。
- 结构表只放最近的上方结构、现价、下方结构及距离。
- 执行表只放主推、失效路径、禁止项；B/C/WAIT/NO-GO 不输出可执行三件套。
- 验证表按行拆分 SVP、HALDRO、订单流、必要的数据源状态；不要把它们串成一条长句。

## 视觉取舍

- 用 `🟢/🔴/🔵/⚠️/⭐/🔁/⚖` 作为固定视觉锚点，但不要在不同层级随意混用。
- 把审计说明缩短为“裁决/辅助/确认/降级/状态可见”。
- 不重复“主推/裁决/不追单”四次；首屏加粗结论，底部只保留一次“下一步”和一次“失效”。
- 不使用宽四列表、Unicode框线、假对齐空格或图片表格代替 RichMarkdown 表格。

## 回归检查

- 运行 `python scripts/render_tv_card.py`，检查示例输出可扫读。
- 运行 `python -m pytest -q`。
- 检查每个表头前为空行，且表列数不超过 3。
- 检查 WAIT/NO-GO 不泄露旧的入场、止损、目标价格。
- 未经用户明确授权，不做真实 Telegram 外发；用 renderer fixture 或 monkeypatch 验证 payload。

## 研究依据

Telegram 已支持机器人富文本、表格和嵌套内容；Hermes 的 RichBlockTable 入口为 `sendRichMessage`。移动端交易信号的通用最小集合是品种、方向、入场、止损、目标和风险收益比，但棠溪的安全规则优先：只有 FinalVerdict=GO-A 且 executable=true 才展示执行三件套。
