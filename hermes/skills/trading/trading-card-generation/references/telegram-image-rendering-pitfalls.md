# Telegram 图片渲染坑（2026-08-31 实战铁律）

## 核心问题

用户手机 2160×3840（9:16 标准屏）。**Telegram 客户端对图片有"等比缩放显示到屏幕宽"行为**，导致长宽比异常 / 高度异常的图片**在预览框中被截切**。**图本身完整**（PIL `Image.open().size` 返回原像素尺寸正确），但客户端**只显示部分内容**——用户反馈"看不到了""下面没有了""裁了"。

## 用户反馈 → 根因映射

| 用户原话 | 根因 | 修复 |
|:---|:---|:---|
| "下面看不到" | 高度 > 2200px，预览框高度阈值约 60% 屏幕 | 高 ≤ 2000px |
| "下面绿色框看不到了" | 长图（2160×3840 / 1920×3444）下半被裁 | 高 ≤ 2000px |
| "右侧留白太多" | 宽度 > 1080px，缩放后右侧空白 | 宽 = 1080px（手机宽） |
| "不是表格" | Markdown 管道表被 TG 降级 | 改用 PIL 渲染 PNG |
| "应该是两张照片，分开发" | 嵌图+分析卡 = 单图太大 | TV 截图独立 + 分析卡独立 |
| "时间窗下面没有了" | 高度不够 | 让"📌 下一步"行紧贴底边 y = 裁剪高度 - 25px |

## 实战可用尺寸

| 尺寸 | 宽高比 | 适用 | 风险 |
|:---|:---:|:---|:---|
| **1080×1613** | 0.67 | 完整三表速读版 | ✅推荐 |
| **1080×2021** | 0.53 | 完整三表+完整性备注 | ✅Telegram 预览可能略裁 |
| **1080×1260** | 0.86 | 紧凑版 | ✅无裁切 |
| 1920×3444 | 0.56 | 9:16 准长图 | ⚠纵向裁切 |
| 2160×3840 | 0.56 | 设备原生 9:16 | ⚠纵向裁切 |
| 1200×870 | 1.38 | 紧凑横版 | ✅无裁切，但单页装不下 |
| 1200×1335 | 0.90 | 紧凑长版 | ✅无裁切 |

**默认出图尺寸：1080 × (内容高 + 40px 边距)**

## 边距/字号推荐

| 元素 | 推荐值 |
|:---|:---|
| 边距 M | 40-60px |
| 标题字号 | 36-40px |
| 副标题字号 | 24-28px |
| 正文字号 | 18-22px |
| 行高 | 52-72px |
| 推荐操作框边距 | 12-18px |

## 验证图是否完整

```python
from PIL import Image
import numpy as np

img = Image.open("outputs/btc_one.png")
arr = np.array(img)
H, W = arr.shape[:2]

# 找绿色框
green = np.array([63, 185, 80])
green_mask = np.all(np.abs(arr.astype(int) - green) < 20, axis=-1)
gr = np.where(green_mask.any(axis=1))[0]
print(f"绿框: y={gr[0]} ~ {gr[-1]}, 距图底 {H-1-gr[-1]}px")

# 看最底 50 行是否有内容（不能全背景）
last_50 = arr[-50:]
content_mask = np.any(last_50 != [13, 17, 23], axis=-1)
content_rows = np.where(content_mask.any(axis=1))[0]
print(f"最后50行内容: {len(content_rows)} 行, 最小y={content_rows[0] if len(content_rows) else 'N/A'}")
```

**判定标准**：
- 绿框距图底 < 30px → 推算成功
- 最后 50 行有内容 ≥ 30 行 → 推算完成
- 绿框距图底 > 100px → 留白太多，**用户会嫌"太长"**
- 最后 50 行全背景 → **被裁了**

## 单图 vs 多图

- **单图**：完整内容压缩到一张图（1080×1613 推荐）
- **分两张**：上半（标题+矩阵）+ 下半（执行+推荐）——**不要连续发两张图**，Telegram 客户端会**把第二张压成小图预览**
- **截图独立**：TV 截图单独发（full 窗口，含价格轴+CVD 窗格），分析卡不含 TV 截图
