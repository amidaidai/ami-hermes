# 原分析卡版式回归记录（2026-09-12）

## 适用场景
用户要求“按原分析卡/系统模板来”，或连续反馈“排版难看/不是这个格式”。本文件只记录可复用的版式回归规则，不是某次行情结论。

## 根因
自定义卡把“位置、方案、推荐理由、最终裁决”拆成多个新标题，导致：
- 首屏没有原模板的“现在在哪/现在怎么做”；
- 方案理由漂移到表格外，用户看不出为什么A优先；
- 价格已经靠近VAH却仍被描述为POC/S VWAP中轴；
- A/B看似并列，最优推荐不够明确；
- WAIT卡容易泄露未经授权的入场/止损/目标。

## 正确输出骨架
```markdown
MEDIA:<本轮15m全屏截图>

YYYY年M月D日 HH：MM · BTC

一、现在在哪：{现价相对最近具名结构位的位置}
二、现在怎么做：{直接动作 + 触发条件}

① 当前结构
{≤3列表}

② 多周期定位
{D/4h/1h/15m/5m，周期/状态/裁决}

③ 关键位矩阵
{方向/具名结构位/用法}

④ 多源验证
{维度/数值/方向}

⑤ 执行方案
{方案/触发/动作与推荐理由}

⑥ 最终裁决
{唯一⭐主推、理由、是否执行}
```

## 方案行规则
- `⭐A主推`：触发条件、动作、推荐理由完整写在同一行/同一单元格。
- `🔁B备选`：仅主推失效后的路径，不与A平权。
- WAIT/C：只写观察触发、失效条件和“未授权”；不输出订单三件套。
- 方案的“最优”不是方向强行变成GO；可以是“最优等待路径”。

## 位置校验例
- `现价 < 15m VAH` 且距离很近 → “15m VAH下方，等待收复或拒绝”。
- `现价`落在 POC/S VWAP附近 → 才写“中轴争夺区”。
- `15m VAL + 4h POC` → 写作复合具名支撑，不简化为“下沿”。
- 远端周高/周低/磁吸位 → 写“后续观察”，不写成当前唯一触发位。

## 出卡前检查
- [ ] 首屏有“现在在哪/现在怎么做”两句。
- [ ] 正文只有①—⑥六段，未发明同义重复标题。
- [ ] 每张表≤3列。
- [ ] 每个价格绑定具体结构名称和动作。
- [ ] A/B均有触发、动作、理由；A唯一⭐主推。
- [ ] WAIT/C没有入场、止损、目标数字。
- [ ] 最终裁决在正文最后，并明确是否执行。
