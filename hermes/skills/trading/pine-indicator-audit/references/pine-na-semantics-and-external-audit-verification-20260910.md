## 一、`array.sum` 的 na 语义 —— 我写错过，以官方为准

**官方语义**（tradingcode.net / TV 文档核实）：

- 数组**只含 na** → 返回 `na`
- 数组**有非 na 元素** → **忽略 na**，求和其余

**我写错过**：曾以为「遇任一 na 就返回 na」。实测触发条件是「该格两条腿都 na」。

**修正后的因果链**（AggVol 实测复现）：

```
GetRequest() 用 ignore_invalid_symbol=true → 不存在的腿返回 na
COINBASE 的 USDT.P / USD.P 两个永续后缀都不存在 → 该格 array 只含 na
→ array.sum 返回 na → PERP 求和 na → AggregatedVolume na
→ usingAggregatedFeed / fallbackToChartFeed 双双为假（na 比较恒 false）
→ Coverage Feed Mode = 4 → haldroUsableA = false → 副指标自废成 S0
→ 主指标 aggGateDegraded → A 级永久被禁
```

**推论（很重要，必须能自称）**：na 安全改造 `Σ nz(x_i)` 对「部分 na」场景**行为完全不变**
（`nz(na) + 有效值 == 原 array.sum 结果`），只把「全 na」从 `na` 改成 `0`。
→ 这类改造**可以声称没有改动任何原本正常的路径**，但必须用算式复算钉住。

**修复模板**

```pine
EditVolume(type)=>
    Type = 0.0
    for _vi = 0 to array.size(type) - 1
        Type += nz(array.get(type, _vi))
    ...
```

**反例复算**（写进验收脚本，别只在心里算）

```
legs = [1234, 987, 456, na, 321]
修复前 naive（全 na 才 na；此处仅 1 腿 na → 不触发）
真实触发场景：legs 全 na 的某一所
修复前 naive = na → AggregatedVolume = na → FeedMode = 4（设计外）
修复后 safe = 2998 → AggregatedVolume = 7998 → FeedMode = 1
全腿缺失时 safe = 0 → FeedMode = 2（设计内回退）
```

> 铁律：**聚合类求和要逐元素 `nz`，不能只在最外层给总量套 `nz()`** ——
> 那会吞掉其他所有有效所的成交量，等于静默削源。

## 二、na 比较恒为假 → 「双布尔同假」是隐藏 na 的指纹

```pine
bool usingAggregatedFeed = datatype == 'Aggregated' and AggregatedVolume > 0
bool fallbackToChartFeed = datatype == 'Aggregated' and AggregatedVolume <= 0
plot(usingAggregatedFeed ? 1 : fallbackToChartFeed ? 2 : 4, "Coverage Feed Mode")
```

设计上只有两个状态（1 聚合 / 2 回退），却观测到**第三态 4** →
不是「既不 >0 也不 <=0」，而是**上游是 na**。

**排查口诀：三态 plot 落到设计外的值 ⇒ 先去找 na，别去改判定顺序。**

## 三、把一个量拆成两个语义不同的布尔，是这类 bug 的温床

`X and A > 0` / `X and A <= 0` 看似互补，但**X 为假时两个都假** → 落到第三态。
凡是写这种互补对，都要追问一句：**「X 为假时落到哪？」**
（本次的另一半：`datatype == 'Single'` 时 `haldroUsableA` 恒 false ——
聚合缺失与 Single 模式共用同一个开关，修的时候必须一起改，
否则会出现「聚合修好了、Single 仍然自废」。）

## 四、外部审计指控的取证方法（本次用它核了 20 条）

当另一个模型/AI 交来一份审计报告要你「看看」时，**不要复述、不要采信、也不要凭印象赞同**：

1. **先证明审计对象与手上文件是同一份** —— sha256 逐字节比对。不同就一切免谈。
2. **按它给的行号把原文抠出来**逐行读，**读源码不读它的转述**。
3. **对可计算的指控做算术反例**。它给算例就复算，对不上就直接标记存疑。
   本次它给 `triggerPack = 1099899`，复算 `(0+10)*100000 + 999*100 + 0 + (-1)` 完全吻合。
4. **分四档记结论**：已确认 / 部分确认 / 未复核 / 证伪。
   **没查的绝不写成默认成立** —— 报告末尾单列「未复核」。
5. **主动找它纠正自己的地方**。本次它纠正了我的 `array.sum` 机制表述。
   被外部审计纠错要写进报告，不要悄悄改。
6. **必须给出「我不同意的部分」**，哪怕是「方法不同但结论一致」。

### 四-bis、核验完之后的交付形状（7 节，别少）

1. **结论先行**：它质量如何 + 逐条计数（例：18 条取证，15 完全成立 / 3 部分成立 / 0 误报）。
   **0 误报也照实说** —— 不为了显得有主见而硬找分歧；「基本没有分歧」是好结论。
2. **逐条核验表**：编号 / 它的指控 / 我的源码取证 / 判定（带行号）。
3. **它纠正了我什么** —— **单独成节**，写明我改了哪行注释/代码。被外部审计纠错要写进报告，不要悄悄改。
4. **我不同意什么** —— 没有就写「基本没有」，绝不编造分歧。
5. **它没覆盖到的** —— 你手上的独有发现（尤其是**严重性升级**：它说数据错，你核到实际是执行授权被闸死）。
6. **重排实施顺序** —— 按「改动风险 × 影响面」，**不要照抄它的顺序**。
7. **验收矩阵** —— 好用就采纳并说明补了什么。

**它的推测要单独标出**：审稿里「可能导致…」「也许还会…」的句子，不要写成已被你的复核验证。

### 四-ter、若修复会改变行为，必须单独披露

审计建议里有些不是「修 bug」而是「改行为」。这类交付必须附一节
**「装上后会看到什么变化」**，逐条写清用户能观察到什么，例如：

- 执行门槛变严 → **A 级执行次数会变少**
- 去掉重复偏移 → HTF 区域**提前一根高周期柱**出现
- 事件不再被显示开关吃掉 → **扫线事件变多**，结构/评分跟着变
- 包装值/合同号变了 → **主副必须同时换**，只换一侧会 fail-closed

并明确区分两档：

| 档次 | 含义 |
|---|---|
| **已验证** | 逻辑与编译过了（可声称） |
| **需实盘观察** | 触发条件本地复现不了（如 RTH 股票会话、48h 后的稳定位退役）——**不得冒充已验收** |

另：若审计的修复只验证了逻辑、没做样本外回测，要明说「会不会改变胜率得靠样本回答」，
**不要把「逻辑正确」说成「效果更好」**。

## 五、被核实的 Pine 缺陷模式（可直接当检查清单复用）

| 模式 | 特征 | 检查手法 |
|---|---|---|
| `array.sum` 全 na | 聚合量变 na 向下游传播 | 见第一节 |
| 双布尔同假 | 出现设计外的第三态 | 见第二节 |
| **HTF 返回值重复偏移** | UDF 内部已用 `[1]`/`[3]`，返回元组又 `[1]` → 最新位置变 `[2]`，**多滞后一根高周期柱**（日线多等一天、4h 多等 4 小时）。是延迟不是未来函数 | 看 UDF 内部与返回处是否**都**偏移 |
| **打包最低位可为负** | `... + (code + 1)` 而 code 可为 -1/-2 → **向高位借位**，把 age/fresh 字段一起搅乱 | 枚举每个字段的**最小取值**，`< 0` 就是雷 |
| **紧凑格式化用于执行价** | `"#.####"` 这类格式串：Pine 里 `#` 是**可选**占位符 → 丢前导零（`0.5` → `.5`）、低价品种（`0.00001234`）直接显示 `0` | 用户要照着执行的入场/止损/目标价必须 `format.mintick`；紧凑格式只给百分比/倍数/成交量 |
| **`nz(x, 0)` 兜零掩盖缺失** | 下游无法区分「数据缺失」与「真的 0」→ 面板显示「持平 0.00%」 | 缺数据要**独立有效位**，不是兜零；升级格式要带合同版本 |
| **显示开关改变业务状态** | `isHidden` 先置位，事件扫描又要求 `not isHidden` → **同一根刚发生的事件被自己吃掉** | 视觉状态与业务状态必须分离：先登记事件，再按显示规则处理对象 |
| **按优先级先选后判新鲜度** | 高优先级候选已过期，仍压住新出现的低优先级候选 → 显示「触发过期」 | 每个候选**先过滤**（方向/区域有效/新鲜度）**再**排序 |
| **会话靠 `isSession` 布尔翻转** | 只显示常规时段（RTH）的股票图，相邻两根都 in-session，中间没有 false 柱 → **永不换日**，极值跨日累计 | 需要 session ID / 交易日边界，不能靠布尔翻转 |
| **对照品种只用 close** | 本品种用 `high/low`，对照只请求 `close` → 对照影线创高但收盘回落时被漏判 | 两边请求同一组 OHLC；正/负相关分支要分别定义对应极值 |
| **计价货币只看图表** | `syminfo.currency` 是**图表**货币，不是每条 `request` 的货币 | 每个源单独判计价 + 汇率；不可换算的源要排除并说明 |

## 六、验收要覆盖的边界（写断言时别漏）

- **单所整类缺失 / 整所缺失 / 全部缺失 / 真零成交** 四种情况，总量、覆盖率、回退标记、状态码要一致
- **价格精度要测 `0.0001` 量级的品种**（只测 BTC 完全看不出格式串问题）
- **聚合类的 `Feed Mode` 只允许落到 1 或 2**；落到 4 就是异常态，不允许出现
- 面板明确显示「等待解除某条件」时，**执行导出必须无效**；仅提示风险时不得用「否决/不执行」措辞
