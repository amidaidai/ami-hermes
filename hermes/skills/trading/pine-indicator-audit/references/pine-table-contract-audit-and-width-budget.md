# Pine 表格内容审计：逐行职责合同 × 宽度预算（2026-09-10）

适用：用户问「表格内容要不要优化 / 还能怎么优化」时的**取证方法**。
不是重新设计表格，而是拿**已定稿的逐行职责合同**逐行比对代码，找「合同未落实」与「信息丢失」。

## 1. 三步取证法

1. 从合同参考（`references/pine-dual-indicator-table-and-bus-integrity-20260827.md` 等）抄出每一行的**职责边界**：该行只负责什么、明确禁止重复什么。
2. 逐行列出**实际拼装表达式**，标注它消费了哪些上游文本变量。
3. 找三类问题：
   - **跨行重复**：同一个上游变量被两行消费（合同通常明文禁止）。
   - **逐字重复**：同一字符串在两张行出现。
   - **信息丢失**：上游有变量、注释写着「要显示」，但 rows 里没有任何消费者。

## 2. 四类可复用检查项（2026-09-10 实证）

| 类型 | 实证 | 判据（合同原文） |
|---|---|---|
| 跨行重复 | 结论行 `actionStateText + " ⚠" + panelRiskOne`，风控行又 `+ "·阻:" + panelRiskOne` | 「风控：若结论已显示阻断原因，不再重复 `阻:`」 |
| 逐字重复 | 协同行与结论行都输出 `副S3冲突·不执行` | 同一字符串出现两次 |
| 机器式拼接 | 副表流向行无条件 `本锚 + 滚动 + 前锚` 三段 | 「不要每次机械拼接；前锚只有冲突时才值得占宽」 |
| 信息丢失 | `entryDistAtr`（入场距离）、B/C 人工候选的入场价 | 注释写「决策原语」，rows 里无消费者 |

修法顺序固定：**先互斥**（抽一个共用 bool，让两行二选一消费，信息不丢）→ **再压宽**（同向/平/na 一律不占宽）→ **最后才补信息**。

跨行重复的正确修法示例：抽 `riskInConclusion = panelRiskOne != "" and not str.contains(actionStateText, panelRiskOne)`，
结论行与风控行互斥消费。这样无论哪种状态，阻断原因都恰好出现一次——**不是简单删掉一处，那会丢信息**。

## 3. 「computed-but-unused」的正确分流

不要一律「接回表格消费」（会撑宽），也不要一律删（会丢决策原语）。分两类：

- **重复路径 → 删**：语义已被另一行/另一字段完整承载。
  实证：`panelEntryVal`（整句进场许可）＝ 结论行 + 路径行之和；`rdyGauge` ＝ 方向行「条件x/10」；
  `magnetTarget*` ＝ 磁吸行 `f_mag_text`；`chartTfSec` ＝ `curTfSec`；`volume_buy/volume_sell` ＝ 被 `deltaLtf/deltaWick` 取代。
- **真丢信息 → 接回并条件化**：是设计好的决策原语，只是没有消费者。
  实证：`liqOIDropA`（去杠杆 OI 收缩幅度）、`htfTxtA`（上级方向）、`atrPctile`（波动率分位）、
  `cvdBgDecoded`（副总线 CVD 背景码）、活扫位计数（活N/M）。

**判定问句：这条信息在别的行里能不能读到？** 能 → 删；不能 → 接回，且**必须加条件**（仅在冲突/异常/存在时占宽），否则常态撑宽。

## 4. 宽度预算的记账方式

- 逐行枚举最坏组合、算 CJK 字符等价值，报 **Top-3 最宽行**，给「改前 → 改后」。
- 「变宽的行」和「变窄的行」一起报，说明净效果。
- 主表声明 `table.new(…, 2, N)` **不等于**实填 N 行；以 `array.push(rowLabs, …)` 的实际数量为准（本轮仍 13 行 ≤ 18）。
- 副表固定 6 行是**硬合同**：要加新信息优先「挤进已有行」，不要加行、不要加第三张表。

## 5. 执行权边界：不要擅自扩大「表里出现的价位」

A 级「待确认态」（`displayLongA` 成立但 `executablePlan` 未成立：等收线/等触发）当前**不显示** 止/标/R:R，
因为 `visiblePlan = executablePlan or manualBcCandidate`，`panel*` 字段全部为 na。

把 `visiblePlan` 扩到待确认态、让风控行显示 `观察·入…·止…·标…·R:R` —— 这属于**改变「什么价位出现在表里」的显示语义**，
是用户的执行权边界。**可以分析、可以推荐，但必须用户明确同意后才能实现**，不得在「优化表格」名义下顺手改掉。
同理：X/WAIT 时执行 Entry/Stop/Target 恒空；B/C 价格只进人工候选字段；`replay*` 执行导出只在 A 可执行时有值。

## 6. 增强建议的交付形态

用户问「还需要怎么增强」时，输出**分级清单 + 配额账**，每条含：现状（源码证据）→ 改法 → 代价（request/plot/input/六项和）→ 价值 → 建议做/后置。
必须附一节「明确不建议」（伪增强），典型：第三套 CVD、第二套评分或胜率百分比、增加交易所覆盖、
更多颜色/标签/行、把 OHLC 估算包装成真实 footprint/清算量、把「OI 上升」直接写成「多头增加」、新增 `alertcondition`。
