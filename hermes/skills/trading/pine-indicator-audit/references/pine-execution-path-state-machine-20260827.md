# 主指标执行路径状态机

适用于 SVP/ICT 类人工决策主指标，把“到位后怎么做、下一步等什么、何时放弃”落成不扩表的路径行。

## 设计原则

- 主指标仍是唯一执行授权源；副指标只能支持、降级或否决。
- 不增加表格行、不增加警报、不增加交易执行。
- 表格只显示“最近完成步骤 → 当前唯一下一步”，不能把候选步骤写成已发生。
- 严格区分：到位 ≠ 反应，反应 ≠ 结构确认，结构确认 ≠ A执行。
- WAIT/X/B/C 不得在路径行输出可执行价格；B/C只能标为人工候选。

## 推荐状态

`0=无方向/无可靠位置`、`1=等到位`、`2=已到位等反应`、`3=反应完成等结构`、`4=结构完成等收线/协同`、`5=条件齐可执行`、`-1=路径失效`、`-2=触发过期`、`-3=硬阻断`。

若受 Pine token/外部元素限制，第一版可以用已有 `triggerCode`、`triggerFresh`、`barstate.isconfirmed`、聚合状态和 `executablePlan` 拼装路径文本；后续再将其收敛为持久化 `pathStage/pathModel/pathFailCode`。

## 触发优先级陷阱

简单的 `swept ? 1 : mss ? 2 : ...` 会在扫位条件持续为真时把路径永久卡在扫位阶段。至少要让更高阶段（如 MSS）优先，或按事件年龄/持久状态推进。修改触发编码顺序后，必须同步检查 triggerAge、triggerFresh、activeTriggerText、triggerPack 以及所有依赖触发码的执行门。

## 结论优先级

最终展示应遵守：

`低流动/硬X > R:R硬阻断 > 总线未接/副S3冲突 > 副S4降权 > CVD/结构冲突 > 触发过期/未收线 > A执行 > B/C > 等方向`。

实际项目如已有明确合同，应拆成 `hardBlockCode / waitCode / warningCode / finalActionState`，让结论、路径、价格输出和 Data Window 共用最终状态。

## 路径文案

- 未触发：`等到位/等回踩○`
- 已触发未收线：`MSS↑✓→等收线`
- 副指标冲突：`主触发✓→等副同向`
- 数据降级：`主触发✓→等数据恢复`
- 已执行：`条件齐✓→A执行 价格`
- 过期：`MSS↑过期×→等新触发`
- 失效：`失效×→等新位`

完整路线不常驻表格，避免过宽、重复和把未来步骤误读为当前事实；完整编码可放 Data Window。

## 路由模型

优先按胜出位置选择路径：流动性位=扫位→收回/拒绝→MSS→回踩；FVG/OB=承接/承压→位移/MSS→回踩；VAH/VAL/VWAP=站回/跌回→MSS→回踩；趋势=等回踩/反抽→不破→位移→协同；VA中部=不追→等出区或VA边。

路径、现位、Entry、Stop、Target必须尽量绑定同一个 winner zone。若暂时无法建立统一对象，路径文案不得声称首次回踩或承接已完成，只显示已有布尔条件真正证明的阶段。

## 验收矩阵

1. 主表仍13行，原“进场”行可改为“路径”，不增加行数。
2. 同一根/连续K中，扫位持续为真时 MSS 能推进，不永久停在扫位。
3. X同时伴随未收线/过期时，结论显示X，不显示普通等待。
4. 触发未发生时，路径显示预期动作，不显示Entry执行价。
5. B/C只显示人工候选，绝不升级A。
6. 副S3/S4优先显示对应的冲突/恢复动作。
7. triggerCode调整后，triggerAge、triggerFresh、triggerPack无语义错位。
8. 云端编译通过不等于 TradingView 客户端真实加载、接线和回放验收；两者必须分开报告。
