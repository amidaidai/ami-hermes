# 20260814 收尾：TV 3.3.0 注入失效 + 交付隔离规范 + 副指标文案定稿

来源：20260814 会话末段。CE10117 修复后用户反馈两件事：①拿错文件仍报 101085 token 超限 ②副指标"结论专业一点，压缩一下宽度，信号也是"。

## 一、TV 3.3.0 Monaco 注入路径失效（pitfall，20260814 实测）

- 现象：`FIND_MONACO`（React fiber 路径，core/pine.js 的标准做法）在 TV 3.3.0（Chrome 140/Electron 38）图表页上**整条 DOM 链找不到 `__reactFiber$`**；`window.monaco` 不存在；全局只有 `MonacoEnvironment`（AMD loader 配置）。
- 含义：pine 编辑器 Monaco 实例不再通过 React fiber 暴露，之前 references 里"Monaco 查找复用 core/pine.js FIND_MONACO 逻辑"的注入法在此版本失效。
- 处置（本次采用的验证闭环）：不依赖桌面注入也能完成编译级验证——`translate_light` 全量编译（语法+警告）→ TV 桌面编译结果用**逻辑推断**（同源注释更少的版本 token 必更低）→ 交付。
- 未来会话若需真实桌面编译验证：先探测 `document.querySelectorAll('.monaco-editor.pine-editor-monaco')` 的 fiber 可达性再决定路径；Monaco 可能在 AMD 模块作用域内（`MonacoEnvironment` 相关），或用 `tv_pine_check_files.mjs` 的 translate_light 端点做最终验证。
- 注意：这是版本状态观察，不是"注入永久不可用"——TV 版本滚动快，下次先探测再选路径。

## 二、交付文件隔离规范（用户报错教训）

- 事件：超 token 的"完整注释存档版"与可编译版放在同一交付目录，用户拿了存档版报 CE10117（101,085/100,256）——数字与存档版一致。
- 规范：**不可编译的存档/实验文件必须放入 `存档_勿用` 子文件夹**（或文件名前缀 `_存档_`），交付目录顶层只放可编译最终版；交付说明里点名"只复制最终版，别碰存档"。
- 教训：审计会话会产出多个版本（审计LF版/P2修复版/增强最终版/注释存档版），用户无法从文件名判断哪个可编译——隔离 + 点名是最低成本的防错。

## 三、副指标文案专业化+压宽定稿（用户明确偏好）

用户要求"结论专业一点，压缩一下宽度，信号也是"。定稿规则：
- **术语化**：口语词全部替换为标准术语——"轧空冲顶"→"挤空冲顶"、"踩踏杀跌"→"抛售踩踏"、"实涨可信"→"增量买盘"、"真实下跌"→"抛压主导"、"多向/空向未确认"→"多头/空头未确认"。
- **主词化**：去口语助词（"疑似/别急追/风险大/警惕/或"），保留状态词+动作词——"挤空冲顶 · 防反转"、"价量背离 · 慎追"、"涨势衰竭 · 空头回补"、"缩量上涨 · 勿追"、"逆高周 · 降级"、"去杠杆 · 防反弹"。
- **压宽**：目标每分支 ≤9 全角字（原 12-14 字，平均 -40%）；缺票维度空格分隔改点分隔（"缺OI HTF"→"缺OI·HTF"）。
- 边界：动作词（勿追/慎追/防反转/防反弹/降级）一个都不能删；"强确认多/弱确认多"等已专业词不动；操作行 comboTxt 未点名不动。

## 四、主指标注释精简规则定稿（CE10117 配套）

- TV 客户端编译 token 上限 100,256，**注释计入 token**（详见 pine-20260814-ce10117-token-limit.md）。
- 可编译交付版的注释保留规则：整行注释仅保留含关键词（202608/2026-/审计/修复/P0-P3/口径/诚实/铁律/估算/proxy/请求/配额/多市场/定稿）且 ≤64 字符的审计锚点行；**行尾注释全部删除**；装饰分隔线全删。
- 本轮实测：删 13,926 字符注释后（219,618 字符），translate_light 0 错 0 警，token 逻辑上低于已通过桌面的 lean 版。
- 完整注释版只作存档（隔离在存档_勿用），任何未来交付都遵循此规则。
