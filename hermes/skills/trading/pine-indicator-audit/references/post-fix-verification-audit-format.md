# 修复后验证审计格式 (Post-Fix Verification Audit)

> 适用场景：用户上传 `_fix.pine` 文件，要求审计"修过的版本"。与首次发现审计（`comprehensive-audit-deliverable-format.md` 8段）互补——验证审计的核心任务是**确认已修复、验证一致性、推荐行情**，不是重新发现问题。

## 一、触发条件

- 文件名含 `_fix` 或用户说"审计这些"且是上一轮修复的产物
- 修复列表已在注释中标注（`20260810 审计修复（P0/P1/P2）`）
- 用户末尾跟"辅助决策怎么推荐" → 需要同时出行情推荐

## 二、6 段输出骨架

### 1. 静态统计总览（必须）

用 `scripts/static_scan.py` 跑双指标，输出对比表：

| 维度 | 主指标 | 副指标 | 备注 |
|---|---|---|---|
| 行数/字符/token | | | vs 上次基线 ±N |
| request.security | | | ≤40 ✓ |
| plot/bgcolor/fill | | | 最坏式 ≤64 ✓ |
| alert()/alertcondition | | | |
| MCP DW plot | | | |
| 性能热点（barssince/valuewhen/na/str.tostring） | | | |
| 疑似死变量 | | | |

### 2. 配额合规判定（必须）

逐项打 ✓/✗：plot ≤64、request ≤40、alertcondition=0(免费)、intrabar ≤100K、max_bars/labels/poly/box ≤上限。

### 3. 已修复问题确认（必须，核心区别）

逐条列出注释中标注的修复（如 `20260810 审计修复（P0-1）`），每条标 ✓。这是验证审计的灵魂——确认上轮发现的问题确实已修。

格式：
```
### 主指标 — N 项已修复
| 优先级 | 问题 | 位置 | 状态 |
|---|---|---|---|
| P0-1 | 市场判定用 ticker 字符串 | L277 | ✓ |
...
### 副指标 — N 项已修复
...
```

### 4. 锚定一致性矩阵（必须）

market×timeframe 矩阵表，逐格标 ✓/✗。SVP 1d+→12M 是有意分叉需标注。

### 5. 主副协同链路验证（必须）

逐链路验证数据传递是否完整：OI 数据源、状态包、守卫条件、锚定口径、HTF 映射、市场判定六条同源链。

### 6. 剩余优化建议（非阻塞，O1-O5 级别）

仅列"非致命可优化项"，标 O1/O2 级别。末尾必须给结论："无 P0/P1 致命问题"。

## 三、行情推荐（用户要求时附加）

用户末尾跟"辅助决策怎么推荐"时，审计后追加行情推荐：

1. **实时行情获取**：用 `browser_navigate` 打开 `tradingview.com/symbols/BTCUSDT/` 和 `tradingview.com/symbols/XAUUSD/`，从 a11y snapshot 中提取价格/涨跌/日内区间。web_search 限流时此法可靠。
2. **多源交叉验证表**：日内/周/月方向 + 新闻线索 + 结构位置
3. **推荐结论**：⭐ 主推一个品种 + 入场/止损/目标/失效/逻辑
4. **禁做**明确标出
5. 只有通读指标确认无 P0 后才推荐——如果发现 P0，先修再推

## 四、与首次发现审计的区别

| 维度 | 首次发现审计 | 修复后验证审计 |
|---|---|---|
| 段数 | 8 段 | 6 段 + 行情 |
| 联网 | 必须(社区对标) | 可选(行情) |
| 核心段 | P0/P1/P2 + 10条建议 | 已修复确认 + 一致性矩阵 + 协同链路 |
| 社区能力清单 | 必须列 | 不需要 |
| 输出导向 | "修什么" | "确认修好了 + 推荐行情" |

## 五、写作风格（继承棠溪偏好）

- 中文为主，专有名词用英文
- 中文日期「2026年8月10日」+ 全角冒号
- 不用装饰分隔线（═══、━━━）
- 表格驱动
- 缺失须注明
- 末尾给"可上 TV 编译实测"或"有 P0 须先修"
