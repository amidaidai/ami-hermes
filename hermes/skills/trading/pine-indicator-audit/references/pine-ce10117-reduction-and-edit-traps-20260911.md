# CE10117 减重 与 大文件 Pine 编辑陷阱

来源：2026-09-11 主指标（3,553 行）撞 CE10117 后的完整减重过程。
适用：任何 3,000 行量级、已接近编译上限的 Pine v6 指标。

> 本文件尚未写入 SKILL.md 的核心参考索引 —— 因为 SKILL.md 已超过 100,000 字符上限，
> 无法再 patch。请从 `linked_files` / references 目录发现本文件。

## 1. CE10117 的事实（不要猜）

- **上限 100,256 个 token，硬限制，与套餐无关。** 官方文档原文：
  "The IL form of each indicator, strategy, and library script can contain a maximum of 100,256 tokens."
  → **升级订阅解决不了**。网上那些「limit is 72000」是 2024 年的旧值。
- **云编译（`translate_light`）不查这一项。** CE10117 / 64 绘图槽上限 / 面板缩放
  全是**客户端检查**。
  → 本地**无法**验证是否过关，真正的验收是用户贴进 Pine 编辑器编译一次。
  → 所以交付时必须说清：给的是**推算值**，不是回执。

### 先反推基线，再决定叙事

用用户报的数字反推改动前的状态，避免把「撞顶」说成「你改坏了」：

```
比例 = 用户报的 token / 交付文件字符数
本案例：100,490 / 229,285 ≈ 0.438 token/字符（≈2.28 字符/token）
```

若本次改动只加了 D 个字符，则改动前 ≈ 报数 − D×0.438。
**本例反推：v13 时就已经约 99,100/100,256（99%）—— 是撞顶，不是回归。**
这句话决定了后续对话：到底该「削一点」还是「必须删功能」。

## 2. 官方指定的两条减重手段（其余都是徒劳）

社区/官方口径一致：**缩短嵌入常量字符串** + **减少重复代码 / 把重复逻辑封装成函数**。

- **注释和空白在分词前就被剥掉 → 删注释不省 token。** 不要承诺从注释里省。
- **变量名长短几乎不影响。** 不要靠缩短标识符。

### 实测收益排序（照这个顺序找）

| 顺位 | 目标 | 本案例收益 | 做法 |
|---|---|---|---|
| 1 | **tooltip 字符串** | 1,894 → 988 字符 | 见下方「tooltip 压缩」 |
| 2 | 重复子表达式 → 提升到**已存在**的全局 | ~308 字符 | `timeframe.in_seconds(timeframe.period)` ×11 → 已有的 `curTfSec`。**先查有没有现成全局**，别再新建 |
| 3 | 重复的颜色/常量表达式 → 一个 `const` | ~145 字符 | 5 处 `color.new(BG_COLOR, BG_TRANS)` → `color LBL_BG = ...` |
| 4 | 重复的连续代码块 → UDF | ~200 字符/处 | 用滚动窗口重复扫描器定位（见下） |
| 5 | 一个函数体被内联在另一个函数里 | ~260 字符 | 让第二个直接调用第一个（并把它定义**移到调用点之前**，否则 CE10271） |

### tooltip 压缩（收益最大，但有下限）

规则化：先去掉尾部 `...`，再截到**最后一个完整分句**（分隔符 `；;，,。`），
最后按 ~16 字符做边界感知截断。

**下限是 16 字符，不要压到 12。** 12 字符中文会被切成
「只想要确认行的FVG✓信」这种半句，help text 直接失效。
16 字符仍可读：「关闭后不显示VAH/VAL线条」。
压缩前先确认原文在 git 历史里可取回，并在交付说明里写清「信息有损」。

### 定位重复块的扫描器（写进脚本，别靠肉眼）

把每行归一化（去注释、压空白），对 3–9 行的连续窗口做指纹，
按 `块长 × (副本数−1)` 排序输出。这个扫描器一次就找出了：
周池复位块 ×2、`mergedLabels` 清理 ×2、会话状态复位 ×1（18 行）、
批量推入 vs `storeSingleBar` 同构。

## 3. 绝对不要做的「减重」：位移打包字段

想给打包整数（Basic Packed Bus 之类）加一个字段时，**最容易想到的做法是把合同号
往上移一位（×1e10 → ×1e12）腾位置 —— 这会越界 2^53，整数精度静默崩掉。**

本案例：`22003 × 1e12 = 2.2e16 > 2^53 ≈ 9.007e15` ✗

**正确做法：用值域哨兵，零位移。**
编码域是 `1..19999`（`10000 + round(pct*10)`，pct ∈ [-999.9, 999.9]）时，
`0` 天然不可达 → 拿它当「缺失」哨兵。合同号只升不位移（22002 → 22003），
主指标同时接受两版（旧语义：0 就是 0.00%；新语义：0 = 缺失）。

配套必做：算一遍**最大合法包**并断言 `< 2^53`。
本案例最大 `2200342299199994 < 2^53` ✓

同类失败模式还有 `nz(x, 0)` 把「没有数据」写成「0.00%」——
判「接没接上」必须同时有**值**和**有效性位**，不能只看量程。

## 4. 锚点式改稿的编译陷阱（全部实测踩过）

做大文件的行级替换时，下面每一条都真实发生过：

| 错误码 | 症状 | 根因 | 修法 |
|---|---|---|---|
| **CE10013** | `Mismatched input ... expecting end of line without line continuation` | 替换串**丢了锚点的行首缩进**，注释/语句落到第 0 列，打断了外层 `if` 块 | 替换串的续行必须带与锚点相同的缩进 |
| **CE10163** | `Ternary operations cannot return tuples` | `cond ? request.security(..., [o,h,l,c]) : [na,na,na,na]` 非法 | **请求无条件执行，用三元选「品种」**：`string s = cond ? alt : syminfo.tickerid`，再 `[a,b,c,d] = request.security(s, tf, [o,h,l,c])`。回退到图表自身品种几乎无成本，且不破坏历史预取 |
| **CW10018** | 变量在局部作用域声明 | 在**函数内**引用 `localVar[1]`。函数内局部变量不带可靠历史 | **提升到全局**：`int gKey = ...` + `var int gKeyPrev = na` + `bool gRolled = not na(gKeyPrev) and gKey != gKeyPrev` + `gKeyPrev := gKey` |
| **CE10298 / CE10198** | `Object has no field {fieldName}` | 插代码时锚在 `type` 块里**不是最后一个**的字段上，把类型**切成了两半**（后半段字段变成游离行） | **先 dump 整个 type 块**，锚在真正的末尾（用连续两行字段做锚）。任何「插在声明 X 之后」的编辑都要先确认 X 的块范围 |
| **CE10271** | `Could not find {kind} '{fullName}'` | 把内联代码改成调用，但被调函数**定义在调用点之后** | 把被调定义**移到第一个调用点之前** |

### 两个非编译器的坑

- **自引用常量**：把重复表达式抽成 `color LBL_BG = <expr>` 时，如果先插入定义再全局替换，
  定义行会变成 `color LBL_BG = LBL_BG`。
  → **先替换掉所有用法，再用原始字面量插入定义。**
- **锚点必须全行 + 断言命中数**：`assert t.count(old) == 1`。锚点没命中要**大声失败**，
  绝不能静默 no-op —— 静默 no-op 会让你以为改完了。

## 5. 改稿机制（大 .pine 专用）

- **不要用 shell heredoc 或 `python -c` 跑正则。** shell 会把反斜杠吃掉
  （`[^"\\]` 变成 `[^"\]` → `re.error: unterminated character set`）。
  写进 `.py` 文件再跑。
- **原生 Windows Python 不认 MSYS 路径**（`/c/Users/...` → 找不到文件）。
  传 `C:/Users/...` 正斜杠原生路径。
- **每轮一个带日期的脚本**（`fix_<主题>_<日期>.py` / `shrink_rN_<日期>.py`）：
  读上一版 → 逐条断言锚点 → 写**新**版本文件 → 打印字符/行数/sha 变化。
  **不要原地改**，版本链就是回滚点。
- 每轮之后三件套：云编译 `has_errors` + 绘图槽估算器 + 全量 pytest。
  云编译只抓语法/语义，**不抓 CE10117，也不抓 64 绘图槽**。

## 6. 接口同步：缩短绘图标题会静默打断桥接

Data Window 的 plot 标题被桥接层**精确匹配**
（`scripts/tv_indicator_contract.py` 的 `DW_MAIN` / `DW_SUB` / `DW_ALIASES_*`）。

**减重时缩短 `plot(..., "<标题>")` 会静默丢字段**：Data Window 里明明有值，
桥接层按旧长名找不到。

→ 改标题必须**同一次改动**里同步 contract 别名 + 对应回归测试。
→ 该 skill 的 `test_dw_names_match_indicator_source` 就是这个守卫；
   重命名后它失败是**守卫在工作**，不是误报。

## 7. 面板行内容规则（两轮用户纠正后的定稿）

触发原话：第一轮「结构行太长了，优化一下」；第二轮「磁吸行也要优化一下，感觉重复太多」；
以及关键的**回撤**：「结构行这个感觉原来的也不错，但是要优化一下」。

### 7.1 重复判据（按这个顺序查）

1. **行标签算作行的一部分。** 标签已是「磁吸↑/磁吸↓」，值里再写 `↑/↓` 就是重复 → 删值里的。
2. **同一行内不重复同一个词。** 结构文本已说「多趋势」，regime 又说「趋势」→ 删后者。
3. **同一件事不要跨行说三遍。** 一条信息全表出现三次，一定有一处是赘的。
4. **满窗/满配的计数字尾不要每行都挂。** 磁吸 `40%(12/30)`：窗口上限就是 30，
   满窗时 `(30/30)` 不提供任何信息，上下两行都挂反而像同一串。
   → **满窗不标、未满窗才标**（`n < WINDOW ? "(c/n)" : ""`）—— 置信度差异恰好只存在于未满窗。
5. **组合出来的名字先压掉空格**（`周四 纽 高` → `周四纽高`）再进长度预算。

### 7.2 但「短」不是目标，「不重复」才是

> ⚠️ **本条修正上一版的错误建议。** 第一轮我把 regime 的**动作词**也砍了
> （`收缩·等放量` → `收缩`），用户明确回撤：**动作词是真实信息，不是重复** ——
> 路径行说的是「等方向/新位○」、现位行说的是「等MSS↓」，都不是「等放量」。
> 砍错了就是把决策信息换成空白，而且用户会立刻看出来。

**正确的最小改法 = 只在「同一状态词已出现」时整段省略：**

```pine
string regState = rExhaustA ? "耗尽" : rExpandA ? "扩张" : rContrA ? "收缩" : rTrendA ? "趋势" : "平衡"
string regAct   = rExhaustA ? "·等扫位" : rExpandA ? "·等回踩" : rContrA ? "·等放量" : rTrendA ? "·做回踩" : "·看VA边"
string regimeSeg = str.contains(structurePathText, regState) ? "" : "·" + regState + regAct
```

| 情形 | 结果 |
|---|---|
| 空趋势 + 收缩（无词重叠） | `空趋势·BOS↓·守摆高·收缩·等放量·未扫5/7` —— **与「原版」语义一致** |
| 多趋势 + 趋势（词重叠） | `多趋势·BOS↑·守摆低·未扫3/8` —— 删掉重复的「趋势·做回踩」 |

保留的必须是：**方向 · 事件 · 守哪个摆动 · 波动状态 · 还有几个位**。
`str.contains(text, word) ? "" : seg` 比硬编码两个分支更省 token，也更容易事后调。

### 7.3 分隔符搬进段内时，必须从调用处删掉

第一轮我把 `"·"` 写进了段字符串，却忘了调用处还留着一个：
`guideStructText + "·" + regimeShortText`（而 `regimeShortText` 已是 `"·" + word`）
→ 图上渲染成 **`空趋势·BOS↓·守摆高··收缩·未扫5/7`**（中间两个点）。

**规则：分隔符只能存在于段内或调用处之一。** 段自带前导 `·` 时，调用处写 `a + seg + b`。

### 7.4 行格式的验收 = 读现场渲染，不是读代码

我上一轮写了一张「改前 → 改后」预期表，但它只覆盖了**被省略**的分支，
漏掉非省略分支的双点 —— 是**用户先看到的**，回撤也正由这个 bug 引出。

→ 任何面板行格式改动后，必须 `data_get_pine_tables` 读**实际渲染**的行，
  逐行肉眼查三种伪影：**连续分隔符（`··`）、空段、半句**。
  自己写的预期表要覆盖**每一个分支**，不能只写主分支。

## 8. 减重后仍要交代的事

减重不是终点，必须同时交付：

- **推算余量**（并说明是推算、客户端检查本地验不了）。
- **是否有损**（tooltip 被压短 = 有损，原文在 git 历史里可取回）。
- **下一步的结构性结论**：余量 <1% 时，微观优化只能续命，
  真正拿余量**只能删一块现有功能**。给出候选清单 + 按「代码量 ÷ 决策价值」排序，
  让用户点单，不要自己替他砍功能。

## 9. 装新版之后必做：重接跨指标总线

重装/重加主指标 study（含「添加到图表」）会把跨指标 `input.source()`
**重置回默认 `close`** → 主表立刻显示「副S0未接·A禁」，而副指标本身完全正常
（副表照样输出 `S4降权` 等状态）。

**这是安装的固定副作用，不是谁改坏了** —— 但它长得像「A 级授权被闸死」，
很容易被误判成严重故障，必须在交付说明里先写好。

- **每次装完主指标都要重新选一次总线源**：设置 →「免费版唯一总线」→
  选副指标的 `Basic Packed Bus (唯一主副连接)`。
- **MCP 接线有两个「假成功」信号，都不可当作已接线：**
  1. `indicator_set_inputs` 返回 `success: true` 但 **`updated_inputs` 是空对象** → 没生效。
     必须检查 `updated_inputs` 非空。
  2. `data_get_indicator` 返回 **`inputs: []`** → 该 study 的输入元数据还没加载
     （刚重加 / 正在刷新时常见）。此时别反复硬试，交给用户在设置面板点两下。
- **study 实体 ID 在重加后会变**，不要复用旧 ID；每次开工先 `chart_get_state` 重取。
- 用户在编辑图表时状态会**连续变化**（study 增删、ID 变化）。连续两次读到不同 ID
  就说明用户正在操作 —— 此时不要抢，把状态如实报给用户，别硬改。
