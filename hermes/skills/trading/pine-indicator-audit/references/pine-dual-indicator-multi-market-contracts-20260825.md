# 双指标多市场适配与决策合同审计（2026-08-25）

适用：审计 `SVP+ICT+VWAP+CVD` 主指标与 `AggVol` 副指标是否真正适配加密、贵金属、外汇、股票、期货、指数和期权标的。

## 一、先定职责，不把“能显示”误判成“已适配”

- 主指标是多市场位置、结构、风险与唯一执行授权源。
- AggVol 是加密专用的五所成交量 + 四所 OI 确认器；非加密 `haldroUsable=false` 属安全降级，不是完整多市场副指标。
- 市场适配必须同时通过：身份识别、数据单位、交易时段、日界/锚定、评分权重、执行门控、界面语义七层。
- “编译通过”只证明语法和服务器限制通过，不证明市场语义或图表运行正确。

## 二、市场×模块审计矩阵

逐市场检查以下项目，不得只看 `syminfo.type` 分支：

| 市场 | Volume语义 | CVD | OI | 会话/日界 | 副指标 |
|---|---|---|---|---|---|
| 加密 | base/quote成交量 | 低周期估算可参与确认 | 永续OI可用 | 7×24、交易所日界 | 完整启用 |
| 金属现货/CFD | 常非集中真实量 | 默认权重0 | 不适用 | 伦敦/纽约、交易所日界 | 方向总线归零 |
| 外汇现货 | 常为tick活跃度 | 只显示，不作A级方向票 | 不适用 | 亚/伦/纽、周末关闭 | 方向总线归零 |
| 股票 | 股数成交量 | 可参考 | 标的OI不适用 | RTH/盘前盘后 | 方向总线归零 |
| 交易所期货 | 合约量 | 可参考 | 需专用OI源才可用 | 夜盘/交易日/换月 | 方向总线归零 |
| 现货指数 | 常无可靠成交量 | 权重0 | 不适用 | 现金市场时段 | 方向总线归零 |
| 期权合约 | 合约量但需IV/Greeks语境 | 不作主方向票 | 需按行权价/到期分析 | RTH+到期结构 | 不适用 |

期权模式更适合分析“期权标的方向”；具体合约选择应交给期权链工具，不把主指标扩成期权链系统。

## 三、已验证的高风险代码模式

### 1. 市场路由集合漏项

S VWAP/CVD 锚定分支若只列 `metal/forex/stock/option`，会让 `futures/index` 落入加密式 D/W/M 路由。建立市场×周期矩阵逐格比较主S VWAP、主CVD、副CVD，特别检查 1h 与 4h+。

建议非加密基础规则：4h以下 D，4h及以上 W；期货再按交易所交易日细化。

### 2. 浮点降权被整数化吞掉

危险模式：

```pine
effWeight = nonCrypto ? 0.5 : 1.0
weightInt = int(math.round(effWeight))
```

`0.5`最终仍为1票，不是真降权。审计评分时必须追到最终消费类型。外汇tick量、金属现货、现货指数应显示中性或0票，而不是“0.5但实际1票”。

### 3. 副指标状态只扣展示分，不控制执行

若 `aggSyncScore` 在 `executablePlan/visiblePlan/entryValidCode` 之后才计算，副指标冲突只影响置信百分比，无法降级A级。

联合合同必须在最终计划形成前执行：

- 主X + 副任意 = X；
- 主WAIT + 副同向 = WAIT；
- 主A + 副同向且健康 = A确认；
- 主A + 副反向/冲突/过期 = WAIT或B；
- 主B/C + 副同向仍为B/C；
- 非加密完全忽略AggVol。

### 4. 成交量单位错误正规化

不得把 `tick/n/a` 做 `volume / close` 再包装为基础币；也不得把不同交易所数据先合并后统一乘主图close。

正确方向：在每个请求上下文内返回本所数值与本所close/volumetype，按源转换：

- base量 → `volume × 本所close`；
- quote量 → `volume`；
- tick/n/a → 标未知，不进入USD聚合；
- 合约量 → 保留合约口径或用明确合约乘数，不能伪装美元量。

单位错误会污染总量、同步放量、覆盖率、单所主导、现永占比和爆仓代理，属于P0数据合同问题。

### 5. Freshness命名与真实语义不符

`barssince(not currentValid)` 表示“距上次无效多少根”，不是“数据陈旧多少根”。总有效家数也无法识别某一源冻结或A掉/B恢复后家数不变。

可靠做法：request tuple带回每源 `value + source time`，逐源维护年龄、掉线、恢复；覆盖率与freshness分开。

### 6. 同窗口合同遗漏到显示层

即使OI文字分类已读取副指标同窗口价格方向，行动格颜色若仍使用 `close[1]`，主副仍会出现语义分叉。修复后搜索所有消费端：文字、颜色、Pack、告警、评分、MCP均必须用同一价格方向源。

## 四、执行辅助能力验收

### 可声明“辅助决策良好”的必要条件

1. `X > WAIT > A > B/C` 优先级一致；
2. X/WAIT的执行价格为na；
3. B/C只进人工候选字段；
4. A需要收线、触发新鲜、价格几何、R:R和副指标健康门控；
5. 多单 `stop < entry < target`，空单反向；
6. 行动格、Data Window、MCP、告警和回放消费同一FinalPlan；
7. 非加密不会读取AggVol方向；
8. 当前CVD明确是低周期价格行为估算，不宣传为真实Bid/Ask主动单。

### 使用边界

- 加密5m/15m：可作为主力驾驶舱，但副指标门控未落地前，副冲突须人工把A降为WAIT。
- XAU/股票：以主指标位置、结构和风控为主。
- 外汇/期货：完成量能语义、锚定和会话路由前只作参考。
- 指数/期权合约：不直接依赖执行授权。

## 五、优化顺序

P0：副指标执行闸门 → futures/index锚定 → 非加密CVD真实归零 → 每源volume单位正规化。

P1：逐源freshness → 期货Globex/股票RTH路由 → 日/周CVD背景（不重复计票）→ 所有OI消费端同窗口 → 总线合同版本校验。

P2：SVP增量桶缓存 → winnerZone → 前日VP/HVN/LVN。

不建议：第三套CVD、更多总分、更多交易所、把OHLC估算包装成真实订单流、把主指标扩成期权链系统。

## 六、官方口径摘记

- TradingView `syminfo.type`可含 stock/futures/index/forex/crypto/fund/dr/cfd/bond/warrant/structured/right；不存在可依赖的通用 `option` 类型值。
- `syminfo.volumetype`可为 base/quote/tick/n/a；volume单位随市场变化，不能统一解释。
- 官方CVD使用低周期价格和成交量估算买卖压力，并在新锚定周期重置；不是交易所审计的逐笔主动成交量。

## 七、2026-08-25 实装修复沉淀

### 执行闸门必须在 setupA 前落地

- 用独立 `input.source` 读取固定合同码（本轮 `22001`），再解码 `0无效/1多/2空/3冲突/4降权`。
- 加密 A多仅接受状态1，A空仅接受状态2；0/3/4/未接线降为 WAIT 或 B/C。
- B/C 不得因同向副指标升级A；非加密旁路 AggVol。
- `noTradeReasonCode`、行动格、Data Window 和 alert 都要消费最终门控，不能只改置信分。

### 低成本逐源 freshness 基线

完整方案仍是 request tuple 带 `value + source time`。配额/token紧张时，可先为每个启用 venue 维护连续缺失计数，健康为0、无效逐根递增，连续3根进入降级并导出 stale venue count。必须说明这只能识别缺失，不能等价宣称为真实 source timestamp freshness。

### 期货和无可靠量市场

- 期货存在 Globex，不能因不在亚洲/伦敦/纽约窗口就硬X；后续再细化交易所RTH/夜盘。
- CVD权重为0时应同时停止lower-TF请求、方法码输出0、取消买卖授权词。
- 禁止 `0.5 → round → int` 的伪降权。

### 配额与验证基线

本轮实测：保留5所成交量+4所OI；AggVol近似六项和100，主指标增加合同input后252/254。后续优先复用或打包字段。每次修改按：静态语义断言 → 六项和复核 → 完整源码 pine-facade 云编译 → 图表接线/回放/Profiler。

## 八、审计裁决陷阱

- 在宣布数值算法错误前先查项目既定协议；本项目 Value Area 的“候选桶越阈值则停止”是已定口径，不能凭常见实现直接判错。
- `display.data_window` 仍占 plot。
- “副指标影响置信分”不等于“副指标进入执行闸门”，必须追到 `setupA → executablePlan → visiblePlan → Data Window/alert`。
