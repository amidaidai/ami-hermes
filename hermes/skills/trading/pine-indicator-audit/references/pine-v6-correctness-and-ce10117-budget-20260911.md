## A. Pine v6 语言 / 运行时坑

### A1. `str.replace` 只替换第一处（全替换要 `str.replace_all`）

签名：`str.replace(source, target, replacement, occurrence)` —— **只替一处**；
`str.replace_all(source, target, replacement)` —— 全替。

现场证据：档位名 `"周四 纽 高"`（两个空格），`str.replace(name, " ", "")`
渲染成 `周四纽 高` —— **只吃掉了第一个空格**。改用 `str.replace_all` 才对。

**同类既有缺陷**：现位行的回踩/反抽档位名 `str.replace(pullbackLevelText, " ", "")` ×4
从更早版本起就这么写，一直没暴露，只因那些档位名**恰好只有一个空格**
（`"VAH 76837.8"`）。一旦档位名自带多个空格就漏同样的半个。**一起修掉了。**

判定口径：目标串可能在源串里出现多次时，一律 `replace_all`。
只有确定唯一目标时才用 `str.replace`（如 `ticker` 去 `".P"`、会话名 `亚洲盘`→`亚`）。

### A2. `array.sum` 只在【全部元素都是 na】时返回 na

**部分 na 会被忽略**（有非 na 元素时按有效元素求和）。

→ 所以「某所整类缺失」触发 na 的真实条件是：**该所这一格只有 na**
  （例：COINBASE 的两个永续后缀 `USDT.P` / `USD.P` 都不存在）。
→ 聚合类求和必须**逐元素 `nz`**；只在外层套 `nz()` 会**静默吞掉其他所有有效源**。
→ 修法对「部分 na」场景行为**完全不变**（`nz(na)+有效值 == 原 array.sum 结果`），
  只把「全 na」从 na 改成 0。这点要显式验，才能说「没动原本正常的路径」。

### A3. 三元不能返回元组（CE10163）

`request.security(sym, tf, [o,h,l,c])` 放进三元表达式 →
`Ternary operations cannot return tuples`。

**正确写法：请求无条件执行，用三元选【品种】：**

```pine
string s = cond ? altSymbol : syminfo.tickerid
[smtO, smtH, smtL, smtC] = request.security(s, timeframe.period, [open, high, low, close], ignore_invalid_symbol=true)
```

附带好处：关闭该功能时回落请求图表自身，**历史预取不漏**。

### A4. 函数内局部变量不支持历史引用（CW10018）

函数体内的 `x[1]` 不可靠。需要跨根比较的量，**提到全局作用域算好再传进去**
（例：交易日 key `gSessDayKey` / `gSessDayRolled`）。

### A5. 类型定义插入点必须锚在【真正的末尾字段】

插错位置会把类型定义截断，后续引用被截掉的字段 → **CE10198 `Object has no field`**。
现场：`SessionState` 末尾是 `bool ended = false`，**不是** `lvlLowObj`
（`lvlLowObj` 后面还有 `dayName` / `ended` 两个字段）。
→ 插桩前先读全类型体，锚在最后一行字段上。

### A6. 提取命名常量的顺序：先替换用法，再插定义

先插定义行再做全局替换 → 定义行自己会被替换成 `LBL_BG = LBL_BG`（自引用）。
正确顺序：**先把 N 处用法替换成常量名，再插入定义（定义里写原表达式）**。

### A7. 替换/插桩串必须沿用锚点的行首缩进

缩进丢了会打断 `if` 块 → **CE10013 `Mismatched input ... expecting end of line`**。
现场：注释落到第 0 列，紧随其后的 `array.push` 变成块外语句。

## B. CE10117（编译 token 上限）

- 上限 **100,256 tokens**，是**编译器硬限、与订阅等级无关**。
  网上流传的「limit is 72000」是 2024 年的旧值 —— 别据此建议升级套餐。
- **只算编译产物**：注释、空白**不进**；**嵌入常量字符串、重复代码进**。
  （「删注释能省 token」是错的。）
- 官方文档指定的两条减重手段：
  1. **缩短嵌入常量字符串**
  2. **减少重复代码 / 把重复逻辑封装成函数**
- 实测换算比例：本主指标 229,285 字符 ↔ 100,490 tokens ≈ **0.438 token/字符**。
  只对该文件有效，当**估算**用；真实值只有客户端编译才给。

### 减重清单（按性价比排序，都验证过）

| 手段 | 效果 |
|---|---|
| tooltip 按**完整短语**截断（不要剃到半句） | 77 条 1894→988 字符 |
| 多个同值表达式提取成常量（如标签底色 `color.new(A,B)` ×5） | 省 4×41 字符 |
| 同构的清理/复位块封装成 UDF（`mergedLabels` 清理 ×2、三个会话各 6 行复位） | 合计 ~400 字符 |
| `timeframe.in_seconds(timeframe.period)` ×11 统一到已有的全局 `curTfSec` | ~308 字符 |
| 批量推入复用已有的单条推入方法（`storeBatchBars` → `storeSingleBar`） | ~200 字符 |

### 两条铁律

- **CE10117 是客户端检查**：云编译（`translate_light`）**不查** token 数
  → 本地**无法验证**，只能给「累计省了多少字符 + 换算推算 + 明确说这是推算」。
- **不要把「剃帮助文本」当第一选择**。若文件已贴在 99%，正确做法是把
  「削减到了哪一轮、还剩多少余量」摊给用户，让他**选一块功能删掉换余量**
  （按「代码量 ÷ 决策价值」排序给候选）。剃光 tooltip 只买到 0.5%，还伤了可用性。

## C. 打包总线改字段：**不能位移**

- 最大合法总线 `2200342299199994` < 2^53 ✓ 安全。
- 想「把合同号上移一格」腾出字段位 → `22003 × 1e12 ≈ 2.2e16`
  **越过 2^53**，整数精度崩 ✗
- → 新增语义用**值域哨兵**，不要位移：
  如 `oiPctEnc == 0` 表示「OI 缺失」（正常域 1..19999 取不到 0，天然可当哨兵）。
- → 换语义时**升合同版本**（22002→22003），**解码端同时接受新旧**，保证换装顺序安全：
  旧主 + 新副 → 主显示「副合同不匹配」= **fail-closed**，不会静默误读。
- → 每改一次要在**所有状态 × 所有字段组合**上做往返验证（本轮 state −2..4 × code ±1/±2/±5/±7 × age × fresh 全跑）。
  拿**修复前的真实包**当反例：旧 bug 包 `1099899` 应解出 998/9（证明借位确实发生），
  新正确包 `1099901` 应解出 999/0/−2。

## D. 批量改大体积源码的安全工作流（本机实测）

- **不要把带正则/反斜杠的代码塞进 bash heredoc 或 `python -c`**：
  本机反复被 shell 吃掉转义（`[^"\\]` 变 `[^"\]` → `unterminated character set`）。
  **用 `write_file` 落成 `.py` 文件再跑。** 本轮这一条踩了 5 次以上。
- **`patch` 工具对 CRLF 多行匹配不稳** → 用**整行锚点 + 断言**的 Python 替换脚本。
- 原生 Windows 程序不认 MSYS 路径：`python s.py /c/Users/...` 失败，传 `C:/Users/...`。
- 每次替换都 `assert t.count(old) == 期望次数`，否则静默漏改/多改。
- **条件分支类的改动必须【两个分支都验】**。
  现场：结构行只验了「省略 regime」那一支，另一支渲染成 `守摆高··收缩`（双分隔符），用户当场看到。
  **能读现场就读现场**（`data_get_pine_tables`）拿真实渲染文本，不要只跑本地推理。
- **装完按行为验收**（Data Window 值变化），不看源码行数；
  `pine_list_scripts` 有缓存，不能当「保存成功」的判据。
- 改行文案前后各扫一遍消费者：`grep -nE 'split\("·"\)' <consumer>` ——
  按【行标签】取值才安全，按 `·` 拆值取下标遇到段数变化就错位。

## E. 面板行文案的重复审计（用户反馈驱动）

用户的抱怨形态是「太长了」「重复太多」「感觉原来的也不错」。

### 三类**真**重复

1. 同一个词在同一行出现两次（`多趋势·…·趋势·做回踩`）
2. **行标签已表达的信息在值里再写一遍**（标签已是「磁吸↑」，值里又写 ↑）
3. 同一件事在相邻行各写一遍（regime 的「等回踩」vs 路径行的动作 vs 现位行的「回踩/反抽」）

### 反例：**删重复 ≠ 删信息**

本轮我把 regime 的「等放量」一起砍了，用户回「**原来的也不错**」——
那个动作词是**真实信息**：路径行说的是「等方向/新位○」、现位行说的是「等MSS↓」，
**都不是**「等放量」。**只删真正的重复，保留语义**，然后靠「结构文本已含该状态词就省略」这类规则消重。

### 统计量的样本量显示

命中率这类量：**满窗时不必标样本量，未满窗才标**。
否则上下两行都拖一串 `(n/30)`，看着像同一串（用户会问「30/30 是什么」）。

### 会话/面板行标签是动态的

「风控」行标签有四态：`风控` / `风控·观察` / `风控·未授权` / `禁做·不出价`。
只认字面「风控」会在观察态漏读执行价。
