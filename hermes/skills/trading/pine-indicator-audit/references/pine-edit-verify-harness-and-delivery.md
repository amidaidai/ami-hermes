# Pine 成批编辑工装与验证陷阱（2026-09-10）

适用：对 3000+ 行主指标 / 800+ 行副指标做成批修改（删死链、改语义、调表格文本），交付要求是「本地文件 + 服务端编译回执 + 可复跑断言」。

## 1. 大文件不要手改 —— 写「带断言的变换脚本」

1. 脚本从**原文件**读 → 按「行号区间 + 首行/末行内容断言」删除或替换 → 再做「唯一字符串替换 + 命中次数断言」的细改 → 写新文件。
2. 行级编辑必须按**行号降序**应用，否则前面的编辑会让后面的行号失效。
3. 每处编辑都断言首行/末行包含预期片段；断言失败立即停，不要「看着差不多」继续。
4. 脚本必须能**幂等重跑**（每次从 source 读，不就地改原文件），改一处重跑一次即可，不必手工回滚。
5. 把 `before/after 字符数 + sha256` 打进脚本输出，漂移量当场可见。

**插入块陷阱**：插入的新派生变量，它引用的每个标识符都必须已在插入点**之前**声明。
本轮把 `spot2SuffixOn = SPOT2 != 'None' and SPOT2 != perp1Suffix` 挂在 `spot1Suffix` 之后插入，
而 `perp1Suffix` 在下一行才声明 → 服务端报 `CE10272 Undeclared identifier`。
锚点要选在「所有依赖都已就位」的那一行之后。

## 2. 交付必须是 LF（Windows 上会被静默改成 CRLF）

`Path.write_text()` 走文本模式，在 Windows 会把 `\n` 翻译成 `\r\n`；Pine 交付约定是 **LF / UTF-8 / 无 BOM**。

```python
Path(dst).write_bytes(text.replace("\r\n", "\n").encode("utf-8"))
```

核对时**按原始字节**算 sha256：文本模式读回来的 hash 是 LF 归一后的，和 `read_bytes()` 的 hash 不同，
容易被自己绕进去（本轮先报了 LF 版 hash，实际落盘是 CRLF 版 → 又跑了一遍归一化）。

## 3. 验证脚本的四个「假通过」陷阱（全部真实踩到过）

每一条都会让测试**通过但什么都没验证**：

1. **编解码往返比较错了对象**：Packed Bus 的 `price/oiDir` 编码端是「方向+1」（0/1/2），解码端还原成「方向」（-1/0/1）。
   若拿**输入码**去和摘要比较，测试 100% 通过却完全没验证解码。必须比较**解码出的语义值**：
   `want = (state, pdir, odir, agree, pct, badge)` vs `got = (d['state'], d['price'], d['oiDir'], ...)`。
2. **「标识符已删除」断言没去注释**：新加的修复注释会提到被删的变量名 → `assert name not in text` 假失败。
   断言前先 `code_only(t) = "\n".join(l.split("//")[0] for l in t.split("\n"))`。
3. **计数断言与真实代码形状不符**：`GetRequest(GetTicker(` 在 UDF 体内只出现 5 次（4 次调用共用同一函数体），不是 20 次；
   「20 个请求上下文」应断言 `GetExchange(` 出现 5 次（1 定义 + 4 调用）× 5 所。写计数断言前先 grep 真实次数。
4. **断言指向了错误的文件**：主副两份文件同类字段很容易串（`nz(oiAgreementPctA, 0.0)` 在副指标不在主指标）。
   断言失败时先判断「代码错了」还是「断言写错了」——本轮 7 个 FAIL **全部**是断言写错。

## 4. 回归要跑上一版的全量断言

- `verify_fixed_<date>.py` —— 上一版全量断言（修复项语义 + 合同 + 死链零残留 + 配额不变量 + 总线往返）。
- `verify_v<N>_<date>.py` —— 先用 `subprocess.run` 跑上一版脚本**作为回归**，再跑本轮新增断言。

只跑新增断言 → 「这轮把上轮修好的东西改坏了」会漏网。两个脚本都接受 `sys.argv` 传文件路径，便于新旧版本交叉复跑。

## 5. 配额不变量必须逐项断言

每次改完断言：`request.*()`、`plot()`、`input.*()`、`input.source()`、`alertcondition()` 的数量，
以及**六项和**（input + plot + alertcondition + request + input.source + input.timeframe）上限。
主指标余量长期很紧（本轮 237/254，余量 17），任何新增 input/plot 都要先报账。
副指标额外断言：五所成交量调用数（`GetExchange(` ×5）与四所 OI 品种名（`f_oi('BINANCE'|'BYBIT'|'OKX'|'BITGET')`），防静默削源。

## 6. 表格文本改动要把宽度代价写进交付说明

有意的加宽（例如给路径行补「入场价 + 距现价距离」）必须在交付说明里给出：
加宽量（+≈19 字）、最坏总宽（≈31 字，仍小于结论行 36 字）、**以及「不接受就删哪一行」的确切回退点**。
让用户能 1 行回退，而不是重新走一遍审计。
