# 双指标审计修复：证据裁决、跨指标契约与告警边沿（2026-08-25）

## 适用场景

审计或修复大型 Pine v6 主指标（SVP/ICT/VWAP/CVD）与聚合成交量/OI副指标时，用于防止“静态看起来像问题”被误判，以及避免主副指标在窗口、编码和告警状态上分叉。

## 1. 审计结论必须先与项目协议裁决

本次先把 Value Area 的“候选桶加入后会越过阈值则停止”判成 P0，随后加载 `pine-decision-integrity-repair-and-verification.md` 才确认：该项目明确采用 TradingView 对齐的停止口径，而不是“首次达到/超过”口径。

规则：

1. 先读实现；
2. 再读该技能的项目协议/历史裁决；
3. 若实现与协议一致，不得仅凭另一平台或个人习惯判错；
4. 若产品要改口径，必须标成“自定义算法”，并补确定性样例；
5. 报告已经误判时，修复阶段必须主动纠正，禁止为了和旧报告一致而错误改码。

## 2. OI方向必须满足“同窗口价格 × 同窗口OI”

错误模式：副指标导出 `ACT_LB` 根 OI 变化率，主指标却用 `close > close[1]` 判断价格方向。这样会把“10根总体上涨、当前一根回落”错分成新空。

可靠契约：

- 副指标计算并导出同 `ACT_LB` 的价格方向：`1=上涨 / -1=下跌 / 0=持平`；
- 主指标通过独立 `input.source` 读取该方向，不自行重算；
- OI方向票只认 OI 上升：
  - 价格涨 + OI升 = 新多，支持多；
  - 价格跌 + OI升 = 新空，支持空；
  - OI降 = 平仓，只能中性/存疑，不得当方向票。

接线守卫不能只检查 `abs(source)<=1`；默认 source 可能是低价币的 close。至少同时检查 `source != close`，更完整的系统应配合契约版本码。

## 3. CVD日锚不是故障，修体验而非取消锚

低周期自动日锚会在交易所日界重置；Binance 加密通常对应北京时间08:00。推荐保留锚定，避免无限累计受加载历史影响。

体验修复：

- 锚后不足 `ACT_LB` 根时显示“锚定样本 N/M”；
- 方法码动态导出，不能固定写死：
  - `1=五所聚合K线结构估算`；
  - `2=当前图表交易所1分钟估算`；
- 界面可写“买方占优/卖方占优”，但 Data Window 必须诚实标明方法和质量；
- 不得把当前所 lower-TF Delta 描述成五所聚合逐笔CVD。

## 4. 聚合告警必须按事件独立取边沿

危险模式：

```pine
anyNow = condA or condB or condC
fire = anyNow and not anyPrev
```

当 `condA` 持续为真时，后出现的 `condB` 会被吞掉。

修法：每个条件独立取上升沿，再汇总到唯一 `alert()`：

```pine
newA = condA and not condA[1]
newB = condB and not condB[1]
fire = newA or newB
```

消息优先级必须消费 `newA/newB`，不能继续消费持续态 `condA/condB`，否则会发错事件文字。

## 5. 候选扫描完成后才能登记统计样本

磁吸候选循环中若每次刷新“当前最佳”就立刻写 `magSide`，临时第一名也会进入命中率样本。

可靠做法：

1. 循环内只保存最佳候选索引、价格和分数；
2. 所有 ICT 与 nPOC 候选比较结束；
3. 仅对最终胜出且确属 ICTLevel 的对象登记方向；
4. nPOC若不属于该统计口径，必须显式排除。

## 6. 修复交付与验证

- 原文件不覆盖；在原目录新建日期文件夹；文件名带日期；附修复说明和接线表。
- 先做源码语义断言，再将完整原样源码 POST 到 TradingView `translate_light`；不得手抄精简版编译。
- 分开报告：云端错误数、警告数、近似六项和、语义断言。
- 本次基线：副指标约99；主指标新增一个 input.source 后约251/254，仅余约3个外部元素，后续增强优先复用现有输出，不随意增加 input/plot/request/alert。
