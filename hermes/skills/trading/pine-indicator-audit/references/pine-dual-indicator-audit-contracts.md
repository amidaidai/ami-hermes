# 双指标审计增量：锚定重置、SVP价值区与主副数据契约

适用于审计 SVP 主指标与 AggVol/OI 副指标。以下问题均以完整源码静态追踪及 TradingView `translate_light` 全量编译验证为基础；编译通过不代表业务逻辑正确。

## 1. “副指标每天重置”先拆状态，不要笼统归因

定位顺序：

1. 找自动锚定周期，例如 `cvdAnchorEff`。
2. 找真正归零语句，例如 `newPeriod ? Delta : prev + Delta`。
3. 分别检查图形累计值与行动格累计值，常见为两份状态（如 `CumDelta`、`sessCvdA`）。
4. 明确哪些模块未重置：OI变化率、量能均线、覆盖率、HTF趋势通常是滚动值。
5. `time("D")` 未指定时区时跟随交易所日界；Binance 加密日界 UTC 00:00，即北京时间08：00。

推荐：低周期日锚通常应保留；若用户要跨日观察，改周锚优于无限累计。无限累计会受加载历史长度影响并淹没近期变化。

## 2. SVP 价值区按 TradingView 官方规则不得越过剩余目标

TradingView 官方当前口径（2026-08-26 浏览器实查）：从 POC 开始比较上下候选桶；如果加入所选桶**不会超过剩余目标量**则纳入，若会超过则停止。因此以下写法主体是官方一致逻辑，不得误判为 P0：

```pine
candidateFits = current + candidate <= threshold
if not candidateFits
    break
```

还必须核对官方并列规则：候选桶量相等时先选离 POC 更近者；若距离也相等，选 POC 上方。只写 `vUp >= vDn` 会在两侧距 POC 不同时错误地总选上方，属于 P1 边界问题。

只有产品明确声明采用“首次达到/超过70%”的自定义口径时，才纳入越线桶；不得把该自定义口径称为 TradingView 官方一致。官方来源：https://www.tradingview.com/support/solutions/43000502040-volume-profile-indicators-basic-concepts/

## 3. OI方向铁律与周期契约

四象限：

| 价格 | OI | 含义 | 方向票 |
|---|---|---|---|
| 涨 | 升 | 新多扩仓 | 多票 |
| 跌 | 升 | 新空扩仓 | 空票 |
| 涨 | 降 | 空头回补 | 不计票 |
| 跌 | 降 | 多头平仓 | 不计票 |

审计主副协同时必须检查：

- 空头支持条件必须是“价格跌 + OI升”，不能把“价格跌 + OI降/多平仓”写成支持空。
- OI变化若按 `ACT_LB` 根计算，价格方向也必须按同一窗口；禁止用10根OI变化配1根价格变化。
- 最稳做法是副指标直接导出 OI状态码/方向码，主指标只解码，不二次推导。
- Pack 必须有版本/契约校验；仅用 `source != close` 判断是否接线，在低价币或数值偶合时可能误判。

## 4. CVD口径必须区分“当前所低周期”与“五所聚合回退”

常见混口径：

- `security_lower_tf(syminfo.tickerid, "1", ...)` 只读取当前图表交易所；
- 回退算法却用五所聚合 `Volume` 做 wick/body 分配。

因此两条路径不仅精度不同，覆盖范围也不同。行动格、Data Window 和方法码必须明确区分：

- 当前所1m估算；
- 聚合K线估算；
- 无数据/不可用。

若代码实际用了 lower-TF，但导出仍固定 `Method Code (1=K线)`，属于数据契约错误，至少 P1。

## 5. 聚合告警总边沿会饿死新事件

危险结构：

```pine
anyNow = condA or condB or condC
fire = anyNow and not anyPrev
```

当低覆盖等长驻条件持续为真时，后续新出现的A级/共振事件只形成“真→真”，不会报警。修法：每类事件独立检测边沿，最后按优先级合并到单个 `alert()`。

## 6. 磁吸命中率只记录最终赢家

扫描候选位时，不能在每次刷新“当前最佳”时立即给候选写 `magSide`。早期临时第一名可能被后续更高分目标替换，却仍进入命中率样本，污染统计。

修法：循环内只保存最终最佳索引；循环结束后，仅标记最终上方/下方目标。验证时构造多个分数递增候选，确认只有最后赢家进入样本。

## 7. 验证清单

- 对完整原文件调用 `translate_light`，确认 `errors2=[]`、`warnings2=[]`。
- 编译通过后仍逐项做业务不变量检查：VA覆盖率、OI四象限、主副回看窗口、方法码、告警边沿、磁吸样本集合。
- 不要把“0错误0警告”写成“逻辑正确”或“TradingView云端完整可用”；它只证明该编译端点接受源码。
