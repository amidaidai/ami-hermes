# 面板“全是不给做”审计：展示层优先级 vs 授权层

适用：审计主副指标（SVP 主指标 + AggVol 副指标）时，用户反馈“表上永远是不可做/仅候选/等”，要给出根因，而不是复述风控多严。

## 读源码方式（大文件）

261KB/3578 行的 Pine 不要整体读。用 Python 按行切块打印（带行号）+ 正则抽取变量定义行号清单，先拿到“变量 → 定义行”索引，再按链读：

- 表渲染区块：搜 `table.new|table.cell|table.clear`，确认行数、`clear` 闭区间不越界。
- 决策变量：搜 `actionStateText :=|panelStateA =|executablePlan =|displayLongA =|aggAllow.* =`。
- 图表状态：搜 `plot(` 计数，核对 Basic 64 绘图槽位余量（副指标常已达 46+）。

## 审计顺序（不要先看风控阈值）

1. 抄出面板结论文本变量（如 `actionStateText`）的完整 if/else-if 链，按行号列成分支顺序表。
2. 找到主指标自身等级变量（`displayLongA/displayShortA` 一类）在该链中的位置。
3. 判定：任何“副指标状态 / 等待状态”分支排在等级分支之前 ⇒ 等级被稳定遮蔽。这是“全是不给做”的第一根因，与阈值宽严无关。
4. 逐个列出前置分支的条件与常态概率。三类典型的“常态真”分支：
   - 未接总线：`input.source` 默认 `close`，重新添加指标后 TV 会重置回 `close`，落该分支。
   - 副指标降权态：副指标的 S1/S2 若要求“强信号”（多因子同时成立 + 确认分门槛 + 无背离 + 无拥挤），其余时间全部落 S4。
   - 未收线 / 触发过期：实盘未收线分支占每根 K 的绝大多数时间，等级被整段时间藏起来。
5. 再核对 Pine 授权层：允许变量（例如 `aggAllow* = not aggVeto*`）是否按合同区分 S3 真否决与 S0/S4/未接线降级。
6. 继续追踪机器消费链：plot 标题/行动格行→唯一字段契约→解析器与打包码解码→FinalVerdict→渲染器。搜索 `decode_no_trade`、状态码映射、Quality/Execution pack 消费，确认软降级没有在任一层被重新加成 WAIT/NO-GO；特别检查同一位掩码是否混装“低流动时段”与“薄量资产”、或把 S3 与 S0/S4 合并。
7. 用完整有效 A 候选作为基线，单变量注入低流动时段、S0、S4、未接线、S3、低流动资产等状态并实际运行最终裁决：软态按合同保留观察路径/授权资格，硬态仍清空执行字段。仅 Pine 面板更改或源码静态通过，不算端到端修复。若 Pine 授权与消费者结果不同，修机器契约/消费者及其测试，不要只改文案或放宽门槛。

## 必须写完的两张对照

- 授权 / 展示 / FinalVerdict：同一状态在 Pine 内部是 allow 还是 block、面板怎么显示、下游最终裁决是 GO-A/WAIT/NO-GO；三者必须一致，并注明执行价与观察条件各自保留/清空情况。
- 输出分布：给出等级成立所需的完整 AND 项数 + 稳定确认根数 + 收线 + R:R 门槛，说明这是设计取向而非 bug。用户要更多方案时，优先给可执行状态的具名等待条件、结构观察位与下一步触发；不要只回“不给做”，也不要为增加方案盲目放宽硬门槛。

## 多市场禁做陷阱（黄金/外汇先查这几条）

- 市场预设必须走“自动”（按 ticker 识别）或手选正确市场。停在“加密”会把贵金属当加密处理，副总线判定生效 → 恒“副S0未接·A禁”。
- 检查低流动时段与薄量资产是否分开：时段空档按软标注处理，不得继续进入 `setupX` 或被消费端作为硬阻断；薄量资产可保留独立硬门。分别核验行动格、NoTrade/Quality 打包位与下游裁决，防止面板已软化而机器码仍按旧语义拦截。
- 非加密分支若把结论/操作行写死（“不适用”“看主指标”）但同类文本变量已算出未消费，那是信息浪费，报为可改点而不是设计。

## 报告形态（用户偏好）

- 先给结论（能不能正常出方案：能/不能 + 一句根因），再给数据；没有把握直说“待实测”。
- 用真管道表格、≤3 列、每行一个关键值；「位置/现象/根因」三列最有效。
- 每条根因带源码行号，便于下次复核；不要只给“建议放宽阈值”这类无法定位的说法。
- 不列选项，给推荐；修复建议具体到位置与改法，改完交用户编译，不自行云编译。
- TV/客户端未连接时明确标注“静态审计，未做运行态实测”，并给出可选的实测路径（读主副行动格 + Data Window），不要把静态推断说成已验证。

## 面板与硬闸同步修复配方

诊断之后真正要改的是「抢占位」，按分支性质分三类处理，不要一律删：

| 分支性质 | 例子 | 处理 |
|---|---|---|
| 硬阻断（保留抢占） | `setupX` / R:R不足 / 副S3真冲突 / 加密薄量资产硬门 | 留在链首，但文案必须拼上等级词（如「A多 · 等好价」），阻断理由只做后缀——等级成立却不显等级＝把「不给做」占满结论行，违反用户等级常显要求 |
| 降级类（改尾注） | 副未接 / S0无效 / S4降权 / 低流动时段⚠ | 移到等级分支之后，拼成 `subStateTag` 追加；机器码也必须映射为软告警 |
| 动作类（交 ⚠ 承载） | 未收线 / 触发过期 / ADR慎追 / CVD不配 | 删抢占分支，由 `panelRiskOne` 的 `⚠` 与风控行表达 |

判据是「该前置分支是否与等级为真互斥」。互斥（S3 时 `setupLongA` 含 `aggAllowLongA=false`，`displayLongA` 必假）⇒ 放前面无害；非互斥（S4/S0/未接/未收线/过期）⇒ 必然遮蔽等级。

配套三处必须同改，否则文案重复或与导出矛盾：

- `stateAlreadyHasWait` 加「已有 ⚠未收线/触发过期」判定，否则结论行同时出现「· 等收线」与「⚠未收线」。该行若需引用其后才声明的 `riskInConclusion`，必须在声明行之后用 `:=` 追加，不能前向引用。
- `panelUnlockText` 里与低流动相关的文案（「等开市」）要跟硬门变量同步，不能继续用 `lowLiquiditySession`。
- `pendingPlan` 里的 `not lowLiquiditySession` 不同步，软降级时观察价会消失。

**（2026-09-27 已随 SVP/AggVol OPTv3.1 落地）** 配套补齐：`stateAlreadyHasWait` 补 ⚠ 判定；SVP 转纯 LF；低流动拆位（NoTrade 新增 4096·下游不否决；bit4=薄量资产；Quality 去时段项）并同步 `decision_loop` 豁免掩码 `~(2048|4096)`、`decision_matrix` 解除条件/临时位、`auto_card._C_WAIT_SEMANTICS`（移出未收线/等收线/等解除，补等多/等空）；`_svp_requires_wait` 只留硬词。核验 v3.1 是否已装机时先查这些点。

授权函数只说明 Pine 层行为；NoTrade/Quality 位、HALDRO 状态码和外部消费方可能再把软降级变成 WAIT。逐个检查 packed bits 与消费映射，禁止把 S3 与 S0/S4/未接混成一个阻断位，也禁止把低流动时段与薄量资产共用一个位。只有端到端探针确认所有消费者都遵守软/硬契约，才可把状态标成“不否决”。

非加密品种（黄金）的整段无方案先追踪会话低流动标记是否仍进入 `setupX`、NoTrade/Quality 位或 FinalVerdict；已有软降级设置时直接按其已批准默认值保持等级与观察路径可见，不重复新增开关，也不把时段风险与薄量资产混为一谈。

## 门槛预设档与防抖可调（第二版增量）

用户抱怨“方案少”时，除改展示层外，性价最高的是**门槛预设档**：一个 `input.string("标准"/"保守"/"激进")` 派生四个 `eff*` 开关（位移／溢价折价／ADR／关键位），“标准”分支回落原 input 值 ⇒ 默认零行为变化，不必让用户逐个调。

- 派生变量必须声明在**所有原开关之后、最早使用点之前**（Pine 无前向引用）。本次因 `ADR_AS_FILTER` 声明晚于 DMI 组，派生块只能放 ADR 组末尾，不能跟 input 放一起。
- 联动必须一次改全，否则面板与门槛打架：`allowAByLocation` / `adrLowRoom*` / `adrChaseBlock*` / `dispLongOk|ShortOk` / `pdAllow*`，以及面板风险文案 `badDisp/badPd/badAdr`。
- 预设只覆盖“过滤类”门槛，**不得**覆盖 X 硬闸门、R:R 门槛、副指标否决、CVD 硬门槛——否则等于绕过风控。
- A 级防抖（`setupGradeCandidateBars >= N`）建议做成 `input.int(2,"A级确认根数",minval=1)`：默认 2＝现状，设 1 可当根出 A；撤销逻辑不受影响，低风险可调项。
- 每新增 `input.*()` / plot / alert / request 前后都重新跑脚本级预算，按实际源码差值判断余量；不要把旧版本的行数、配额计数或门槛结论写死成长期规格。

## 审计用户手改版的双向越权检查

- 副指标状态直接覆写主图方向 bool（`cvdRisingEff = aggState==1 ? true : ...` 一类）＝副指标变相投出方向票，违反「副只确认/降级/否决」契约。逐个 grep 被 Eff 覆盖变量的消费者链：若覆盖值同时进入计票项（如 cvdBullConfirm→confirmScore）又有独立同步加分（aggSyncScore），一个副状态在总分里双计、条件完成度虚高。修法二选一：覆盖只进文案不进计票，或保留计票但同向时不再叠加同步分。
- 硬阻断降级为可见降级时（setupX/面板文案改了），必须核对该状态位是否仍打进 NoTrade/Quality 打包码——下游决定性掩码（`code & ~信息位`）会把图上已软化的状态在卡层重新拦成 WAIT，端到端效果被吞。按拆位先例：Pine 拆位（阻断位与新增信息位分开）→ 契约解码表 → 消费端掩码豁免该信息位 → 补测试断言，四层同改缺一层即半修。

## 状态文案与端到端裁决必须区分「否决」与「降权」

在否决制下 **S4/S0/未接不否决**；低流动时段是可见降级，低流动资产可仍为硬门。先查看 Pine 的 `aggVetoLong/Short` 与 `setupX`，再检查 NoTrade/Quality 位、HALDRO State Pack 的每个消费者和 FinalVerdict；不能从 Pine 局部布尔值推断整条系统已放行。任何软态若仍产生 WAIT，先修状态契约/消费逻辑，避免只改成“不否决”文案。

- 文案定稿：`S3冲突·否决` / `S4中性·不否决` / `S0无效·不否决`。判据是该状态在主指标和 FinalVerdict 两侧是否真的否决；只有 Pine 侧与下游均不阻断时，才可写“不否决”。
- **反直觉**：放宽 S1/S2 阈值会让「否决」更频繁（S1 否决做空、S2 否决做多）。用户抱怨“不给做”时不要走这条路。
- S1/S2 少见的结构性原因要能背出来：四所 OI 至少 2 所有效 + 一致≥75% + 离散≤2.5；三票中≥2；必须放量；CVD 同向；确认分≥3；无 CVD/OI 背离；**LSR 不拥挤**；数据质量全绿且**锚内样本满窗**（锚重置后头 ACT_LB 根必然是 S4）。
- 非加密副图会因默认 mode 带 `isCryptoPlot` 门控而一片空白（Delta/CVD/OBV/MFI/Imbalance 都门控，Spot&Perp/EX 系列量源为 0，只剩 `Volume` 有输出）。提示要放在**表格行**（如“改Mode=Volume·副图才有线”），不要用绘图槽位做提示——槽位可能只剩 1 个。
