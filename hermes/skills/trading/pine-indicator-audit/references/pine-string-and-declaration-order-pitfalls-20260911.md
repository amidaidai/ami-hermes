# Pine 字符串 / 声明顺序 / 减重：三组可复用坑（2026-09-11）

来源：对两份生产指标（SVP 主 3.5k 行 / AggVol 副 0.97k 行）做 20 条审计修复
+ CE10117 减重 + 行优化的一轮实战。每条都当场踩过并验证过修法。

## 1. `str.replace` 只替换【第一处】—— 全替换必须用 `str.replace_all`

官方签名：

```
str.replace(source, target, replacement, occurrence) -> string
str.replace_all(source, target, replacement)         -> string
```

**现场症状**：图表磁吸行渲染成 `周四纽 高 77518.6` —— 档位名原文是 `"周四 纽 高"`（两个空格），
`str.replace(name, " ", "")` 只吃掉了第一个空格。

**排查路径（可复用）**：不要从代码猜，从**渲染结果**反推 ——
「一个空格被去掉、另一个没去掉」说明不是「没匹配」而是「只替了一处」。

**横向扫描是必须的**：发现一处后立刻全库 grep `str.replace(`，逐个判断目标串是否可能多次出现。
本次扫描结果：

| 用法 | 判定 |
|---|---|
| `str.replace(syminfo.tickerid, ".P", "")` | 安全 —— ticker 里只有一个 `.P` |
| `str.replace(name, "亚洲盘", "亚")` | 安全 —— 会话名只出现一次 |
| `str.replace(guideActionWord, "等", "")` | 安全 —— 三个取值各只含一个「等」 |
| `str.replace(pullbackLevelText, " ", "")` ×4 | **危险，且是既有缺陷** |
| `str.replace(name, " ", "")` | **危险，本轮引入** |

**关键教训**：危险写法**常常已经存在**，只是目标恰好只出现一次所以一直没暴露；
一旦输入变成带空格的档位名（`"周四 纽 高"`）就露出同样的半个空格。
扫到一处要扫全库，不要只修报告里的那一处。

## 2. CE10117（编译 token 上限）减重 playbook

- 上限 **100,256 tokens 是硬限、与套餐无关**（官方 Compiled tokens 文档）。升级解决不了。
  「limit is 72000」是 2024 年的旧值，别引用。
- **只有两条官方认可的手段**：① 缩短嵌入常量字符串 ② 减少重复代码 / 封装成函数。
  **注释、空白、短标识符不计入** —— 删注释省不了 token。

### 先量化

```
tokens ≈ 非注释字符 × 0.44
```

对 22.9 万字符的 SVP 实测反推（100,490 tokens / 229,285 字符 = 0.438）。
只对该文件有效，当估算用，别当公式。
**推算值必须标注为推算** —— 见下面「客户端检查」。

### 实测有效的缩减项（本次共 1,800 字符 ≈ 790 token）

| 手段 | 做法 |
|---|---|
| tooltip 压缩 | 77 条 1894 → 988 字符。按「**最后一个完整分句**」截断，别切半句（12 字符硬截会把「只想要确认行的FVG✓信」这种残句露出来，16 字符是可用下限） |
| 重复调用提全局 | `timeframe.in_seconds(timeframe.period)` ×11 → 复用已存在的全局 `curTfSec` |
| 常量提取 | `color.new(A, B)` ×5 → 一个 `color` 常量 |
| 方法复用 | 同构的内联推入块 → 直接调已有的 `method` |
| UDF 封装 | 两份相同的清理块、三个会话各 6 行同构复位 → 各一个函数 |

### 不要靠「位移字段」腾位

想把合同号从 `*1e10` 上移到 `*1e12` 来插一个新字段 —— 最大包变成
`22003e12 ≈ 2.2e16`，**越过 2^53**，整数精度直接崩。

**正确做法**：在值域里找**取不到的哨兵值**。例：`oiPctEnc` 正常域是 `10000±9999 = 1..19999`，
`0` 天然取不到 → 用 `0` 表示「缺失」✓ 零位移、零精度风险。
（同理：任何打包整数新增语义前，先算 `最大值 < 2^53`，并写进断言。）

### CE10117 是客户端检查

`translate_light`（云编译）**不查 token 数** —— 本地永远验不了，必须让用户在 Pine 编辑器编译一次。
所以：余量薄（<1000 token）时要**如实说这是推算**，并主动给「删哪块功能换余量」的候选清单
（按「代码量 ÷ 决策价值」排），不要假装已经解决。

## 3. 编辑 Pine 源码时的声明顺序 / 结构坑

每条都是本轮当场撞到并被编译器抓住的：

| 报错 / 现象 | 根因 | 修法 |
|---|---|---|
| CE10013 Mismatched input | 替换串**丢了行首缩进**，把 `if` 块打断 | 替换串每一行都带上锚点的缩进 |
| CE10163 Ternary cannot return tuples | 三元里放 `request.security(..., [o,h,l,c])` | 改成「**请求无条件执行、品种用三元选**」 |
| CW10018 局部变量历史引用 | 函数内局部变量用 `[1]` | 需要历史的量提到**全局**再传参 |
| CE10198 Object has no field | 往 `type` 定义**中间**插函数，把类型切断 | 锚点取类型的**真正末行**（本次是 `bool ended = false`，不是 `lvlLowObj`） |
| CE10271 Could not find method | 调用点在被调 method **之前** | 把定义上移，先声明后调用 |
| CE10272 Undeclared identifier | 常量插在依赖它的变量之前 | 定义顺序 = 依赖顺序 |
| 自引用 `X = X` | **先插定义再全局替换**，把定义行自己替掉了 | **先替换用法，最后插定义** |

---

## 4. 编辑纪律（本轮反复验证）

1. **批量改 Pine 用「Python 行替换脚本 + 每步 assert 命中次数」**，不要用多行 patch
   （patch 工具对 CRLF 匹配不稳，会假失败）。
2. 一步一编译：**云编译 0 错 0 警 → 再断言 → 再交付**。声明顺序类错误只有编译器能抓。
3. 断言写「期望命中 N 次」而不是「命中一次」，这样重复块被误改会立刻暴露。
4. 交付时带上：行数、`sha256[:24]`、云编译回执、绘图槽估算、CE10117 推算值 —— 并标明哪些是推算。
