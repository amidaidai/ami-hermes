# 价格发现态的“现位”压宽合同

## 触发场景

主指标行动格的“现位”在价格发现阶段因多段动态文案拼接而撑宽，例如：

`多·价格发现·等回踩低点·不追·等MSS↑·16:30定`

## 核心原则

压宽时按**决策增量**裁剪，不能按字符长度机械截断。

必须保留：

- 方向身份：`多 / 空 / 待`；
- 下一结构确认方向：`等MSS↑ / 等MSS↓`；
- 稳定位置确认时间：如`16:30定`，它帮助人工判断锚点新鲜度。

优先删除或合并：

- 与“路径”行重复的阶段描述：`等回踩低点 / 等反抽高点`；
- 已由执行纪律隐含或在其他行表达的`不追`；
- 冗长状态名`价格发现`可压成`发现中`。

推荐显示：

- `多·发现中·等MSS↑·16:30定`
- `空·发现中·等MSS↓·16:30定`
- `待·发现中·等MSS↑·16:30定`

不要压成仅`多·发现中`：这会丢失用户最关心的确认方向和时间锚。

## 行职责

- **现位**：方向身份 + 当前位状态 + 确认方向 + 位置确认时间；
- **路径**：最近完成步骤 + 当前唯一下一步；
- **结论**：A/B/C/WAIT/X执行许可；
- **结构**：已经发生的结构事实。

允许“现位”的`等MSS↑/↓`与路径产生有限重复，因为前者用于一眼识别方向，属于高价值冗余；应删除的是低价值的完整阶段复述。

## 实现模式

```pine
string guideLookText = priceDiscoveryLong ? "多·发现中" : priceDiscoveryShort ? "空·发现中" : ...
string guideActionWord = longBias ? "等MSS↑" : shortBias ? "等MSS↓" : "等扫位/位移"
string currentRow = guideLookText + "·" + guideActionWord + guideTimeTag
```

方向必须沿用现有计划/结构偏向合同，不新增独立方向源。时间必须沿用稳定支撑/阻力时间，不得伪造“当前发现位已确认”的时间。

## 验证

1. 静态确认旧长串不再可达；
2. 多、空、待三类发现态均保留MSS箭头；
3. 有稳定时间时保留`HH:MM定`，无时间时不显示空占位；
4. 主表行数不变；
5. 不新增警报、请求或执行授权；
6. 完整源码跑TradingView服务端编译；
7. 客户端检查极端动态字符串的实际像素宽度。
