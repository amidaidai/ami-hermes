# 信号→结果 自动验证闭环（20260910）

> 解决一个结构性漏洞：**副指标握着 A 级一票否决权，但这个权力从没被数据验证过。**
> 实测 `data/trading_journal.db` 原本是空的（只有一张 0 行的 `analysis_log`）——
> 依赖"用户手动记账"的复盘管线在手动交易场景下**永远不会积累数据**，
> 所以"10-20 笔真实交易后才可调核心参数"这条经验法则永远不到期。

## 为什么要另开一条链路

| | 手工成交记录（既有 trade-review-pipeline） | 信号自动验证（本文） |
|---|---|---|
| 记什么 | 用户真实成交 | **指标给出的 A 级信号** |
| 谁触发 | 用户开仓后手敲 | cron 每 15 分钟自动 |
| 回答 | 执行质量（滑点/拿单） | **信号质量 + 副指标是否加值** |
| 数据量 | 取决于用户勤快 | 只要挂着图就自动积累 |

两条链路**互补不替代**：手工链路算真实盈亏，自动链路算"如果按信号执行会怎样"。

## 数据流

```
data/tv_dmi_cache.json ──record──> signals 表 ──eval(回看K线)──> outcomes 表 ──report──> 分组统计
   (既有采集链已写好)              (A级信号)      (先到目标还是先到止损)
```

实现：`<repo>/scripts/signal_outcome.py`（init / record / eval / report / tick）

## 六条设计规则（每条都对应一个真踩过的坑）

1. **A 级认定看行为不看措辞**：路径行含 `A执行` **且** 风控行能解析出 `入/止/标`。
   不解析结论行的文字 —— 那行会随版本改措辞，一改解析就静默失效。
2. **方向由几何反推**：`入 > 止` ＝ 多，`入 < 止` ＝ 空。同样为了免受措辞变化影响。
   同时校验目标在正确一侧，否则丢弃该信号。
3. **同一根 K 内先到谁未知 → 保守判先到止损。** 多空双向都可能在同一根内被触及，
   只有分钟级数据能分辨；用 15m/日线回看时必须选对自己不利的那个判定，否则胜率虚高。
4. **观察窗未满不得结算**（实案 bug）：初版一读到 bar 就结算，新信号下一个 tick 立刻被标 `timeout`。
   正确做法：`len(可用K线) < 窗口长度` 时 `continue`（保持未结算，下个 tick 再来）；
   满窗后才结算，且 **`timeout` 按到期收盘 mark-to-market 折算 R，不丢样本** ——
   否则横盘期信号全部消失，期望值算不出来。
5. **不可解析的品种不得伪造结果**：非 Binance 品种（XAU/外汇）标 `unresolved` 并排除出统计，
   绝不用替代价源硬算。
6. **去重键 = symbol + 对齐到周期的 bar_ts**（不是当前时间），否则同一根 K 每个 tick 落一条。

## 分组才是答案

`副确认放行` / `副未确认(降权·不升级)` / `副缺数据·未接` / `副不参与(非加密)`

**只有"副确认放行"组的期望 R 显著高于其它组，副指标那票否决权才有数据支撑。**
若无显著差异 → 应把 A 级的独立否决权收回，副指标降为纯参考。
输出列：胜/负/超时/未解析、胜率、期望 R、平均 MFE / MAE。

## SQLite 坑

`CREATE TABLE IF NOT EXISTS` **不会给已存在的表加列**。加了字段后必须写迁移：

```python
def _migrate(c):
    cols = [r[1] for r in c.execute("PRAGMA table_info(outcomes)")]
    if "r_mult" not in cols:
        c.execute("ALTER TABLE outcomes ADD COLUMN r_mult REAL")
```

否则只有全新库能跑，老库报 `no column named ...`。

## 部署：Hermes cron 契约（本轮实测）

| 事实 | 正确做法 |
|---|---|
| `script` 只接受 `~/.hermes/scripts/` 下的**相对文件名**，绝对路径直接被拒 | 仓库里放真实现（跟其它交易脚本一起版本管理），`~/.hermes/scripts/` 放 3 行 `runpy` 转调启动器 |
| `schedule="15m"` 建出来是**一次性**（`once in 15m`） | 周期任务必须写 `every 15m` |
| `update` 改了 schedule，`repeat` 仍停在 `once` | **删掉重建**才会得到 `repeat: forever` |
| `no_agent=True` + **空 stdout ＝ 什么都不发**（watchdog 模式） | 脚本必须静默：只有真发生事（新增信号/结算）才 `print` |
| `deliver='local'` | 自动任务不外发（用户长期偏好），只本地留档 |

## 自检（可复现，勿跳过）

`python sandbox/selftest_signal_outcome.py` 覆盖 4 项：

1. 真实缓存非 A 级态 → **拒绝记录**
2. 构造真实历史 A 级信号（用真实 Binance K 线定 入/止/标）→ 落库 → eval 真 K 线结算 → report 出分组
3. `symbol + bar_ts` 重复录入 → "新增 0"
4. **早结算守卫**：宽到不可能触及的止损 + 1 小时前的信号 → 结算数必须为 0；
   再把窗口缩到 4 根 → 必须出 `timeout` 且 R 有值

自检末尾**必须清理自检数据**，否则污染真实统计。
