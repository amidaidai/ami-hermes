# 双指标 vNext：执行状态机、跨所 OI 一致性与直白文案

## 适用场景

成熟的 SVP/ICT/VWAP/CVD 主指标与 AggVol/HALDRO 加密副指标已具备足够结构概念，下一步应强化“能否执行”和“数据是否可信”，而不是继续添加 ICT/SMC 名词。

## 用户文案偏好

订单流行动格使用交易者直白说法：

- 保留“爆仓”；显示“空头爆仓偏强 / 多头爆仓偏强 / 无明显爆仓”。
- 不要擅自改成“杠杆失衡代理”等文绉绉术语。
- 源码注释可以诚实说明它是基于 PERP-SPOT 成交量差和 K 线方向的代理，并非交易所真实强平流；行动格仍使用“爆仓”。

## 主指标执行状态机

### Entry Valid

建议稳定导出 `MCP Entry Valid Code`：

| 代码 | 含义 |
|---:|---|
| 3 | A级、已收线、触发新鲜、价格几何与 R:R 均有效，可执行 |
| 2 | B/C级触发完成，可按轻仓规则执行 |
| 1 | 有计划但等待收线或新触发 |
| 0 | 无计划 |
| -1 | R:R不足 |
| -2 | 价格几何无效 |
| -3 | 主指标X禁做 |

A级提醒必须消费 `Entry Valid == 3`，不能只检查 Grade 和 R:R。

### No-Trade Reason 位图

建议：1 高周期冲突；2 过热延展；4 低流动性；8 价格几何无效；16 R:R不足；32 CVD质量不足；64 ADR空间不足；128 PD位置不允许；256 未收线；512 触发过期。

注意：256/512 是 WAIT 原因，不应被下游验证器当成永久 NO-GO；下游应以 `code & 255` 判断硬禁做位。

### Trigger Code 与有效期

推荐触发码：

- ±1 Sweep 收回/拒绝
- ±2 MSS
- ±3 FVG
- ±4 OB
- ±5 CVD吸收/派发或背离
- ±6 VA/VWAP接受
- ±7 位移

事件必须记录 `ta.barssince(event-start)` 年龄，而不是区域当前仍为 true 就永久视为新鲜。默认有效期可按周期路由：5m=6根、15m=4根、更高周期=3根。过期后保留方向背景，但 Entry/Stop/Target 置空，行动格显示“○ 触发过期 等新确认”。盘中未收线显示“○ 盘中候选 等收线”。

## CVD 背离

主副指标均优先采用“价格枢轴锚定 CVD”：

1. 确认价格 Pivot High/Low；
2. 读取该价格枢轴对应时刻的 CVD（`cvd[pivotLen]`）；
3. 与上一个价格枢轴及其 CVD 比较；
4. 再叠加摆动幅度、斜率、数据质量、关键位和有效期门控。

不要强制价格 Pivot 与 CVD 自身 Pivot 同一根确认，否则容易漏掉真实背离。

## AggVol 跨所 OI 一致性

四所 OI 先分别计算百分比变化，再计算：

- `OI Breadth = 上涨交易所数 - 下跌交易所数`；
- `OI Agreement % = 与聚合方向一致的有效源数 / 有效源数`；
- `OI Dispersion Ratio = 跨所变化率标准差 / max(abs(均值), 0.05)`。

OI只有在有效源至少2家、一致率至少75%、离散比不高于2.5时才给 Confirm Score 加分。建议 HALDRO Risk Code 增加：128=跨所OI分歧，256=数据掉线/过期。

## 数据新鲜度

分别记录 Coverage、OI、CVD 最后一次有效数据距当前的 bars，并检测有效源数量是否突然减少。有效源中断不能沿用上一根强共振：Strong 必须被数据质量门控，Data Window 输出 Freshness Pack。

## 体制码

趋势/平衡/收敛/扩张/耗尽先只以影子字段导出，不直接改变 Grade 或仓位。积累真实闭柱样本后，按体制×模型验证平均R、MFE/MAE和先止损/先目标，再决定是否进入生产路由。

## Plot 配额策略

新增机器字段前先计算 plot-count。主指标若已有约52/64，新增 Entry Valid、RR、NoTrade、Execution Pack、Trigger Pack、Regime Pack、Contract Pack 后约59/64，已接近上限；后续优先打包字段，不再随意增加独立 plot。

## 独立决策验证器

生产指标保持 `indicator()`。外部验证器消费结构化快照，唯一输出 `GO-A / GO-B / WAIT / NO-GO`，并追加 JSONL 影子样本。验证器至少测试：

- 多空价格几何；
- 未收线与触发过期应为 WAIT；
- 硬禁做位应为 NO-GO；
- 加密副指标反向、关键风险、OI一致率不足应阻断；
- 合格主副共振才允许 GO-A。

开发时先写失败测试再改 Pine/验证器；最终运行静态配额扫描、未定义变量/def-before-use、词法平衡和真实验证器样例。未取得 TradingView 服务器回执时，只能称“本地静态与语义验证通过”，不能称云端编译通过。
