# 单边行情关键位审计（2026-08-12）

## 场景
用户问：主指标遇到单边行情时所有关键位一下子全部突破/破位，表格内容不科学，怎么办？

## 根因（代码级，主指标 SVP_ICT_v2_20260813）
关键位筛选 `f_sup_res` 只按 `位 <= close`（价格位置）选最近支撑/阻力，**不检查 swept 状态**——
已扫（破位）的次级位（DO/前日/上周高与低）照样当选支撑/阻力。单边行情把所有位打成已扫后，
表格仍拿死位当活位用。

## 单边行情下行动格各行失真（诊断表）
| 行 | 现象 | 根因 |
|---|---|---|
| 现位 | 显示"回踩周一高 xxx"但该位已被扫 | f_sup_res 不查 swept，已破位当选回踩位 |
| 前位 | 连续"打破"记录滚屏 | 看位稳定化（0.5ATR 保持带 + 3K 强制切换）单边下每 3K 切一次，全是破位切换 |
| 磁吸↑↓ | "--" | 已扫位不参与磁吸（levels 循环排除 swept）→ 无候选；降级合理但信息真空 |
| 结构 | "扫8/9"虚高 | ictSweptCount 计的是**已扫位**，单边后全是旧的，计数无决策价值 |
| 结论 | "等多 回踩"但回踩位已破 → 自相矛盾 | 方向分（趋势分高）与位体系（全失效）两套逻辑打架 |

## 推荐修复（2026-08-14 已全部落地，SVP主指标_适配修复_20260814，编译0错0警）

1. **f_sup_res 次级位 not swept 门控（已落地）**：支撑/阻力两侧各 4 个次级位（前日高/低、上周高/低）加 `not swept` 条件。前日高/低补全局 bool（`prevDayHighSwept = not na(prevDayHighObj) and prevDayHighObj.swept`，L1354 区，与 prevWeekHighSwept 同模式）；DO 保持原逻辑（当日动态位）；结构位不受影响。**CE10116 注意**：f_sup_res 是 UDF，引用全局 bool 计外部元素 +4，实测 0 错 0 警（250→254 内）。
2. **看位行单边文案（已落地）**：`"位待定"` → `"等新位"`（"多·回踩等新位"），直白告知旧位体系失效。
3. **扫N/M → 活N/M（已落地）**：`sweepCntText = ictActiveCount > 0 ? "活"+N+"/"+(N+M) : ""`——已扫计数无决策价值；活位=0 时不显示（避免"活0/9"占宽）。
4. **配套瘦身（同日落地）**：磁吸行对齐 20260813 定稿 `↑名称 价格·距离A·分NN★HTF·命中%`（距离紧随价格、分数+HTF 合并、命中收尾）；结论行删 finalInvalidSpecificText（失效价=止损价 finalStopCandidate，与风控行"止"重复，na 时旧文案输出"多失效 --"撑宽——用户反馈"空失效"）；obLife 死代码删除；ADR 请求函数化短路（f_adr_daily + `ADR_ENABLE ? f_adr_daily() : na`，const 条件编译期剪枝）。

约束：不动外观参数、不删输入、不加 input（全用已有变量）；遵循增强落地流程
建议→多重审计→确认→落地→模拟验证（用户两次强调建议非结论，不照搬）。

## 可复用审计配方（审任何关键位系统逐条查）
1. 支撑/阻力候选是否过滤 swept（死位当活位 = 最常见单边失真源）
2. 计数类显示（扫N/M）计的是已扫还是未扫
3. 磁吸/看位在无候选时的降级文案是否自洽（"--"合理 vs 死位硬撑）
4. 结论行与位体系矛盾检查：趋势分高 vs 位全失效时是否输出矛盾指令
5. 修复方案是否遵循"移动信息优于删除/最小侵入"——先改判定与文案，不动布局
