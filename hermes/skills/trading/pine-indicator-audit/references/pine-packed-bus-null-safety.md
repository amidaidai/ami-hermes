# Packed Bus 空值传播与总线存活审计

适用于 Pine 主副指标通过单一 `input.source()` 传递合同号、状态码和数据字段的架构。

## 核心不变量

**字段缺失不得让整条 Packed Bus 变成 `na`。**

Pine 算术具有空值传播：任一参与打包的字段为 `na`，后续加法、乘法及最终 `plot()` 都可能变成 `na`。主指标若再用 `nz(bus, 0)` 解码，会把“副指标在线但某字段缺失”误判成“未接线/合同不存在”。

典型危险写法：

```pine
packed = contract * CONTRACT_SCALE + math.min(int(agreementPct), 99) * AGREEMENT_SCALE + payload
```

当 `agreementPct == na` 时，整包可能为 `na`。

## 正确合同

1. 合同号和状态码必须在局部数据缺失时仍可解码。
2. 每个可空字段打包前必须显式给缺失编码：
   - 百分比/计数：通常用 `0`，但必须确认0不会与有效语义冲突；
   - 有正负方向的数据：使用偏移编码并预留一个缺失码；
   - 需要区分“真实0”和“缺失”时，另加valid bit或质量位图。
3. 数据缺失应输出S4/降权及对应风险位，而不是让总线退化为S0/未接。
4. 解码端先验合同号，再读取状态与字段；不得只靠 `source != close` 或 `nz(bus,0)` 判断接线。

## 审计方法

逐个追踪所有参与打包的表达式，重点检查：

- `int(na)`、`math.min(na, ...)`、`math.max(na, ...)`；
- 未经 `nz()`/valid bit 处理的跨所一致率、覆盖率、OI变化率；
- 分母为0时返回 `na` 的派生字段；
- 条件分支中可能未赋值的字段。

必须构造至少以下语义用例：

| 场景 | 预期 |
|---|---|
| 全部数据正常 | 合同有效，S1/S2/S3/S4按规则输出 |
| OI全部缺失 | 合同仍有效，输出S4与OI缺失标记 |
| 成交量聚合失效但单图回退 | 合同仍有效，输出S4/回退单图 |
| 非目标市场 | 使用明确的非适用合同/状态，不输出伪方向 |
| 总线未接 | 主指标才显示S0/未接 |

## 服务端编译回执解析

`translate_light` 的大响应可能包含变量文档及控制字符。验证时不要依赖完整响应可被严格JSON解析后才判断结果；可在解析前移除JSON字符串中非法控制字符，再读取 `result.errors2` 与 `result.warnings2`。最终只报告这两个数组的数量和内容。网络瞬时失败采用带退避重试，以最终成功回执为准。

编译0错0警只证明语法/服务端接受；Packed Bus的空值用例仍需运行态或确定性语义断言验证。
