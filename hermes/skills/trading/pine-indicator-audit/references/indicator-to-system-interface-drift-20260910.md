## 一、这类故障长什么样

Pine 指标是**生产者**，下游系统（`scripts/auto_card.py`、`scripts/tv_data_bridge.py`、分析卡 skill）是**消费者**。
消费者一旦把**行名 / DW 字段名硬编码**，指标侧改面板就会静默断链 —— **不报错、不告警，只是少几行**。

实案：主指标 v13 行动格是 **13 行**，而 `auto_card.py` 的 `main_keys` 还是旧 10 行
（结论/方向/进场/止损/目标/确认/核对/风险/磁吸↑/磁吸↓）。两版只有 4 个名字重合 →
**同一份缓存里 13 行只有 4 行进卡**。丢掉的是：位置·路径·**风控**·CVD·OI·**协同**·结构·**前位**·**现位**。

而 v13 恰好把 **入场/止损/目标/R:R 折进了「风控」行**（`入X·止Y·n.nA·标Z·n.nR`）——
等于卡片连执行三件套都拿不到，只能写「等待触发」。

**判定口径（可复现）**：拿真实缓存跑一遍消费者函数，数行数。
```python
tables = auto_card._tv_cache_decision_tables(cache)
len(tables[0]["tables"][0]["rows"])      # 旧代码 = 4 + 合成行
```

## 二、检测方法：消费矩阵（consumer matrix）

不要靠人眼对文档。用脚本把「指标对外输出」和「系统读取」做笛卡尔比对：

1. 从两份 `.pine` 源码把所有 `plot*/bgcolor/hline/fill(title=…)` 的 **title 字符串**抽出来（就是 DW 名）。
2. 把所有行动格行名抽出来（`array.push(rowLabs, "…")` / `table.cell(actT, 0, n, '…')`）。
3. 对每个名字，在整个消费语料里搜引用：`scripts/`、`docs/`、`config/`、`tests/`、`contracts/`、skills 目录。
4. **零命中的才是可信清单**。

⚠ **不要把「有命中」当成「已消费」**：`Volume` / `CVD` / `SPOT` / `PERP` / `Composite` 这类通用词
会命中几百处无关代码，全是假阳性。**只有 0 命中的名单可以直接拿来用。**

反向也要查：文档里写着、源码里已经没有的名字（v13 的 `MCP CVD Value`、`OI Total`、
`Estimated CVD Value`、`MCP EMA Length 1-4`、`MCP Bull FVG CE`）—— 这些映射恒空，
属于「看起来接了、其实永远拿不到数据」。

## 三、修法：单一契约源

散落在 N 处的硬编码名 = N 个漂移点。收敛到一个模块：`scripts/tv_indicator_contract.py`
（`scripts/` 已在各测试的 `sys.path` 里，直接 `import` 即可）。契约内含四类东西：

| 类别 | 内容 |
|---|---|
| 行名与顺序 | `MAIN_ROW_LABELS` / `SUB_ROW_LABELS` + `ordered_main_rows()/ordered_sub_rows()` |
| 字段名映射 | DW 原名 ↔ 内部 snake_case（主副各一份） |
| 解码器 | 位掩码/枚举 → 人话（见第四节） |
| 兼容白名单 | `LEGACY_*`（只增不删） |

**三条纪律**：
1. **旧名只增不删**。历史缓存和历史测试都引用旧名；删了会连带打断回归链。旧名与新名并存，命中才用。
2. **顺序跟面板，不跟字典**。缓存 JSON 的键序不可信，必须按契约里的面板顺序输出，
   否则卡片行序会随缓存写入顺序漂移。
3. **调用侧加兜底**：契约 import 失败时退化成空壳（返回空列表/`缺失`），不能因为契约文件缺失就整条出卡链崩掉。

另：**动态行标签必须单独处理**。风控行的标签是四态（风控 / 风控·观察 / 风控·未授权 / 禁做·不出价），
只认字面「风控」会在观察态漏读价格。契约里应给 `RISK_ROW_VARIANTS` + `risk_row_value()`。

## 四、解码器：把机器码翻成人话

指标已经把「为什么不能做」编码成位掩码了，别再让模型猜面板摘要。

**`MCP NoTrade Reason Code` 位掩码**（v13 主指标源码里的 `noTradeReasonCode`）：

| 位 | 含义 |
|---:|---|
| 1 | HTF 冲突 X |
| 2 | 过热追高 X |
| 4 | 低流动性 |
| 8 | 价格几何不成立 |
| 16 | R:R 不足 |
| 32 | CVD 质量不达标 |
| 64 | ADR 禁追 |
| 128 | 溢折价不允许 |
| 256 | 本根未收线 |
| 512 | 触发不新鲜 |
| 1024 | 副指标冲突/降权 |

**其他**：`MCP Entry Valid Code`（-3 X禁做 / -2 几何不成立 / -1 R:R不足 / 0 无方向 /
1 待确认 / 2 可执行B/C / 3 可执行A）；`HALDRO State Pack`（0 S0未接 / 1 支持多 /
2 支持空 / 3 冲突 / 4 降权）；`MCP RR Ratio`（≥2.0 过硬闸 / ≥1.5 仅B/C直通）。

### 解码器自检法：找一个「可独立解码的打包字段」交叉验证

`MCP Execution Pack = 几何*1e6 + 收线*1e5 + 止损ATR*10 + (入场码+3)`。
实读 **1801** → `几何0 / 未收线 / 1.80ATR / 入场码-2`。
这一条同时印证了三件事：`Entry Valid Code = -2`、NoTrade 掩码里 `256 未收线` 置位、
以及面板写的「⚠未收线」。**三个独立来源对上，解码器才算可信** —— 只写一个测试断言不算。

## 五、坑

1. **别把「算出来没人用」直接判成闸门缺失**。先查底层条件有没有在别处生效。
   实案：`entrySideHtfOk` / `entryDispOk` 零引用，但 `htfAllowLong` / `dispLongOk`
   已经接在 `setupLongA` 与 `badDisp` 上 → 那只是**冗余包装**，不是漏闸。
   只有「底层条件也零引用」才是真的决策完整性缺口。
2. **别名解析别用通用规则**。`key.lower().replace(" ", "_")` 对带括号/百分号/中文后缀的 DW 名全失效
   （`HALDRO State Pack (0无效/1支持多/2支持空/3冲突/4降权)`、`OI Agreement %`）。
   改成**从契约反查**：建 `{DW全名: snake_key}` + `{DW短名: snake_key}` 两张表
   （短名取 `split(" (")[0]`）。实测实改后 17/17 命中。
3. **加契约别名时别把受控通道旁路掉**。`tv_data_bridge` 故意跳过 `mcp_evidence_*`，
   让它只能走 `_read_evidence()` 校验通道。新增的契约别名循环必须显式排除这些前缀，
   否则通用别名会把未校验的字段漏进缓存。
4. **验证要走真实路径**。快速档卡片根本不渲染 TV 面板，改完跑一次快速卡看不出区别；
   该验的是**缓存路径**（`_tv_cache_decision_tables` 吃 `tv_dmi_cache.json`）。
5. **别用 `git diff --stat` 判断自己改了多少**。工作区脏的时候，行尾风格差异会让
   `diff` 显示整份文件（实测 5550 行），而真实改动是 +68/-4。
   对比**改前备份副本**才能量出自己的改动量。
6. **回归链变红是预期**：改格式串/删死开关/换字段名之后，历史 verify 脚本里写死了
   `inp_new == inp_old`、旧格式串、旧 sha 的断言会集体红。改成容或式
   （`new or old` / `<=` / sha 白名单），**不要删断言** —— 断言还在守契约。
