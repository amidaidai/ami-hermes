# 主副指标实盘一致性核验 + 总线未接定位

> 触发：用户问「主副一致吗 / 你看看一致吗」、主表「协同」行写 `副S0未接`、怀疑总线没接、
> 或需要证明「面板上显示的就是代码算的」。**全程只读，不碰用户图表。**
> 实案：2026-09-10 用户问「你看看一致吗？」→ 查出主副没连上（配置问题，非代码 bug）。

## 为什么必须实盘核验

静态断言只能证明"代码里两处同源"。**主副是两个独立 study，靠一条 `input.source` 总线连接** ——
代码对、断言全绿，总线没接一样会失效。这类问题静态扫不出来，只能读图。

## 三步核验（TV MCP，只读）

| 步 | 调用 | 看什么 |
|---|---|---|
| 1 | `chart_get_state` | 两个 study 是否都在图上（记 id 与名字）；品种 / 周期 |
| 2 | `data_get_study_values` | 副指标那条 `Basic Packed Bus (唯一主副连接)` 的**真实数值** |
| 3 | `data_get_pine_tables` | 同时读主表与副表，**逐行对比**主表「协同」行 vs 副表「信号」行的 S 码 |

第 2 步要**解码验真**，不要只看"非零"：

```
raw   = 2200230275100052
cvdBg = raw % 10                    → 2
raw2  = raw // 10
合同   = raw2 // 10**10             → 22002   ✓ 加密合同
状态码 = (raw2 // 10**9) % 10       → 3       ✓ 与副表「信号」行 S3 一致
```

## 症状 → 根因对照

| 主表显示 | 含义 | 根因 |
|---|---|---|
| `副S0未接` | 总线读到 0 | **`input.source` 停在默认 `close`**（最常见）；或副指标不在图上 |
| `副合同不匹配` | 读到数但合同号 ≠ 22002 | 接错了 plot（接到了别的输出） |
| `副关闭` | `SHOW_AGG_SYNC = false` | 用户主动关了同步 |
| `副不参与` | 非加密标的 | 正常 |
| S 码与副表不同 | 真不一致 | 才是代码 bug |

**定位那个输入**：`data_get_indicator(entity_id=<主指标 study id>)` → 在 inputs 里找
value 恰为字符串 `"close"` 的那一项（主指标**只有 1 个 `input.source`**，可用静态断言钉住这个数量）。
它对应的 `in_<N>` 就是总线入口，需要用户在设置里改成副指标的 `Basic Packed Bus (唯一主副连接)`。

## 这是配置问题，不是代码 bug —— 且 fail-closed 是对的

`aggBusWired = marketCrypto and SHOW_AGG_SYNC and aggContractOk and aggStateCode in 0..4`
→ 未接时 `aggAllowLong/Short` 全 false → **A 级授权直接禁**。
要向用户明确：这不是漏洞，是设计要的失效安全；但也意味着**总线没接期间主指标只读不执行**。

接好后的预期变化（可直接当验收清单）：协同行 `副S0未接` → `副S3冲突`；结论行 `A禁` → `不执行`；OI 行从 `OI未接` 出数。

## 顺带核验的其它项（同一次读图全部可查）

- 前位行角色 / 距离 / 退役时刻：`仍撑·↓9.9A·19:45定`
- 小数前导零：`基差-0.03%`（不是 `-.03%`）
- 行标签顺序没变（`scripts/auto_card.py` 的 `sub_keys` 解析契约）
- 副指标是否还在图上（`chart_get_state` 的 studies 数组；本轮实测副指标被移出过图）

## 已知 quirk

`tv_health_check` 与 `chart_get_state` 的 `resolution` 字段可能不一致
（20260910 实测：health_check 报 `1D`、chart_get_state 报 `15`）。
以 `data_get_study_values` 的 `source_bar_time` 与面板文本（锚定标记如「本锚近NK」「日·」）为准，
不要据此判断周期、更不要据此改代码。
