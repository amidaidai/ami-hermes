# 双指标表格压宽与数据合同修复（2026-08-27）

适用于成熟的 SVP 主指标 + AggVol 副指标，在**不增加表格行数和宽度**的前提下修复决策合同并提高可读性。

## 1. Packed Bus 不得因可选字段 `na` 整体失效

危险写法：

```pine
int packed = contract * ... + math.min(int(oiAgreementPct), 99) * ...
```

当四所 OI 全缺时，`oiAgreementPct=na`，任一加法项为 `na` 会令整条 Packed Bus 变成 `na`。下游经 `nz(bus, 0)` 后会把“副指标在线但 OI 缺失”误判为“S0 未接线”。

正确合同：

```pine
int oiAgreeEnc = math.min(int(nz(oiAgreementPct, 0.0)), 99)
int packed = contract * ... + oiAgreeEnc * ...
```

- 合同号和 S 状态必须继续输出；
- OI 缺失应编码为 0，并由质量状态进入 S4；
- S0 只表示未接线、合同不匹配或副指标真正不可用；
- 对所有 Packed Bus 字段做逐项 `na` 传播审计，不能只检查最终 plot。

## 2. 同级双边候选不得用固定方向破局

若多空最高等级相同且都大于 0，固定“多头优先”会制造隐性方向偏置。正确仲裁：

- 等级高者胜出；
- 同级双边异常 → `WAIT/C等待`；
- X 仍覆盖全部方向；
- 预仲裁（用于 X）与最终仲裁必须使用相同的同级规则。

同时检查稳定化状态：同级双边时不要让 `setupGradeRaw` 继续按 if/else 顺序落到多头。

## 3. 表格压宽：一项信息只出现一次

主表职责：

- 位置：价在 VA 内/外、VWAP 锚、周月环境；
- 结论：做不做、最高优先阻断、信号年龄；
- 方向：方向、状态、条件完成度；
- 进场：许可、下一步、价格/触发链；
- 风控：止损、目标、R:R、最高优先阻断；
- CVD/OI：各自独立证据；
- 协同：S0–S4、高周、时机，不重复 CVD/OI；
- 结构：结构事件、市场状态、下一步；
- 磁吸/前位/现位：保持各自生命周期职责。

若“条件完成度”已在方向行，位置行不得再显示第二份就绪度。规则分数不要写成百分比，避免被误读为胜率；使用 `条件7/10` 或 `就绪7/10`。

## 4. 副表固定六行的紧凑增强

固定六行不增加：信号、结论、流向、持仓、量能、操作。

信号行只显示：

1. S 状态；
2. 共振票；
3. 一个最高优先风险；
4. 无风险且未满票时，一个最高优先缺票。

推荐风险优先级：

`CVD背离 > OI背离 > 汇率缺 > 掉线 > 低覆盖 > 单所主导 > 回退单图 > OI分歧 > 高周逆 > LSR拥挤/缺失`

无风险时缺票优先级：`CVD > OI > 量 > HTF`。不要同时罗列全部风险和缺票。

操作行不重复信号行的 `Sx` 前缀，只给恢复动作，例如：

- `单所主导·等成交分散`
- `回退单图·不升级主指标`
- `覆盖不足·等覆盖恢复`
- `OI分歧·等至少2所同向`

## 5. 信号年龄必须有正确状态机

常见错误：信号持续时年龄不递增，导致每根都显示“新”；从未发生过信号时却显示“信号N根前”。

正确做法：

- 用 `lastSignalDir != 0` 区分“历史上发生过”；
- 信号边沿归零；
- 此后每根递增，包括信号仍持续时；
- 当前信号显示 `新/持续N根`；
- 无当前信号只显示最近短窗口（快进快出可用 6 根），更旧历史不再撑宽。

## 6. 用户工作流偏好

- 此类人工决策指标默认不主动增加警报、自动交易或自动执行；用户明确要求时才新增。
- 表格优化优先做职责去重、短词替换和风险优先级，不通过删五所成交量、四所 OI、Packed Bus、Entry/Stop/Target 或磁吸信息来压宽。
- 指标修改交付到桌面 `hermes下载文件/<任务名>_YYYYMMDD/`；新文件名带修改日期，保留旧版。

## 6. 动态文本预算与逐行职责审计

表格是否“太宽”不能只看 `table.new()` 的行列数，必须审计每个状态下最终渲染的动态字符串。主表即使声明 18 行，也可能实际填充 13 行；副表必须保持固定 6 行。检查时列出每一行的最坏组合，并识别跨行重复。

### 主表职责

- `位置`：VA内外、VWAP锚、周月环境；不显示第二份完成度。
- `结论`：只回答 X/WAIT/A/B/C、最高优先原因及必要解除条件。
- `方向`：唯一方向、趋势/反转/均衡、`条件x/10`。
- `进场`：许可、价格、触发链；不重复现位名称和普通环境解释。
- `风控`：止损、目标、R:R；若结论已显示阻断原因，不再重复 `阻:`。
- `CVD/OI`：只显示各自事实及其对当前计划的支持/反向关系。
- `协同`：S0–S4、主副关系、高周和必要时机；不重复CVD/OI细项。
- `结构`：只显示已确认结构事件和市场体制；“做回踩/等反抽”等动作交给进场或现位。
- `磁吸↑/↓`：保留身份、价格、ATR距离、评分、HTF和触达率；先缩短目标名，再考虑删次要修饰。
- `前位`：名称、价格、生命周期原因；通常不需要历史确认时间。
- `现位`：具体盯盘位置和到位动作；避免与结论、进场重复“等回踩”。

### 副表职责

固定顺序仍为 `信号/结论/流向/持仓/量能/操作`：

- `信号`显示S状态、共振票和一个最高风险；无风险时才显示一个最高缺票。
- `操作`只显示动作/恢复条件，不重复信号行风险名。例如信号为`S4·低覆盖`，操作写`不升级·等覆盖恢复`。
- `流向`优先显示当前锚与滚动背景的“同向/冲突/样本不足”，不要每次机械拼接“今日+滚动+前锚”；前锚只有冲突时才值得占宽。
- `持仓`正常时显示四象限、变化率、共识；低共识时显示`分歧`，不要同时打印完整百分比、分歧标签和多个来源说明。
- `量能`的主导、同步放量、去杠杆强度使用互斥优先级；不要把全部解释同时拼接成最长行。

### 语义预算，不做盲截断

每行应按语义优先级降级，而不是按字符数硬截断：

1. 必保：X/WAIT/A/B/C、唯一方向、可行动价格、触发/恢复条件。
2. 次保：R:R、OI/CVD方向事实、S状态、结构事件。
3. 可先删：确认时间、旧信号年龄、历史触达率、HTF装饰、次级解释词。
4. 禁止截出残句，如把完整触发链截成不可执行的半句话。

建议用状态分支生成“正常短格式/异常短格式/数据降级格式”，不要新增一个只隐藏显示但保留全部拼装复杂度的所谓紧凑模式。

## 7. 增强分级与冻结边界

先分类为`已具备/部分/缺失/伪增强或不建议`。当前紧凑双指标优先做零宽度或负宽度增强：短名称映射、风险优先级、同向/冲突压缩、逐行去重、动态文本预算。不要为可读性新增：

- 第三套评分或第三套CVD；
- 更多表格行、交易所或颜色；
- 副指标Entry/Stop/Target；
- 警报、自动交易或自动执行；
- 未经验证的Footprint/真实清算叙事。

实施顺序：先逐行职责去重，再短码化磁吸/协同，再压缩副表CVD三层记忆与量能互斥显示，最后做客户端最坏状态宽度、实时/收线、重载和回放验收。

## 8. 验证

- 完整源码 `translate_light`：两份均 `errors2=[]`、`warnings2=[]`；
- 静态断言：副表恰好六行、唯一 `input.source()`、五所量和四所 OI 保留、无新增警报；
- 语义断言：OI 全缺时合同仍有效且进入 S4；同级双边返回等待；表格不存在重复完成度；
- 文本断言：结论/进场/现位不三次重复同一等待动作；信号/操作不重复同一S风险；风控不重复结论已显示的阻断；
- 客户端最终验收：双指标同时加载、Packed Bus 真接线、S0→真实 S 状态，并检查每个高风险/长价格/长目标名状态下的实际表格宽度与回放稳定性。
