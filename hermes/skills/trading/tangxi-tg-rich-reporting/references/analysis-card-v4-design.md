# 分析卡 v4 设计规范（2026-08-31 用户参考图驱动）

## 用户原话

「类似这样，再优化的」 + 提供深色终端式参考图（Bloomberg/TradingView 风格）作为目标形态。

## v4 视觉规范（必须遵守）

### 整体
- **底色**：`#0E0E12`（近黑，非纯黑 `#000`）
- **尺寸**：1080 宽（出图 ≤ 2200 高）
- **字体**：微软雅黑 `msyh.ttc`（Windows 自带）
- **风格**：终端式 / 信息密度优先 / 高饱和强调色

### 配色（信号灯四色 + 中性灰）
| 角色 | 色值 | 用途 |
|:---|:---|:---|
| 主红 | `#EF4444` | 做空/风险/止损 |
| 主绿 | `#4ADE80` | 做多/确认/操作建议 |
| 主黄 | `#F59E0B` | 警示/待定/中间态 |
| 主蓝 | `#2563EB` | 表头/强调数字 |
| 灰 label | `#C8CCD2` | 字段名 |
| 白数值 | `#FFFFFF` | 关键数字 |
| 灰 mid | `#9CA3AF` | 中性信息 |
| 蓝 accent | `#60A5FA` | 现价高亮 |
| 暗分隔 | `#1F1F26` | 行间分隔线 |

### 填充色（深色主题专用）
| 用途 | 色值 | 说明 |
|:---|:---|:---|
| 红色块背景 | `#3A0808` | 裁决条 / 风险条 — **不能用 `#1F0707` 等过暗色** |
| 绿色块背景 | `#062812` | callout 框 — 同理 |

### 布局（自上而下）
1. **标题行**：白色 `BTC 78,541 · 15m · 2026年8月31日 19:05`，字号 34
2. **裁决条**：深红填充 `#3A0808` + 红边 `#EF4444` 2px + 左 4px 红色粗条 + 红字 28pt
3. **KPI 行**：4 个大字块（44pt），用 1px 灰色竖线分隔；右侧可选 sparkline
4. **Section 区**：每个 section 标题 = 左 3px 绿竖条 + `📊 标题` 绿字 26pt；标题下接三列表格
5. **三列表格**：蓝色表头 `#2563EB` 42px 高 + 数据行；最后一列若为"评级"自动加 `●` 色块前缀
6. **风险 Banner**（可选）：深红填充 + 红边 2px + 左 4px 红粗条
7. **绿色 callout**（可选）：深绿填充 + 绿边 2px + 左 4px 绿粗条；4 行操作建议
8. **页脚**：灰色 mid 20pt

### 价格标尺（信号矩阵右侧）
- 5 个关键位：止损↑ / 摆动高 / 现价 / VWAP / 目标↓
- 标尺高度 240-300px
- 每条线带价格 + 标签
- 颜色按 level 编码（止损红、目标绿、现价蓝）

### Sparkline（KPI 行右侧）
- 短时序点（30-60 个），自动归一化 y
- 绿色折线 2px + 末端 8px 圆点高亮
- 高度 60px

## v3 → v4 升级点（避免回退）

| 项 | v3 | v4 |
|:---|:---|:---|
| 红色块填充 | `#1F0707`（视觉上等同黑） | `#3A0808`（明显深红） |
| 绿色块填充 | `#07140A` | `#062812` |
| KPI 竖线 | 无 | 1px 灰色分隔 |
| Section 标题 | 绿字+emoji | + 左 3px 绿竖条 |
| 评级列 | 单色文字 | ● 色块 + 文字 |
| Sparkline | 无 | KPI 右侧折线 |
| 价格标尺 | 无 | 第一个 section 右侧 |

## 验证清单

每次出卡后必须验证：
- [ ] 整体在 1080 宽，≤ 2200 高
- [ ] 中文显示无方框（msyh.ttc 已确认可用）
- [ ] 红色块/绿色块肉眼可见填充（不是只有边框）
- [ ] 4 个 KPI 数字清晰
- [ ] 表格评级列有色块 ●
- [ ] 推 TG 后用户在当前 thread 收到（target = `telegram:-1003733144325:<thread_id>`）
- [ ] 文件名带时间戳：`outputs/<品种>_YYYYMMDD_HHMM.png`

## 调试方法

如果不确定某个元素颜色效果：
```python
from PIL import Image
img = Image.open("outputs/test_card_v4.png")
crop = img.crop((x, y, x2, y2))   # 裁出关注区域
crop.save("outputs/debug_crop.png")
```
然后用 `vision_analyze` 调模型问"框内是深红底还是黑底"——视觉模型能识破"看起来像黑"的伪填充。
