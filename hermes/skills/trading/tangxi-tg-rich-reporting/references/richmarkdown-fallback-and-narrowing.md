# RichMarkdown 表格兼容性参考

## 目标
让 Telegram 报告在移动端和旧客户端保持可读：RichMarkdown 真表格优先，语义文本兜底。

## 规范化顺序
1. 识别真正的管道表：表头、分隔行和至少一行数据必须构成连续表格块；普通正文中的单个 `|` 不得误判。
2. 清理表格前的独立标题行或在标题与表头之间插入空行。
3. 清理单元格内的粗体、反引号、转义字符和换行，避免破坏解析。
4. 宽表压缩为不超过三列：保留前两列，剩余字段按“字段名：值”合并进“详情”列。
5. 将规范化结果写入 `rich_message.markdown` 后再调用 `sendRichMessage`。

## 失败兜底
普通 `sendMessage` 不具备 Markdown 表格渲染能力。RichMarkdown 失败时，不发送原始管道符表格；逐行转换为短标签句，例如：

```text
指标：OI · 读数：107,616 · 状态：持平
```

标签顺序应与原表头一致，内容保持简短，避免用空格对齐伪造表格。

## 回归检查
- payload 使用 `rich_message.markdown`，且内容已规范化。
- 表格前没有紧贴的非表格标题行。
- 失败降级文本中不出现连续的原始管道表行。
- 非表格正文中的普通半角 `|` 保持原样。
- 自动化投递仅在 `TANGXI_ENABLE_AUTOMATED_TG=1` 且 target 与 `TANGXI_AUTOMATED_TG_TARGET` 精确匹配时放行。
