## 三、FMP 端点迁移（403 + 字段名静默归零）

实测（同一 key）：

| 端点 | 结果 |
|---|---|
| `/api/v3/quote/%5EVIX?apikey=` | **403 Forbidden** |
| `/stable/quote?symbol=%5EVIX&apikey=` | 200 · `price 15.84`、`changePercentage -11.21` |
| `/stable/quote?symbol=%5EGSPC` | 200 · `7656.98`、`+0.86%` |
| `/stable/quote?symbol=%5ETNX` / `DX-Y.NYB` / `GC%3DF` | **402 Payment Required**（套餐不含） |
| `/stable/quote?symbol=EURUSD` | 200 |

- 同仓 `fmp_quote` / `fmp_forex` 早已用 `/stable/quote?symbol=`，**只有 `macro_overview` 漏迁**
  → 宏观整步恒 `unavailable`（0 字段），在卡上表现为「本轮未采到有效字段」。
- 字段名：v3 = `changesPercentage`；stable = `changePercentage`（无 s）。只读旧名 ⇒ 涨跌幅恒 `0.0%`。
  修法：`_fmp_change_pct()` 两个名字都认，macro / fmp_quote / fmp_forex 三处一起改。
- 402 的符号写进 `unavailable_fields`，能取到的照常输出 —— 部分可用必须可见。

修复后实测：`📊 宏观[live]: 中性 | VIX 15.84 | SPX +0.9%`；宏观方向票恢复
`🟢 中性偏多 → 偏多 (强度0.3)`；管线审计 `宏观背景 ✅ 已完成`；完成度 11/15 → **12/15**。

## 四、空结果被缓存成 live（矛盾卡面的根因）

症状：同一张卡「来源矩阵写 `live`」+「管线审计写 `⚠️ 本轮未采到有效字段`」。
机制：通用 TTL 缓存对 fetcher 返回的**空 dict** 也执行写盘；TTL 内命中缓存后返回
`status="cache"` —— 而 `cache` 属于 LIVE 状态集合，于是被矩阵当成可用。

修复（`_cached`）：
1. 空结果不入缓存；
2. 增加可选 `cache_when(payload) -> bool`，让「部分成功才算成功」的源自己定义（macro 只认带时间戳的 payload）；
3. 只有真的取到至少一个字段才盖采集时间戳（时间戳同时决定能否报 `live`）。

同类扫查：任何自带 TTL 缓存的采集层都要问「失败/空结果会不会被缓存后伪装成 live」。
