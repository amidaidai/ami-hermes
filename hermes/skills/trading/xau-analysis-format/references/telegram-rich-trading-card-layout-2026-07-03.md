# Telegram RichMarkdown 交易卡首屏与真表格布局（2026-07-03 会话沉淀）

## 背景

棠溪多次纠正：普通聊天回复里的 Markdown 表格会在 Telegram 降级成项目符号，不是真表格；全篇只有表格也不好读；首屏必须先展示“现在基本情况”，并且使用北京时间。

## 必须使用的发送路径

正式交易卡 / 分析卡 / 审计卡 / 能力清单，只要包含表格：

1. 生成 RichMarkdown 文本文件或字符串。
2. 通过 `scripts/telegram_reliable.py::send_telegram_reliable(..., parse_mode="RichMarkdown")` 发送。
3. 目标话题按品种：BTC 话题 `telegram:-1003733144325:386`，XAU 话题 `telegram:-1003733144325:385`，其他/报告 `416`。
4. 终端回执应为 `True rich_sent`。
5. 不要把正式表格卡作为普通 assistant 文本回复发送；Telegram 会降级成“字段 + 项目符号”。

## 首屏固定顺序

首屏必须像“交易员简报”，不要像流程日志。先给时间、方向、现价、核心动作，再补结构位。禁止在卡片正文前写“开始完整驾驶舱 / 正在补数据 / 准备截图”这类过程句；过程句只允许出现在内部工作流，不进入正式分析卡。

```markdown
## 2026年7月3日15：40 · BTC

○ 等待 · 现价 `62,000` · 主区间 `61,806-62,105`

BTC刚从 `62,386` 冲高回落，15m仍在 VWAP/POC 上方，但5m执行层已经转短空去杠杆。这里不是追多位，属于“高位回踩确认”。

关键位：VWAP `61,806` · POC `61,717` · VAL `61,494` · 压力 `62,105→62,386`

结论：等 `61,806-61,717` 守住再轻仓多；15m收破 `61,494`，多头预案失效，转看 `61,229`。
```

要点：
- 第一行：北京时间中文格式 + 品种。
- 第二行：方向符号 + 状态 + 现价 + 主交易区间，短而醒目。
- 第三段：2句话说明“刚发生了什么 + 为什么不能/可以动”。
- 第四行：只放2-4个最关键结构位，优先 VWAP / POC / VAL / VAH / DO / 周高低。
- 结论：不用堆指标，必须明确动作：等、做、不追、失效。
- 正式卡开头禁止“TV运行正常/开始采集/补外部源/准备截图”等过程日志。

## 避免降级的排版规则

- RichMarkdown 标题用 `## ① 结构位`，标题和表格之间空一行。
- 不要用紧贴表格的 `表1 · xxx` 标题行；它容易导致手机端降级成文字。
- 表格列数保持 2-3 列，最多 4 列；交易卡优先 3 列。
- 单元格短句，避免长段落撑爆手机宽度。
- 价格用反引号，结论用加粗。
- 正式卡可以在 Telegram 话题用 RichMarkdown 发送；普通聊天最终回复只做简短提示和 MEDIA，不承载正式表格。

## 发送代码模板

```python
from pathlib import Path
import sys
sys.path.insert(0, 'D:/Hermes agent/scripts')
from telegram_reliable import send_telegram_reliable

text = Path('outputs/card.md').read_text(encoding='utf-8')
ok, reason = send_telegram_reliable(
    'telegram:-1003733144325:386',
    text,
    parse_mode='RichMarkdown',
    timeout=20,
    retries=3,
    persist_on_fail=True,
)
print(ok, reason)  # 期望 True rich_sent
```
