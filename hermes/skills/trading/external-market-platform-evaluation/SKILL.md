# 外部行情/交易平台评估

触发：用户丢来一个交易/行情/看盘平台链接并问「这个怎么样 / 值得用吗 / 能不能接进来」，或在对话中引用第三方平台的数字。

产出目标：一句话结论 + 能补哪块空白 + 三条落地动作 + 明确的「不要做」清单。**不是功能清单的复述。**

## 评估顺序

1. **取证（先文档后营销）**：抓首页，再找机器可读文档面（`/learn/llms.txt`、`/docs/llms.txt`、`/openapi`）与 **FAQ** —— 接入门卡通常只写在 FAQ 里，不在营销页。
   若用户给的是**分享/会话链接**（`/chart/<id>`、`/share/<id>`、带 `?act=` 的地址），先无 cookie 打开看**最终落点 URL**：跳到 `/login?act=xxx` 就是登录墙，链接没坏、平台也不是不可用，只是要先给凭据。
2. **数据对账**：挑 1-2 个关键数字与官方源逐项对账（BTC 永续价/OI/资金费率/24h 高低/成交额；黄金用 OANDA 或金十口径）。端点、判据与「滚动窗不算错」见 `crypto-market-verification` 的「第三方源数据比对」节。对账表要写进回复。
3. **能力矩阵**：三列 `能力 | 我们现有 | 它能补什么`，**只列能补空白的行**。重复项不列 —— 罗列功能等于没做评估。
4. **门卡**：API 是否开放新订阅（closed 就是 closed，这条决定它是「能进管线」还是「只能人看」）、免费档实际额度（标的数/刷新频率/分辨率/提醒数）、哪些能力被推荐制或订阅锁住。**密钥存在 ≠ 有权限**：用密钥实测 1-2 个目标端点看返回码（`401 Upgrade plan` 这类），并确认鉴权头名字（各家不同，CoinGlass 是 `CG-API-KEY`，写错会回 `30001 API key missing`）；旧版接口测到 500 即当作已下线。
   **免注册数据站测的是「免登录直连」，不是订阅档**：用 `performance.getEntriesByType('resource')` 列出它的 XHR 全 URL，在 Python 侧无 cookie/无密钥重放 → 返回结构化 JSON 即判「能进管线」的白嫖级源，写明刷新周期（`cycle_secs`）与字段级新鲜度（`age`）、以及必须走本机代理；只有「加密字段 + 一次性签名」才按「只能人眼看」处理（判据与取数配方见 `references/browser-evidence-capture.md`）。
5. **风险**：品牌与团队连续性（改名/换主体要写出旧名）、执行语义（宣称跨所路由成交或「可撤销」= 第三方托管/代理下单）、背书证据等级、平台自有 DSL 与我们的 Pine 主指标是否兼容。
6. **结论**：用 / 不用 / 只当副战场，给 3 条具体落地动作 + 「不要做」清单。

## 子类：评估 MCP 服务 / 工具仓库

用户丢来 GitHub 仓库或 MCP 服务地址时，顺序与评估平台账号不同：**先核实身份，再判类别，最后才谈能不能用**。

1. **先查它是不是已经装着的那个**（最容易被跳过、代价最高的一步）：`grep -n -A3 "<名字>" ~/AppData/Local/hermes/config.yaml` 拿到实际注册路径，再到该目录 `git remote -v` + `git log --oneline -3` + 读 `package.json`/`pyproject.toml` 的 name。「要不要装这个」有相当比例的真实答案是「它就是你正在用的，而且本地版更新」。跳过这步就会向用户推荐他现役的组件。
2. **判类别——类别决定它能不能进主证据链**：

   | 类别 | 判定特征 | 能力边界 |
   |---|---|---|
   | 数据 API 型 | 从公开端点取数（scanner / 公开 REST / 第三方库），**不接触也不需要你的账号** | 拿不到你图表上的自研指标，没有截图 |
   | CDP / 桌面驱动型 | 连本机已登录的桌面应用（`--remote-debugging-port`），README 会写「需要有效订阅」 | 能读自研指标绘图与截图——**唯一能进主证据链的一类** |
   | 官方托管 / 授权型 | 厂商托管、OAuth 拿你账号换它的官方数据面（例 `mcp.tradingview.com/mcp`） | 拿得到官方数据面，**仍读不到你图表上的自研指标与截图**；门槛写在文档页的订阅档里 |

   同一个产品名（如「TradingView MCP」）下三类都存在，只看名字必然判错；判定看的是「它从哪取数」，不是它宣称覆盖什么。
3. **官方托管版的档位门槛写在文档页而非营销页**：实读 `/mcp/docs` 一类页面拿原文（官方 TradingView MCP 明写 `Included in Essential and above; trial plans don't include MCP access`——免费档不在内）。这类门槛不实读文档就无法证伪。
4. **免费档能不能跑要实跑，不从文档推断**：文档写「需要有效订阅」的 CDP 桥，免费账号往往实跑可用（它只驱动你自己已登录的桌面版，不绕过任何付费墙）。判据是一次完整写操作 + 读回（切品种 → 读自研指标 → 全屏截图），不是读 README 的 Prerequisites。跑通就把「免费档可用 + 哪几项限制仍在」写进结论。
5. **「缺口」必须先实跑内部源验证过，不是凭印象**：在结论里写「它能补 X」之前，先 grep 脚本树定位本系统管 X 的那个函数，**并当场调用它读一次真实输出**。
   反例（本次实测）：把「宏观数据（VIX/SPX/DXY/美债/金银）缺失」当成已成立的前提去推荐一个外部数据源，实跑 `macro_filter.fetch_macro_snapshot()` 返回的却是 **live** 的 VIX 17.2 / SPX 7585.73 / DXY 99.664 / 10Y 4.996 / Gold 4368.2 / Silver 65.08，还带完整降级契约（`status=live` / `cached=false`）——缺口根本不成立，整条推荐的前提作废。
   配套判据：**候选源与本系统现有源的同一个数字逐位相同 ⇒ 同源，增量必然为 0**（两个实现都走高 Yahoo，VIX/SPX 完全一致），此时无论它列出多少功能都判「不需要」。没跑过内部源就写下的缺口 = 编造评估前提。
   门槛也不要猜：官方托管型的能力/档位门槛只写在机器可读的文档页（`/mcp/docs` 一类），不写在营销页；不实读就无法证伪。

## 结论写法（固定）

- 首行一句裁决，例如：`值得注册免费用，但只能当副战场＋交叉验证，不能替代 X，也不要碰 Y。`
- 随后两张窄表（≤3 列）：`数据对账` 与 `能力补空白`。
- 再 `短板与风险` 按严重度排序 + `建议怎么用` 三条 + `不要做`。
- 无装饰分隔符；先结论后数据；每轮更新带新截图（拿不到桌面版截图时以 DOM 文本取证并说明）。
- 裁决若是「能用，但要你先给登录态 / 先订阅」，首行就把「给什么才能用」写明白，并给一条决策问句；要凭据只走 vault（`browser_vault_save_login` / handle），**绝不索取密码**。

## 用户问「能不能给我自动套利 / 给你自动化」时

按三层答复，层次分明，先给结论不列选项：

| 层级 | 答复 | 依据 |
|---|---|---|
| 拉数 / 盯盘 / 算账 | 能，且当场落地 | 免登录 JSON 面已实测可取，只读、无资金风险 |
| 出候选 + 成本 + 回本天数 + 失效条件，人工点单 | 能，推荐 | 符合本用户「只手动交易」；给候选页而非执行三件套（只有 GO-A + executable + R:R≥2 才给三件套） |
| 自动下单（跨 CEX API + 链上签名） | 不做 | 需双边资金、CEX API key 与链上私钥；单腿爆仓 / 提款延迟 / 新场所跑路都是真金风险 |

- **私钥、助记词、API key 一律不索取、不接受、不写入对话或落盘**；要凭据只走 vault（`browser_vault_fill` / handle），绝不索取密码。
- 自动化的**第一个交付物是只读扫描脚本 + cron 落档 + 阈值提示**：本地留档，推 TG 需用户单独授权，不自动外发、不自动 flush。
- 「新场所给的高年化」= 对手方风险溢价，不是 alpha；候选表必须带 OI / 成交量 / 场所新旧标注，并给出「现价差为正 + 已实现为正 + 回本天数」三重门槛。
- 起手脚本：`scripts/perp_dex_arb_scan.py`（只读、并行取数、落 json+csv）。
- **候选的「成本」必须按该对自身的两条腿取**（`execcost/live` 里按 exchange+symbol 配对），「最便宜两场所」只能当下界并明确标注；**单腿名义 ≤ 该场所该币 OI 的 1~2%**，否则那档滑点数字作废。策略、成本模型、退出阈值与 GitHub 先例见技能 `funding-rate-carry-arbitrage`。

## Pitfalls

- **营销页与文档口径冲突时以文档+实测为准**：实测遇到首页写「20+ venues」而文档写「6 场所/13 交易所」；对外只写文档口径，不抄营销数字。
- **免费档能力要写实际值**：营销说「实时」，免费档常被推荐制或订阅卡住（1 秒 K 线、高分辨率热图、多图工作台、提醒条数）。评估时写免费档实际能给什么，不按承诺推荐。
- **平台自研 DSL ≠ Pine**：主指标（SVP）无法迁移，**执行授权不跟着搬** → 该平台最高只能当副战场/交叉验证，不能替代 TradingView 作主战场。这条决定结论，必须在第 1 段就写清。
- **执行通道默认不碰**：凡把「跨所路由下单」「成交可撤销」当卖点的平台，属第三方托管/代理语义；本用户只手动交易 → 只用图，不用它的下单权限。
- **背书与变现按 D 级处理**：推文墙多含推荐链接；场所跳转接口（如 `/api/venues`）会直接暴露推荐码（`url` 里的 `ref=<CODE>`）；「免费群 / 我分享自己的仓位 / 自动推机会」是引流闭环 —— 只作线索不作证据，引用其覆盖与收益宣称时把变现关系写明。
- **第三方「机会/排行」页的默认排序是把最假的机会排最前**：结论只建立在平台自带的**已实现/历史**列（如 24h/7d/30d settled、成本列）上，不用「现价差」「年化」快照列。价差类榜首常见两种假机会：① 同名不同工具（同一 ticker 的 RWA pre-IPO / 股票永续在不同场所是不同标的，8~16% 的价差是结构性错配，历史实现值≈0）② 资金费年化快照（极端小时费率在小市值上会翻向，榜首年化上千%的组合 7d 实际常为负）。平台自身的阈值（如 >10% 标 suspect、>20% 直接隐藏）可当证据引用，但**阈值之内不等于真机会**。
- **价值必须对应真实缺口**：结论里的「能补什么」要落到我们现有栈的空白（分交易所 CVD、期权 GEX/IV、清算与 TP-SL 热图、官方聚合 API）。说不出缺口的平台结论就是「不需要」。
- **SPA 平台取证走 DOM 文本**：无头浏览器可能只拿到移动外壳（容器 class 含 `--mobile`、图表 canvas 定位在视口外 `x ≥ 视口宽`）。数据链路照常可读（DOM 文本、页面内实时数值），桌面版截图不保证拿到 —— 取证用文本，不要为截图反复折腾。
- **无头浏览器 UA 会被边缘直接拦**：症状是同一 URL 用 curl（正常 UA）200、在无头浏览器里 nginx 404 或空 200。修法是导航前 `cdp('Network.setUserAgentOverride', userAgent=<正常 Chrome UA>, acceptLanguage='zh-CN,zh;q=0.9', platform='Win32')`。判定三分法与更多取证代码见 `references/browser-evidence-capture.md`。
- **「抓到了接口」不等于能直连取数**：付费平台网页接口常返回**加密字段 + 一次性签名 token**，把页面 token 拿到外部重放只回空壳。必须实测过外部重放再谈接入，不要因为「浏览器里能看到数」就承诺脚本可取。
