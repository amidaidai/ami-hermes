# 骨架卡片审计陷阱速查

用户以骨架格式（品种→周期→决策→原因 → 1.环境 2.结构 3.博弈 4.操作 5.风控）发卡时，逐项过以下清单。

## P0（致命 — 必须指出）

### 1. 方向-结构-资金三角冲突
最常见的陷阱。三个维度必须一致：

| 维度 | 信号 | 方向 |
|------|------|------|
| 市态判断 | 派发/吸筹/趋势/震荡 | 偏空/偏多/中性 |
| 结构（VWAP/EMA/价值区）| 上方/下方/内部 | 偏多/偏空/中性 |
| 操作方向 | 做多/做空/不进 | — |

如果三个指向不同方向（如"派发结构"+"选多头"），这是致命矛盾。→ **拉直：以结构和市态为准，操作方向服从。**

### 2. 模型缺失
用户骨架卡经常跳过五类模型声明。必须逐项过筛：
- VWAP反抽：价格是否触碰 VWAP 并拒绝？
- VAH/VAL回收：是否打出价值区外后回到区内？
- POC拒绝：是否回到 POC 附近失败？
- 扫流动性回收：是否刺破关键高/低后快速收回？
- 突破接受：是否突破关键位后回踩不破？

**任意一个都不符合 → 状态只能是 B等待 或 X禁做，不给入场价位。**

### 3. 止损距离 vs ATR
用户骨架卡常见的紧止损（如 43 点止损 vs ATR 287 = 0.15x ATR）。
- 止损应 ≥0.5x 4h ATR
- 低于此值 = 被正常波动扫掉的概率 >50% → 直接在审计中指正
- 重算：止损距 = max(用户指定, 0.5×ATR, 结构位外侧 + 缓冲)

### 4. 重大事件遗漏
用户骨架卡经常不检查催化剂日历。必须查：
- 金十财经日历（mcp_jin10_list_calendar）
- 金十快讯（mcp_jin10_list_flash）搜关键词
- web_extract 新闻源看当日焦点

Fed 决议、CPI、NFP、FOMC 纪要等 → 30 分钟前硬禁。

## P1（严重 — 应指出并修复）

### 5. 13分评分缺失
骨架卡不带评分。必须补全：结构(0-3) + 周期(-2~2) + 订单流(0-2) + 衍生品(0-2) + 催化(0-1) + 风控(0-2) + 情绪(-1~1)。

评分后的闸门规则：
- 10-13：A做多/A做空
- 6-9：B等待
- 0-5：X禁做
- 数据 C 级：最高 B
- 高周期明显冲突：最高 B
- R:R 低于 1:2：禁做

### 6. 数据未定级
必须输出：`数据：{A/B/C} · {来源数}源{一致/冲突} · {备注}`

XAU 专门：OANDA 现货 → 金十 → Yahoo GC=F/MGC=F。

### 7. 催化未确认
催化至少 2 源（金十 Flash + web/X），单源标注"单源"。

### 8. 仓位计算缺失
骨架卡常写"1%风险"但不执行计算。标准输出：
```
风险金额 ÷ 止损距离 = 数量 · 名义 · 保证金 · 最大亏损 · R:R
```

## P2（格式 — 应修复但不影响逻辑）

### 9. 非等级 emoji
仅 🟢🔵🟡🔴 可用。👈⚠📈📉 等装饰 emoji 禁。

### 10. 置信用星级
用 `{n}/5` 而非 `⭐⭐⭐`。

### 11. X 未标注为 X禁做
`1h X` → 应改 `1h 空头排列` 或 `1h X禁做`，明确语义。

### 12. 监控闭环缺失
骨架卡常不写 monitor_levels.json + source_snapshot.json + trade_plans.jsonl 写入。

## v9.7 新增陷阱（2026-06-17）

### 13. CVD C级未被处理
骨架卡的订单流段常引 TV CVD 但不标等级。规则：
- CVD C级 → 订单流评分 ×0.6
- CVD C级 → 仓位上限半仓
- CVD C级 → 模型确认需多重确认（至少再加 1 个独立信号）

### 14. 跨品种关联写了但不管
骨架卡常写"关联 DXY走强利空"但方向依然做多。规则：
- DXY日内涨幅>0.3% + BTC方向做多 → 扣 1 分
- VIX日内涨幅>5% → 扣 0.5 分
- 有冲突必须扣分，不能"写了当看过"

### 15. 置信度拍脑袋
骨架卡标注"置信 4/5"但无依据。必须按公式：
`评分/13×3.0 + 数据等级权重×1.0 + 模型匹配度×0.5 + 历史胜率×0.5`
取整后给出 1-5 置信。

### 16. 入场距现价过远
检查 `abs(入场 - 现价) / ATR`：
- >0.5 ATR → 禁追（模板规则）
- >1.0 ATR → 计划无效，需重新构入场

### 17. 催化源套娃
"金十 + CoinDesk 都报道" ≠ 双源。两者都是聚合器，可能引用同一源头。规则：
- 彭博/路透 + 金十 ≈ AA级（独立渠道）
- 金十 + CoinDesk ≈ B级（可能互引）
- 两个聚合源 → 催化分打 8 折

### 18. 多空比数据可用但未查
v9.7 后 Binance 签名 API 可查大户多空比（A级质量）和 Taker 期货买卖（B级）。骨架卡不应再用"多空比 0.74"这种过时/错误的数字。统一入口：
`python scripts/data_gatherer.py` → `long_short_top` / `long_short_global` / `taker_futures`

## 审计输出模板

审计时按此格式输出，直指问题：

```
一、结构完整性（缺什么）
二、逻辑矛盾（致命）
三、模型缺失的连锁反应
四、格式违规
五、合起来一句话
```

不要夸。不要绕弯。直说要改哪里、为什么。
