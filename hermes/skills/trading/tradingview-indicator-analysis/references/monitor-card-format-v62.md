# 监控卡片格式 v6.2 经验

用于价格监控、cron 兜底、Telegram/飞书提醒。

## 触发场景

- 用户指出“计划这里怎么是英文？”
- 用户指出“没有告诉现在是什么情况，动作是什么”。
- 任何监控提醒、监控事件回放、cron 兜底输出。

## 用户可见字段

机器字段可以在 JSON 内保留英文，但卡片展示必须中文化。

固定英文术语可保留：BTCUSDT、ETHUSDT、XAUUSD、CVD、VWAP、POC、VAH、VAL、DO、OI、Funding、Basis、Taker、ATR、R:R、ETF、5m、15m、1h、4h。

必须转中文：plan_id、priority、expires、invalid_if、close above、close below、retest holds、near、breach、triggered、invalidated、expired。

## 必备行序

```text
🟡 BTCUSDT 接近计划位
① 品种  ：BTCUSDT
② 价格  ：`65758`
③ 计划  ：比特币日内计划·6月16日23:02
④ 现状  ：价格接近计划位，先观察确认
⑤ CVD   ：卖 · C级
⑥ 价位  ：阻2_收复过滤 `66275` ↓0.8%
     动作：站上才停止追空思路，等待回踩确认
     失效：5m 收盘上破 66370 且回踩守住
     优先：高
     有效：90m
⑦   周期：4h 偏多回撤 · 1h 转弱 · 15m 扫低反抽 · 5m 等确认

  动作：可等待触发
→ 说「分析 BTC」
```

## 计划显示规则

不要直接展示 `BTCUSDT-20260616-2302`。展示层应转成：

```text
比特币日内计划·6月16日23:02
```

解析失败时再显示去掉 `USDT` 的简化文本。

## 现状显示规则

```text
critical：关键位已触发，且动能有配合
warning：价格已贴近或触发关键位
info：价格接近计划位，先观察确认
invalidated：旧计划失效，不按原方向执行
expired：监控位过期，旧计划降权
```

## 动作显示规则

卡片必须同时有两层动作：

1. 价位内动作：该价位触发后具体看什么、做什么。
2. 卡片尾部动作：当前整体处理，如“可等待触发”“尽快看5m确认”“立即按计划确认”“旧计划已失效，等新分析刷新”。

## 常见错误

- 只显示计划编号，不显示中文计划名。
- 只显示接近/触发，不说明当前状态。
- 只在价位内写动作，尾部没有整体动作。
- 把 `priority/high`、`close above` 等机器字段原样发给用户。
- 标签没有序号或没有左对齐。
