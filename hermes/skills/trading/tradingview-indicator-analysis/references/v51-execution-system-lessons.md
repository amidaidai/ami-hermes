# v5.1 中文化执行系统经验

本参考记录交易分析模板与监控闭环的长期做法，适用于后续升级、审计和实盘分析。

## 触发场景

- 用户要求“全面审计”“联网社区”“权威源社区高质量”“全方位多角度”。
- 用户要求把分析模板、监控任务、执行卡、风控和复盘继续完善。
- 用户指出“除了特定英文，其他中文”。

## 语言规则

除固定英文术语外，其余字段尽量中文。

固定英文术语可保留：

- VWAP、POC、VAH、VAL、CVD、DO、OI、Funding、Basis、Taker、ATR、R:R、ETF。

字段中文化示例：

- Setup Playbook → 模型手册
- entry → 入场
- stop → 止损
- target → 目标
- invalid_if → 失效条件
- priority → 优先级
- expires → 有效期
- confidence → 置信
- position sizing → 仓位计算
- journal tags → 复盘标签

机器 JSON 字段可以保留英文，但发给用户的卡片、审计、提醒必须中文化。

## 审计方法

做模板/监控审计时，不要只夸“已很完整”。必须按缺口清单批判性输出：

1. 权威风控：单笔风险、日损、连续亏损、仓位计算。
2. 多周期：高周期过滤、中周期结构、低周期触发、周期冲突规则。
3. 订单流：CVD 可信度、Taker、吸收、衰竭、背离。
4. 衍生品：Funding、OI、多空、Taker、Basis、清算热力图组合解读。
5. 数据可信度：价格源一致性、催化源数量、数据新鲜度。
6. 社区情绪：只调仓位，不覆盖结构。
7. 监控自动化：价格、收盘确认、失效条件、有效期、计划编号。
8. 风控状态：日损、笔数、连亏、是否锁仓。
9. 复盘日志：计划、触发、成交、结果、错因、纪律。
10. 品种模块：BTC/ETH、山寨、XAU、股指/外汇分别审计。

## v5.1 必备模块

每张交易卡至少包含：

- 状态：A做多、A做空、B等待、X禁做。
- 模型：VWAP反抽、VAH/VAL回收、POC拒绝、扫流动性回收、突破接受。
- 评分：结构、周期、订单流、衍生品、催化、风控、情绪。
- 仓位：本金、风险、入场、止损、数量、名义、保证金、最大亏损、R:R。
- 数据可信度：A/B/C，并说明来源冲突。
- 失效条件：明确价格或收盘确认条件。
- 监控位：写入结构化 monitor_levels.json。
- 复盘标签：模型、状态、入场、风险、错误、纪律。

## 评分器规则

建议默认规则：

```text
结构：0-3
周期：-2-2
订单流：0-2
衍生品：0-2
催化：0-1
风控：0-2
情绪：-1-1
```

判定：

```text
10-13：A做多/A做空
6-9：B等待
0-5：X禁做
数据 C级：最高 B等待
高周期明显冲突：最高 B等待
4h 与 1h 同时冲突：X禁做
R:R 低于 1:2：X禁做
日损达到上限：X禁做
连续亏损 3 笔：X禁做
```

## 监控 v6.1 要求

监控不应只做价格提醒，还要能处理计划状态：

- `plan_id`：每次分析生成计划编号，监控事件必须携带。
- `valid_until`/`expires`：过期后标记 expired，不按旧计划触发。
- `invalid_if`：解析简单规则，如 `5m close above 66275`、`15m close below 65928`、`price reclaims 66010`。
- `condition`：near_or_breach、breach、close_confirm、retest、sweep_reclaim。
- `status`：active、triggered、expired、invalidated。
- 触发后不要直接删除监控位，优先标记状态，便于复盘。

## 复盘闭环

新增或维护以下文件：

- `data/trade_plans.jsonl`：每次分析写交易计划。
- `data/trade_reviews.jsonl`：交易后写结果、错因、纪律。
- `data/risk_state.json`：记录日损、笔数、连亏、允许风险、是否锁仓。

每次分析后应能回答：

- 这张卡的计划编号是什么？
- 为什么是 A/B/X？
- 最大亏损是多少？
- 失效后机器能否识别？
- 后续如何复盘这个模型？

## 常见陷阱

- 不要把社区情绪当方向信号；它只调仓位和置信。
- 不要把 K线估算的 CVD 当真实订单流；必须标 CVD 可信度。
- 不要让 `expires` 和 `invalid_if` 只停留在文本里；监控脚本要执行或至少标记无法解析。
- 不要用英文机器字段直接发给用户；卡片展示层必须中文化。
- 不要只输出长研究卡；实盘需要短执行卡优先。
