# 多市场驾驶舱运行态审计与代理节点验证

## 1. 能力“已配置”不等于“已使用”

审计任何数据源或Skill时分四级：

| 等级 | 证据 |
|---|---|
| 已配置 | Key/依赖/脚本存在 |
| 可调用 | 单接口返回有效数据 |
| 已接线 | 对应资产的采集入口实际消费并写入 engine_data/契约 |
| 已裁决 | 数据进入驾驶舱、FinalVerdict或明确的挑战/降级逻辑 |

报告中只有后两级可以写“已用于分析”。套餐限制、仅TG输出无本地JSON、返回空字段均不得标完成。

## 2. TV正式分析前置顺序

正确顺序：

1. 识别资产与主周期。
2. 切目标symbol并用chart state复核。
3. 切主周期。
4. 等Pine重算后刷新同品种Data Window缓存。
5. XAU额外同步5m/15m/1h/4h闭柱OHLCV，结合D形成五层。
6. 再运行VWAP/EMA、体制、模型、风控和FinalVerdict。
7. 最后截full全屏图。

禁止“先跑引擎、后切图”，否则当前卡会吃上一品种或过期Data Window。

## 3. 五层完成度必须按真实覆盖计算

- 只有缓存可用不代表五层完成。
- 必须逐项确认 `D/4h/1h/15m/5m` 均有本轮目标品种数据，才标TV五层✅。
- 单周期Data Window可用但OHLCV只覆盖1/5时必须标⚠️。
- `cron_read`同理：按真实文件名、存在性、mtime和内容质量逐项验证，不能因为路由包含该步骤就标✅。

## 4. 多资产CLI与截图验收

- CLI解析必须接受股票、外汇、期货、期权，不得把未知代码默认为BTC。
- 主周期：加密15m、黄金5m、外汇15m、股票1h、期货15m、期权跟标的。
- 截图必须为full，含价格轴与副指标窗格。
- 非加密HALDRO显示“不适用”，不得制造冲突或方向。

## 5. FinalVerdict渲染不变量

- 最终状态只允许 `GO-A / GO-B / WAIT / NO-GO`。
- 旧A/B/C/X只作指标等级，不能决定执行权。
- GO-B不得被旧模板渲染为“等待”；WAIT/NO-GO不得泄漏可执行入场、止损、目标。
- 数据源名称不是经纪商杠杆。OANDA仅表示行情源，禁止渲染“OANDA 1000x”等未经账户配置验证的杠杆。

## 6. 代理节点应逐节点实测

代理软件可用不代表当前节点可访问目标API。至少测试：

- 强制直连；
- 当前代理节点；
- 香港、日本、新加坡、美国等候选节点；
- Spot公开ping；
- Futures公开ping；
- 只读签名账户接口。

判读：

- HTTP 200：链路正常；
- HTTP 451：节点地域限制；
- TLS失败：当前节点/规则链问题，不代表整个代理不可用；
- 直连超时、代理200：目标域应固定走已验证节点。

切节点测试后必须恢复原节点。签名验证只读账户，不调用订单、撤单、杠杆或持仓修改接口。
