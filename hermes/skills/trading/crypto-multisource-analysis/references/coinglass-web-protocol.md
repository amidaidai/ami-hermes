> 2026-09-16 实操记录。远端改前端就会失效，本文是「再改时怎么在半小时内修回来」的可复用流程。

## 何时用

`data/coinglass_liq.json` 变 `status=unavailable`，错误是
「响应不是 gzip 密文：协议可能已变更」或「未覆盖的响应头 v」。

```bash

# 若报协议错 → 立刻看响应头 v 的取值分布（连打 20 次）
```

只覆盖一支 = 时好时坏。

## 还原三步（关键：轮转）

1. 抓页面 HTML → 取 `_next/static/chunks/pages/_app-*.js`（混淆产物，~2.3MB）。
   **注意：网页 HTML 路由在无头浏览器里会 404（站点挡），但 Python 直连 API 通 —— 不要用浏览器抓。**
2. 找字符串表 `function In(){var t=[...]}` / `function mn(){...}` 与解码器
   `function Mn(t,e){t-=107;...}` / `function gn(t,e){t-=340;...}`。
   **偏移量不同（107 / 340），别抄错。**
3. ⚠ **成败关键**：数组在模块加载时被自带校验式轮转
   `!function(t){for(var e=Mn,n=t();;)try{if(407348===<表达式>)break;n.push(n.shift())}catch(t){n.push(n.shift())}}(In)`。
   直接照抄数组按下标取值 → **全部解错（会得到乱码，很容易误判成算法写错）**。
   正确做法：把「数组函数 + 解码器函数 + 两段轮转 IIFE」**整段逐字提取**，
   在 Node 里原样执行（纯 JS，无依赖），再解 token。

```python
# 提取区间：function mn(){var t=[...]} … 到 In 轮转循环的 `}(In)` 之后的第一个分号
# 另需附加：function Mn(t,e){...} 与 function In(){var t=[...]}
# 然后 node 里直接调用 Mn(idx,key) / gn(idx,key)
```

校验锚点（解出来必须对得上）：
- `bn(205,"#[gv")` = `interceptors`、`bn(296,"xHJs")` = `ECB`、`bn(237,"miln")` = `Pkcs7`、`bn(211,"#UqI")` = `AES`
- 解不出这些 → 序列/偏移/轮转还有一处不对，别继续往下推。

## 2026-09-16 还原出的协议

- 响应管线步骤序 `2|5|1|4|3|0|6`：wn 取路径 → vn 派生 key1 → **substring(0,16)** →
  解 `user` 头得 key2 → 解 body.data。
- key1 按响应头 `v`（vn 内部步骤序 `4|2|0|5|3|1|7|6`）：

| v | key1 原料 |
|---|---|
| `1` | 请求路径（= base64(路径前 12 字符)，旧实现唯一覆盖的那支）|
| `0` / `2` | 我方请求头 `cache-ts-v2` 的值（自己知道，不需要还原）|
| `55` | `170b070da9654622` |
| `66` | `d6537d845a964081` |
| `77` | `863f08689c97435b` |

- key1 = base64(原料)[:16]；两层都是 AES-ECB(16 字符串作 UTF-8 key) → gzip → 明文。
- 未知 v 必须显式抛错：静默套用某一支 = 时好时坏且看不出来。

## 数据口径边界（别误用）

- **强度不是 USD**：是杠杆加权相对刻度，只报强度与占比。
- **总强度随窗口线性膨胀**（实测 15m 2.8e9 → 1h 1.1e10 → 4h 4.1e10 → 24h 1.6e11），
  跨窗口比较总强度没有意义；**只有占比与排序可读**。
- 仅 `Binance_BTCUSDT` 匿名可用；ETH/OKX_* 服务端 `code=40000`（浏览器匿名同样 40000，非参数问题）。

## 窗口选择（BTC，2026-09-16 实测）

| 窗口 | top5 与 15m 重合 | 备注 |
|---|:--:|---|
| 15m | — | 样本小一个量级；真没有新爆仓时会空（OKX 逐笔同刻 15m=0 笔）|
| **1h（推荐）** | 5/5 | 与 4h 结论一致，信息已足够 |
| 4h | 5/5 | 同 1h，无新增 |
| 24h（界面默认）| 4/5 | 把已被扫掉的老堆积算进来，排序会变 → 对短线误导 |

用法：**主口径 1h**；15m 只作「刚刚是否发生插针式扫单」的即时确认；
15m 空窗口时沿用 1h，不得写成「无清算」。
