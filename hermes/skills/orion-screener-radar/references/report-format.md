# Orion 全市场雷达报告格式规范（用户确认 2026-07-01）

## 基本要求

- **全部输出使用真实Markdown管道表**（`| 列 | 对齐 |`），禁止文字对齐替代
- 禁止大段分析段落，所有信息打包进表格
- 时间格式：2026年7月1日09：02（中文，全角冒号）

## 报告结构：必出3张表

Telegram RichMarkdown 下三张表必须直接从管道表开始，不能在表格前紧贴 `表1 · xxx` / `**表1 · xxx**` 标题行。

| 层 | 源 | 状态 |
|:--|:--|:--:|
| ① | Orion Binance | ✅ N 候选 |
| ② | Hyperliquid | ✅ 跨所确认 / ❌ 无对应品种 |
| ③ | Binance REST | ✅ N深度验证 / ⏳ 无 API Key |
| ④ | CoinGecko | ✅ 已执行 / ❌ 未配置 |

下面跟概览行：`N 检测 · 🟢高 X · 🟡中 Y · ⚪低 Z`

第二张候选表必须≤3列，长数据压缩进“数据”列。

| #/品种 | 数据 | 信号 |
|:-:|:----|:----|

列值规则：
- 价格：<$1000 用 `$0.XXX`，≥$1000 用 `$X,XXX` 千分位
- 1h%：带 `+`/`−` 符号，精确到 2 位小数
- OI($)：简写 `$3.5M` / `$159M` / `$6.4B`
- OI%：带符号 ±2 位小数
- 资金费率：百分比 `−0.133%` / `+0.050%`
- 多空比：`2.42x多` / `1.77x多` / `—`
- Taker：方向+数值 `卖0.90` / `买1.22` / `—`
- 置信度：1 位小数 `6.0` / `5.5`

第三张判断表必须≤3列。

| 品种 | 判断 | 动作 |
|:----|:----|:----|

判断逻辑：
- **OI×价**：📈 同涨真突破 / ⚠️ OI涨价跌出货 / 💨 空平反弹 / 📉 同跌趋势下行
- **费率**：🔥 空头重仓(<−0.1%) / 💰 多头拥挤(>0.1%) / ⚖ 中性
- **Taker**：⬇ 主动卖压(卖+<0.8) / ⬆ 主动买盘(买+>1.2) / 🔻 卖方主导 / 🔺 买方主导
- **综合**：⚠️ 真突破+空头重仓·轧空潜力 / ❌ OI涨+价跌+费负=诱多陷阱 / ✅ 量价齐升有机会 / ❌ 暴跌中OI暴增=接盘 / ➖ 观望

下面跟数据来源行：`数据: Orion Screener + Binance API | {ts}`

## no_agent 与 LLM 输出对齐

两个 cron 的输出必须使用相同表格结构：
- **no_agent cron** (ef4cf5f7cd24)：`orion_screener_radar.py` 的 `build_report()` 输出上述 3 张≤3列表
- **LLM cron** (ca1678011963)：仍然只输出 3 张表；x_search 验证压入第二张表，操作建议压入第三张表
