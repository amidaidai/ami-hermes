# Telegram 表格硬化经验

## 背景

用户明确纠正 Orion 雷达 LLM cron 输出：模型把 Markdown 表格降级成了 Telegram 字段列表，例如：

```text
①
• 源: Orion Binance
• 状态: ✅

BREVUSDT
• 现价: 0.10648
• 1h%: +13.39%
```

这不是表格样式，不能接受。

## 必须做法

在 LLM cron prompt 中写入硬约束：

1. 必须使用 Markdown 管道表，包含 `|` 管道符。
2. 每张表必须包含分隔行，例如 `|:--|:--|:--:|`。
3. 禁止 `①`、`②`、`•`、字段列表、逐字段换行。
4. 每个候选必须是一行表格。
5. 如果模型准备输出 bullet，必须立刻改成 Markdown 表。
6. 手动 `cronjob run` 后用 session_search 读取最终 assistant 消息，确认实际送出的内容仍是表格。

## 好模板

```markdown
⚡ Orion雷达 · 候选2个 · 2026年7月2日17：02

| 层 | 源 | 状态 |
|:--|:--|:--:|
| ① | Orion Binance | ✅ 51候选 |
| ② | Hyperliquid | ❌ 未见确认 |
| ③ | Binance REST | ✅ 已核验 |
| ④ | CoinGecko | ❌ 未接入 |

| 品种 | 现价 | 1h% | OI | OI% | 费率 | 置信 | 判断 |
|:----|:---:|:---:|:--:|:--:|:---:|:---:|:----:|
| BREVUSDT | `0.10648` | `+13.39%` | `$5.58M` | `+45.40%` | `-0.0200%` | `5.5` | 📈突破 |
| NFPUSDT | `0.007566` | `-8.21%` | `$2.75M` | `-22.98%` | `0.0000%` | `5.5` | 📉下跌 |

| 品种 | OI+价 | 费率 | 综合判断 |
|:----|:-----|:----|:---------|
| BREVUSDT | OI↑价↑ | 负费率 | 新钱追涨，突破延续 |
| NFPUSDT | OI↓价↓ | 中性费率 | 去杠杆下跌，偏空延续 |
```

## 排序规则

候选表和判断表都按 `confidence` 降序；置信度相同再按 `abs(OI%)` 降序。不要按涨幅、输入顺序或发现顺序排序。
