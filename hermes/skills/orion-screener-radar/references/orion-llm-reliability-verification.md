# Orion LLM 分析 cron 可靠性验证方法 v1

创建时间：2026年6月29日

## 背景

Orion 全市场雷达有两层输出：
1. **no_agent 采集层**（`orion_screener_radar.py`）：四层验证（Orion Binance→HL→Binance API→CoinGecko），输出候选项到 `data/orion_radar.json`
2. **LLM 分析层**（cron `Orion雷达分析`）：读候选项数据，用 LLM 做自然语言解读和交易建议

## 为什么需要 LLM 层

no_agent 脚本只做数值过滤和信号标记——它不会判断"这个 OI 异动是轧空还是真突破"、"BTC跌但这个山寨涨是否有独立叙事"、"三个高置信度候选中哪个最值得打"。LLM 层补上了**叙事推理和优先级排序**。

## 可靠性验证方法

LLM cron 的 prompt 内置了以下验证指令：

### 1. 信号真实性过滤
- 排除 OI < 50万U（流动性不足，易被操纵）
- 排除 24h 涨跌幅 < 5%（波动太小不打）
- 排除 BTC 逆势品种无独立叙事的（跟跌被误判为独立行情）

### 2. 跨交易所交叉确认
- HL 确认标记必须是 ✅HL通 才给高置信度
- 仅有 Orion Binance 单源信号的标记为 ⚪低置信度

### 3. 费率极端度验证
- 费率 > 0.01% → 多头拥挤，做多风险高
- 费率 < 0 → 空头拥挤，可能轧空
- 费率极端 + OI 反向变化 = 拐点信号

### 4. BTC 方向一致性
- 读 `data/source_snapshot_BTCUSDT.json` 确认大盘方向
- 山寨顺 BTC 方向的信号置信度 +1
- 山寨逆 BTC 方向必须有独立叙事（如主网升级、治理提案）

### 5. 输出格式标准化
- 固定 7 列表格（# · 品种 · 价格 · 信号 · 置信度 · HL验证 · 关键指标）
- Emoji 必须带中文标签（🟢OI涨 而非只有 🟢）
- 前 3 候选额外给简明决策建议（方向·关键位·风控提示）

## 常见误判模式及 LLM 修正

| no_agent 信号 | 可能误判 | LLM 修正逻辑 |
|---|---|---|
| OI 涨 + 价涨 | 假突破（诱多） | 检查量是否配合、是否在阻力位附近 |
| OI 跌 + 价涨 | 空头平仓反弹 | 标注 💨轧空、不做多 |
| 费率 > 0.05% | 高拥挤度 | 标注 🔴拥挤风险、降级置信度 |
| HL 标记缺失 | 数据不可靠 | 自动降为 ⚪低置信度 |

## 预期月成本

- 频率：9:00-23:00 BJT，每 30 分钟一次
- 日调用：28 次
- 每次 ~$0.03（LLM 读 JSON + 分析 + 输出表格）
- 月成本：~$25

## 与 no_agent 层的关系

```
orion_screener_radar.py (no_agent, */30m)
  → 四层验证 → orion_radar.json（候选项）
  → 推 TG:846（原始信号表格）

Orion雷达分析 cron (LLM, 5,35 */1h)
  → 读 orion_radar.json
  → LLM 叙事分析 + 置信度复核
  → 推 TG:846（分析后表格 + 决策建议）
```

两个 cron 的时间差 5 分钟确保 no_agent 先落盘，LLM 再读取。
