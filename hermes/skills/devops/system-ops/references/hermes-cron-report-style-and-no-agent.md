# Hermes cron 报告样式与 no_agent 退出码

## 适用场景

用户要求运行、修复、审计 Hermes cron / 维护脚本后，把任务运行结果发到 Telegram 或当前会话。

## 用户偏好

- 报告尽量中文。
- 只保留必要英文：Hermes、Telegram、API、MCP、cron、job、OK、error、PID、文件路径、命令、配置项、日志原文、模型名等。
- 不使用装饰性分隔线，例如 `══════════`、`━━━`、大段 `====`。
- 不使用花哨编号 `①②③`；用普通 Markdown 标题、表格、数字编号和要点。
- 先给结论，再给证据和路径。

## 推荐报告模板

```md
## 任务运行报告

| 项目 | 内容 |
|---|---|
| 任务 | {任务名称} |
| 时间 | {开始时间} → {结束时间} |
| 状态 | ✅ 成功 / ⚠️ 有警告 / ❌ 失败 |

## 执行结果

| 检查项 | 结果 |
|---|---|
| {检查项} | {结果} |

## 需要关注

- {问题或风险}

## 证据

- 状态：`{命令输出摘要}`
- 报告文件：`{路径}`
```

## no_agent 退出码规则

Hermes no_agent cron 的语义：

- stdout 非空：会被作为任务输出/报告交付。
- stdout 为空：静默成功。
- 非零退出：Hermes 会把 job 标记为脚本错误。

因此：

- 监控/审计发现业务异常但脚本成功生成报告时，应该 `return 0`。
- 只有脚本崩溃、采集失败到无法产出可信报告、语法错误、依赖不可用等真正执行失败，才返回非零。

## 修复现有脚本时的检查点

1. 搜索脚本中的装饰分隔线：`══════════`、`━━━`、连续 `====`。
2. 改成普通 Markdown 标题和表格。
3. 如果脚本是 no_agent 报告脚本，确认异常报告分支最后仍返回 `0`。
4. Windows no_agent stdout/stderr 在任何 print 前强制 UTF-8，避免中文和 emoji 乱码。
5. 修改后同时同步生产脚本和仓库副本，再用 `python -m py_compile` 与一次实际 cron run 验证。
